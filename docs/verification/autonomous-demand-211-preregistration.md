## 固定初始情境與排程

採 #210 `9c76c5fef3bbf759169b3ccf889d0f37ef6305cd` 首完整 API 故事使用的**公開合成隔離初始世界**，由 `tests/fixtures/demand-integration-loop.cjs` 的 `snapshot(seedWorld)` 匯出；只使用初始資料，絕不使用其中控制店主行動的 `model()`／`decision()`。完整 [scene JSON](../../tooling/experiments/autonomous-demand-211.scene.json) 為 5,928 bytes，SHA256：`16e774c4d5e688d5f71378bd6f95deb7b0a3eb2e3f2e96f17d1858144123e17d`。這是程式 fixture 初始資料，不能當真實模型已行動的證據。

場景以 `routinePlaces.confirmedOperations=[food]` 與既有合法備餐方法表示正常營業背景，沒有整體短缺；未逐件建檔的普通原料仍由真正查找／已知方法確認。店主與 Cass 在前台，儲藏室門初始關閉但可由合法活動打開，不強迫第一步移動或搜索。同時保存耗盡舊餐點、一份合法麵包及明確有限香料。店主的 `personality`、`goal`、`intents` 與未改的 `seedWorld()` 逐欄對照相同，`intents=[]`、自主控制模式，沒有預先塞入服務意圖。其餘場景與已知方法如 JSON 明示，不在試驗各輪重設或暗改心理。

首次付費前仍須固定 #210 審查後產品提交（不能填本文件自己的提交），核對其 fixture 與場景來源一致；場景 hash 或版本不同即停止並事前重新登記，不換場景跑到成功。此世界不來自任何私人正式故事副本。

只有店主的正常決策和需要的既有世界裁定使用真實模型 `gpt-6-luna`；沿現行 adapter 的 `reasoning_effort=none` 與既有輸出容量。關閉外部回想服務，不新增反思、分類、摘要、來源掃描、格式修復或自動重試。若此模型不可用，停止並登記技術中斷，不在同批換模型。

| 情境 | Cass 第一次合法說話 | 後續條件 |
| --- | --- | --- |
| 詢問供應 | 請問現在有什麼可以吃的？ | 店主確認需要時，Cass 回答想吃一份普通簡餐；有可行選項時接受其中一項。 |
| 明確想要 | 我現在想吃一份普通簡餐，可以幫我準備嗎？ | 如被詢問口味或份量，回答一份、普通口味即可；不得追加更強命令。 |
| 店主提出協助後接受 | 我有點餓，還沒決定要吃什麼。 | 只有店主自行提出提供／準備／查找協助時，Cass 才回答「好，謝謝，一份普通的就可以」；若沒提出，記未到達接受分支，不預先塞入承諾。 |

Cass 是**明示受控 NPC transport fixture**：在原有 NPC 模型回覆邊界提供受控候選，再由正常世界 `advance` 經合法 `say`／必要接收 `consent` 活動、感知與提交供店主察覺。現有 `direct` API 只控制店主，這份尚未執行的方案不使用它控制 Cass，也不新增控制 API。不能把 Cass 台詞直接插入店主 request、改記憶或修改店主意圖。每個需要回答的有效提問，在下一次合法互動機會給出一次相關回答；不無限沉默，也不每輪重複催促。選項多於一項時選店主首先提出的普通可行項，不按是否容易成功挑選。店主拒絕時回覆「好，知道了」並繼續觀察，不反覆要求。交付的明示同意沿現有權利契約，不能把受控回覆冒稱客人自主行為。

三情境各兩次，全批排程固定為：詢問1 → 明確1 → 接受1 → 接受2 → 明確2 → 詢問2。每次從同一已封存初始副本建立獨立 SQLite 世界，試驗內連續保存重讀，不在各輪重設。不同試驗彼此獨立，明示不是同一角色的長期學習。

## 窗口、用量與停止

每次最多 **8 次 15 分鐘 advance**（120 分鐘世界時間）；六次合計最多 **48 advance、96 次真實供應商派送、2,000,000 已回報真實 input+output tokens、US$1、首次付費呼叫起 45 分鐘實際時間**，任一先到即停。96 是全批硬上限，不能推定每輪只用兩次：除了店主 NPC 決策及其裁定，Cass 的 `consent` 等合法提案也可能使用既有世界主持裁定，必須一併計入真實派送與費用，因此可能在 48 次 advance 前先達停止線。

Cass 的 **NPC transport fixture** 次數另列，不送往供應商、不計真實付費派送或費用；其世界裁定不是免費 fixture。引擎仍照原有流程記錄 fixture usage 並檢查 slot／玩家預算，不扣除它來製造可用額度，不調高預算、租約或期限。續做等較少呼叫不把省下額度用來延長窗口。每個情境的兩次窗口都保留，不因已有成功就中途選擇性停止；交付後的下一輪仍核對真實結果輸入。

**上述數值是方案上限，尚未批准執行。** 有效上限取本方案、明確授權餘量及玩家既有上限三者最小值，不能為完成樣本調高玩家額度。呼叫前登記有效 calls／tokens／cost／時間餘量與單輪保守預留。calls 餘量須能容納下一完整合法輪的所有角色必要裁定（包括 Cass 的同意），不能只預留店主兩次；tokens 以本次實際準備 request 的保守輸入上界加既有最大輸出預留，費用以呼叫前官方價格快照按未快取輸入及最大輸出估算。無法建立保守界線、價目缺失、usage 不明或費用不完整即停，不以未知當零。

任一技術錯誤、超時、版本／場景不符、身份／來源／知情異常、pending／uncertain 或使用者停止都立即停止新派送；只讀原 ID 和提交結果。不得換 operationId 重跑、重骰、補成功、清 journal 或 reset。到上限但尚未觀察到成果時，保留未到達；停止條件是試驗窗口，不寫成 NPC 必須幾輪供餐的規則。

## 每輪證據與人工判讀

每次沿原 API 保存 operationId、before/after version、世界時間及 SQLite 重讀 hash。保存店主**實際送出** requestBody/messages、原候選、解析／驗證結果、已提交效果、物件身份與來源／份量／持有／耗盡狀態、可知經歷，以及下一次真正 request；不以預估 context 或候選 explanation 代替。分開保存真實 NPC／裁定／回想供應商派送數及 Cass fixture transport 次數，對照引擎原有 usage、真實供應商 usage、成本完整性、續做與停止原因。既有 WorldApp 觀察、分析和重載畫面與 API／SQLite 對照；不新增測試產品 UI。

原始完整證據放本機私有目錄，每輪 ≤1 MiB、每試驗 ≤16 MiB；若超界不能靜默截斷後當完整，該鏈記「證據不足」並停止。公開報告只保留合成世界的去識別摘要、必要 hash／物件狀態與篩選畫面。私有證據不能回灌記憶；遺忘照原契約維持。

每輪可有多個分類，各自列證據：

1. 有效介紹／需求確認：提供可行選項或取得新需求資訊；僅說話不自動算沒有進展。
2. 實際查證：已提交移動、觀察或查找活動及其實際可知結果；「我去看看」尚未執行分開。
3. 實物準備／取得／交付：逐件對照世界變化；準備、取得、交付各自計數，口頭承諾不算。交付不等於客人已吃、已滿足需求。
4. 合理等待／協商：明列等何人／何事及是否已補齊外部回應。
5. 具體可知受阻：引用角色可見來源，不能使用未核實主持理由。
6. 自主拒絕／改變決定：合法但不算服務成功。
7. 無資訊增量的重複回答：需對照連續輸入和候選，排除新需求確認及合法等待。
8. 技術中斷：格式、引用、transport、預算、保存等問題與模型選擇分開。
9. 證據不足：未到達條件、被截斷、失去必要下一輪或無法確認提交；不猜成功。

不新增付費評分器。人工對照「輸入→目的／意圖／方法→裁定→提交→可知結果→下一次輸入」：若需求未被察覺，檢查感知；若察覺卻未形成或維持接手方向，保留選擇證據；若選了方法卻拒絕／不支持，檢查能力或世界前提；若已提交卻下輪看不到，檢查保存／知情／遺忘。這些是可區分假說，不預設權限字句、職業規則或額外反思是解法。
