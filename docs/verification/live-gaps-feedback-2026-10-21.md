# PR #143 後續：NPC 受阻回饋診斷

日期：2026-10-21（台北）。基準 `5e172d5`。關聯 #104、#106、#123；不關閉工作票。

## 結論與範圍

已重現一般自由裁定的回饋缺口：`denied` 只保存「這次方法沒有成功。」、`unsupported` 只保存「目前的方法無法落實。」；下一回合確實收到同一泛稱。保存與 NPC 投影沒有漏掉既存理由，因為這條分支原本就沒有產生較完整的回饋。

但不能據此說 NPC 完全不知道權限：最小場景的已知介紹原本已告知「只有一份可供 Cass 的餐點」與「杯子借用需店主自己同意」，重讀後仍在下一決策的主觀記憶。PR #143 兩個回合不足以證明無限循環，本機 fixture 刻意重複提案也不證明真實模型會持續重複。

本輪只補一般受阻結果的安全指引：

- `denied` 保留沒有成功，條件式提醒「若尚未取得必要使用許可，須由有權角色自行同意授權」，以及方法／已知條件實質改變後可再提出。
- `unsupported` 明示目前無法承接這種效果、尚未完成，僅改措辭不是方法或已知條件實質改變。
- 是否等待、重試或換方法仍由 NPC 決定。已有日常綁定器產生的可知 `blockedReason` 優先保留。

不讀取隱藏 `allowedTo`、所有者或持有人來猜原因，不新增模型理由欄位、分類／修復呼叫、行動替換或強制成功。沒有宣稱已根治正式模型重複提案。

## 重現及可否證假設

使用真實 world GET／POST、實際 SQLite 保存重讀，僅模型 transport 為 fixture。先以現有 API 進入新的最小場景；Vera／Kris 提案沿用 PR #143 第一回合已捕獲的文字及 target，另外兩名角色選擇休息。裁定 fixture 明示 `unsupported`／`denied`，不將未保存的歷史欄位補成原始候選。

```sh
node tests/run-activities.mjs tests/npc-failure-feedback-api.test.cjs
```

## 驗證

新增三項 API 維護測試：

1. Kris 餐點否決後，保存及下一決策具有條件式權限指引；已知場景介紹仍保留。模型 fixture 繼續自主選同一動作，程式不強制改動、沒有餐點產生或消耗。原 ID 重送不新增裁定，世界重讀完全相同。
2. Vera `unsupported` 與 `denied` 保持不同回饋；具有實質方法／條件變更指引，沒有編造「沒有杯子」「店主拒絕」或「沒有茶包」。物件保持原狀，下一同內容提案沒有被悄悄換成休息。
3. 對明示隱藏 target 的兩類回覆，只保存一般指引；下一 NPC prompt 不含隱藏標籤、來源、所有者、持有人、權限名單或操作診斷。該物件版本不變。

結果：新增測試 **3/3**；與 `routine-obstacles-api`、`free-actions-api` 合跑 **36/36**。TypeScript typecheck、變更檔 ESLint 通過。既有日常已知障礙、權限撤回、保存失敗及可知資訊隔離回歸保持通過。

## 剩餘限制

以上為本機 fixture，不等於正式站或真實模型驗收。尚未取得 Vera 兩次 unsupported 的特定原因；現有裁定契約只有 status，不能把新的安全指引說成模型當時提供的理由。此修正不擴張原契約，也不保證模型下一步改行動或完成目標。

部署後應沿有界驗收流程觀察新的回覆、已知狀態及後續選擇；如仍重複，保存新 operation evidence，先分辨模型選擇、方法辨識、實際前提和可知回饋，再判斷是否需增加產品／裁定契約能力。
