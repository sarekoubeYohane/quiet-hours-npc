# #104 裁定契約與失敗診斷修正

基準：`6ba5b7ed40f90247b75981b5b06d3f586c476d75`。日期：2026-10-17（Asia/Taipei）。

## 修正

- 派送給裁定模型的契約補上效果順序、供應與實體物件 ID、持有／所有權／同意、版本遞增、食用限制、階段前提與否決／不支援語義。供應明示下一個 `materializedObjectId`；裁定收到本次活動的 `durationMinutes`。識別規則與執行器共用計算，沒有替模型修補非法候選。
- 驗證失敗帶回出錯的階段／效果索引、效果內容及當步物件／供應快照。後一步版本錯誤會顯示已執行前一步的預演版本，另保存派送前的裁定輸入，區分兩個時點。
- 候選格式／效果違約使用 `stopReason={scope:adjudication,code:candidate_contract}`；正常 denied／unsupported 與 API／保存故障維持各自處理方式。
- 失敗診斷隨既有 operation journal 原子保存；同操作重送及 GET 重讀可查閱，主頁提供收合面板。診斷不寫入 World 的角色、事件或記憶，不回流 NPC prompt。
- 診斷保存已過濾的裁定輸入與有界候選，遮蔽兩個實際派送 Key、Bearer／常見 Key 字串及憑證欄位；總 JSON 長度最多 24,000 字元，超過時明示截短。只在已登入世界擁有者的操作結果中可讀。最新操作成功或切換場景後不繼續顯示過時失敗面板；歷史操作仍沿 journal 保存／淘汰政策。
- 物件種類、持有、所有權、同意、版本及生命週期校驗維持原條件。候選違約仍整回合回復，保留已付用量；未增加模型重試、裁定修復呼叫或部分提交。
