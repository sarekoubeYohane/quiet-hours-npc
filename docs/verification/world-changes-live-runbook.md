# 通用世界變更：部署後有界驗收

本文件是部署後的執行流程，不代表本輪已部署或通過正式站。本輪開發只使用模型 transport／受控骰子 fixture；沒有付費模型呼叫、正式世界修改、合併或部署。原 #143 已取得的餐點、首次泡茶、保存及同 ID 重送證據保持有效；新版本的能力另行取證，不追補舊 receipt。

## 開始條件與停止界線

1. 記下本 PR 的最終交付 commit/tree，以及站上設定頁顯示的部署 commit。先讀取世界 API 和分析頁的部署證據，確認正式部署包含本 PR 與 PR #144 的整合成果；版本不符立即停止，不用付費回合猜部署狀態。
2. 取得後續正式付費驗收授權才開始。保存目前世界讀取結果、版本、最近操作 ID 和已知用量；不得重置、改寫原世界或把 fixture 回覆送入正式世界。依既有「進入最小驗收場景」確認流程保存原世界，完成後沿「返回原世界」流程退出。
3. 保持玩家現有預算，不提高、不改成無上限；記錄 calls／tokens／本小時與累計用量、模型及已知價格。預算未配置或已達上限即停止，先回報。
4. 本次驗收總上限為 **24 個新 advance、30 分鐘實際操作時間，或現有玩家預算先到者**。每次只手動推進 15 分鐘；不啟用自動運行，不因未到達某種行為而無限追加。重讀與原 ID 重送不算新回合，仍計入實際時間。
5. 任一技術錯誤、提交不明、持續身分／來源／數量不一致、資訊洩漏、超出預算／派送界線，立即停止新增回合。先 GET 世界及原 operationId，若可安全重放則使用分析頁「重送同一操作」，不得換新 ID 重做未知結果。保留失敗資料後回報。

## 逐項操作與證據

以觀察頁、互動入口及既有直接控制入口提供情境。NPC 是否授權、是否採取未經許可或身體互動，仍由 NPC 決定；不能把沒有出現某行為列成引擎失敗，也不能強制成功或偽造同意。各段共用上面的總上限，未到達記為「未到達」。

| 情境 | 操作及可判定結果 |
| --- | --- |
| 餐點與來源 | 觀察取得／食用餐點；核對有限供應減量、產物 ID、生命週期及保存來源。若發生形成／分拆，記下原物、份量、各來源及獨立部分，確認沒有完整原物與全部成果同時可用。 |
| 正常借還 | 向物主請求借杯；只有物主自主產生的權威授權才算 grant。觀察借用、攜帶、洗淨及歸還，杯子 ID／所有者不變；口頭答應不能代替權威授權。 |
| 同杯循環 | 觀察首次泡茶、喝茶、洗杯、再次泡茶；記錄每次杯 ID／revision、前後狀態、前次飲品消耗及新飲品來源，確認只有一件活動中的杯及正確新成果。合理的不同狀態不以固定 dirty 字串判錯。 |
| 意外或未經許可後果 | 僅在自主行動實際到達時取證；核對所有權與 allowedTo 保留、外在持有／狀態改變，不偽造 consent。受影響角色的心理與下一步不由裁定強寫。 |
| 環境／身體影響 | 到達同一事件的物件、環境及身體後果時，核對持續狀態及既有 UI／API 重讀。只檢查角色實際可知結果，不把觀察者理由當 NPC 所知。 |
| 自然變化 | 有已確認安排才推進至其世界時間，記下條件、到期、執行或失效證據；新增裁定應為零，NPC 決策另計。未曾確認的冷卻／乾燥不能以觀察者猜測補出。 |
| 日常重用／真正例外 | 以新活動重用同範圍；比較實際 adjudication／NPC dispatch 次數，不能只看 HTTP 200 或總模型數。首次核准後相符重用應零新增裁定；未涵蓋例外須受既有 slot 上限。 |
| 續做／中斷／保存 | 觀察跨回合進度，重載後進度與早先成果保持；正常中斷只取消未來。對選定原 ID 重送，確認世界、用量及效果不重複。不要在正式站注入保存或租約故障；故障案例由本輪本機 fixture 證據覆蓋。 |

五段結果與失敗消耗只記實際出現者；正式站不控制骰子、不追加重擲來湊齊五段。未出現的級別由本機受控骰子 fixture 與正式站尚未到達分開列出。

## 每個可判定操作保存的最小資料

- 部署版本、世界 context、操作 ID、base/result version、回合與世界分鐘。
- 安全的原提案、裁定候選與理由、選定分支、階段及必要前後狀態；沿有界 receipt 的遮蔽／截斷標示，不另外保存 Key、完整私人 prompt 或原世界備份。
- 物件 ID、所有者、持有、來源、份量、生命週期；自然安排的確認／到期／執行或失效狀態。
- 實際 NPC／裁定派送數與已知 usage，另列未知用量；重送前後對照及 UI／API 重載畫面。
- receipt 已被截斷或 journal 淘汰時明記缺口，不追補舊原文或假稱完整證據。

完成或停止後，沿正常流程返回原世界並核對原物件／經歷保持、共用用量保留。報告分成「本機 fixture 通過」「正式站取得結果」「尚未到達／具體受阻」，保留 #104、#106 既有狀態，不自行關閉。
