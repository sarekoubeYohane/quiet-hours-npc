## 場景切換預檢

既有 enterAcceptanceScene 在已處於驗收場景時拒絕再次進入；一般 reset 在驗收期間也被 route 拒絕。既有可用路徑是完成備份後 exit-acceptance 返回原世界，再 enter-acceptance 產生新場景。切換沿原子保存與 contextId，保留帳戶用量、裁定與預算，不呼叫模型。原世界備份損壞／超限時應拒絕，而非改用種子覆寫。

clearDecisionTraces 只在一般 reset 成功路徑呼叫；進出驗收本身不主動清空 archive。但進出操作會新增實錄，跨 context 共享 64 筆／16 MiB 淘汰上限，因此仍須先私有備份。原操作 journal 另有淘汰範圍，不能依賴日後精確重播恢復唯一證據。

另有對照條件差異須先記錄：當前舊杯子 stateTransitions.contents 為 empty／water／tea；目前程式場景種子含 dirty。相同部署版本不代表舊已保存物件與新種子的能力清單完全相同；若日後依既有種子重建，需明示此差異，不能聲稱除累積歷史外全部世界條件逐欄一致。本輪未修改任何一方以消除差異。

## 具體停止原因：未完成整回合 token 上界確認

呼叫數可由目前四角色、隔離場景停用向量回想及每 slot 至多一次裁定，保守預留 **8 calls／回合**；這不是預測必定發生 8 calls。

token 預檢尚未達使用者要求，依據：

1. lib/activities.ts 的 budgetReached 以已知累計 input+output 判斷門檻；app/api/world/route.ts guard 也是派送前檢查已知用量，沒有預約整回合尚未發生的 tokens。
2. lib/model-adapter.ts 對本輪 NPC 模型輸出設 2,048 上限；lib/adjudication.ts 在 routineOffer 存在時採 12,000 輸出上限。四 NPC 加四裁定的輸出可預留 56,192，但這不包含輸入。
3. response_format/schema 亦須計入模型輸入。歷史實際 request 約 31,902–38,760 UTF-8 bytes（NPC）及 90,614–90,670 bytes（裁定）；它們只是歷史量測。粗略用 byte 作過度保守包絡已不能支持 500,000 的整回合預留；**bytes 不是 tokens，這不表示實際回合必然超支。**
4. 同回合前面角色可先提交到候選世界，再影響後面角色 request／裁定輸入；記憶投影 88 KiB 限制只涵蓋其特定欄位，不是完整派送 body 的上限。未完成對乾淨種子及全部合法中間候選的輸入 token 上界推導。
5. 本輪帳戶每小時 5,000,000 門檻高於本輪 500,000，不能把它當成本輪硬限制；降低門檻仍僅檢查已知用量，不能自動解決整回合預留，也未擅自修改帳戶政策。

**執行者目前無法確認下一整回合在授權餘額內的保守上界，故停止，不宣稱產品在 500,000 tokens 內必定無法完成。** 這是本次預檢／執行阻擋，不是泡茶行為的根因。未為了避開門檻修改模型參數、提示、角色、規則或縮減自然參與角色。
