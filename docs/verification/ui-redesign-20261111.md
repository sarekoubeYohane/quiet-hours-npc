## 文件與實作的差異

- #281／原 README 的五步是既有 UI，不是引擎必須的五次確認。後端 step 1–5 格式仍保留；新畫面映射為三階段（1；2/3；4/5），舊草稿繼續可讀。確認 API 已能在原 step 4 保存，無需變更遊戲或資料契約。
- 全手填不等於免模型：背景判讀仍參與一次形成，不能拿掉而不改人物規則。本輪提前告知，並允許先存文字。
- 原 README「完成後回開局選入」是舊實作，本輪改為保存資產後透過同一開局 API 自動選入，版本衝突仍阻止覆寫。
- `model-task-contract.md` 的舊 v1 描述不能代表當前執行器；README 已註明 `npc-decision.v3` 與後續分層追求契約。本輪不改模型任務語意。
- 前次未提交 UI 將 AI 整理元件從 JSX 移除，並非正式站已撤回的能力。依 [#293](https://github.com/sarekoubeYohane/quiet-hours-npc/issues/293) 修復。

## 設計取捨

以「人物、場景與安排、核對並開始」組織任務，減少頁間往返。先告知需要什麼，再讓使用者投入文字工作。模型設定同頁保存；明示「保存並繼續這次操作」才接續人物形成，取消與純保存不呼叫模型。

進階選項收合，保留能力與資料語意。唯一場所／房間只補空白；多選項不猜。確認與進入觀察合為一個保存動作；實際權威預覽、固定初值、來源快照、同 ID 重試均不變。觀察頁收合模型與自動運行設定，讓世界與下一回合成為主要內容。

場景原本沒有帳號草稿 API，因此未完成內容只保存在目前分頁，不冒稱跨裝置保存；完成時才同步帳號。模型與 Key 是既有兩個服務端保存操作，本輪合成一個 UI 動作但不宣稱原子交易，失敗時明示哪部分已成功。

## 本機環境與 Chrome 驗收

啟動：`node tooling/verification/preview-ui-redesign.mjs`。入口 http://127.0.0.1:5191/start；應用 http://127.0.0.1:5190。SQLite 位於 `outputs/ui-redesign/acceptance.sqlite`，僅 loopback。使用既有真實 Vinext 路由、SQLite 與受控身分／骰子／模型 transport；預載 no-network 防線禁止外部模型流量。Key 欄可填 `local-mock-key`，不是有效供應商憑證。

`ui-redesign-qa` 由空白開始，在 Chrome 實際完成：

1. 空帳號首頁 → 建立第一個世界 → 人物卡製作；輸入姓名／外觀／性格後立即返回，重新開啟仍保留。
2. 手填九項 → 開啟設定 → 取消後文字不丟失；重開設定一次保存模型與假 Key，直接接續形成。
3. 形成後重載仍為原結果；配點力量 13、耐力 11、其餘 12，總分 60；保存完成卡後回同一草稿且自動選入。
4. 填世界名稱 → 建立單房間場景；未保存就離開再返回，名稱／房間／描述由本分頁恢復；保存並帶回後自動選入，起點為河岸小屋／起居室。
5. 注入草稿 POST 一次 503，畫面保留敘述、顯示未同步、禁用下一步；按恢復保存成功。
6. 請 AI 整理 → 建議已保存但未採納 → 採納。返回存檔頁接續，原名稱、敘述、場所與安排仍在。
7. 核對頁顯示實際能力與第 0 回合；注入建立存檔一次 503，按「恢復原存檔操作」成功進觀察，只有一個已建立世界，未推進回合。
8. 重載與返回存檔頁仍為第 0 回合；顯示兩次模擬模型呼叫（形成、可選整理）。
9. 390×844 視窗核對觀察、開局、場景編輯與模型設定；文件寬度等於視窗寬度，沒有水平溢出。Space 選人物，Enter 切換階段；階段標題承接焦點。進階欄位仍可展開。

示範帳號 `ui-redesign-demo` 留作使用者首次體驗。QA 帳號另有手機／熱更新檢查用未開始草稿，不影響已建立世界。

## Bug 診斷與回歸

#293 的最小失敗迴圈為 `node --test tests/opening-ui.test.mjs`：既有開局 step 3 應出現 AI 整理區，前次 diff 會 fail。先分別檢驗「JSX 未掛載」「步驟 gate」「設定／來源條件」假說；HEAD 與 diff 確認是掛載遺漏。恢復元件並放在停用 fieldset 外，避免處理中連原操作恢復也禁用。修復後元件測試與上述 Chrome 生成、查看、採納、離開續作、完成開局皆通過。

新增測試也涵蓋唯一選項不覆寫、場景帶回後提交回覆遺失的冪等重試、24 字元識別限制、帳號不符零寫入、並行版本衝突不盲重送，以及模型／Key 部分成功後保留 Key、純保存不續作、明示續作只執行一次。既有場景元件測試補齊路由與 sessionStorage 的宿主邊界，仍走真實場景 API／SQLite。

驗證記錄位於 `artifacts/ui-redesign-20261111/`。型別檢查與 production build 均成功；本機不部署。相關 API／UI 回歸 69 項全過（`regression.log`），新增 UI／接回測試 5 項包含在內。初次沙箱執行被 loopback listen 權限擋住，升權後重跑通過；既有場景元件宿主邊界也已補齊。
