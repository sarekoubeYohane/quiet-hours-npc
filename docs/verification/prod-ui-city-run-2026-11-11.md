# 正式站 UI 實測：新建 8 人城市並觀察（2026-11-11）

狀態：**城市建成，跑到第 20 回合後依使用者指示停止**（原訂 72 回合）。本檔是日期快照，不是現行契約。

- 環境：正式站 `https://quiet-hours-npc.houmengkou.workers.dev`，版本 `bec6983`
- 操作方式：建城、觀察、推進全程只用瀏覽器 UI（Chrome）。network 狀態碼、`wrangler tail`、程式碼只用來判讀原因；D1 查詢由帳號持有人自己執行
- 模型：天上意志 OpenAI `gpt-6.1-sol`，NPC OpenAI `gpt-6-luna`

## 結論

1. **AI 模式目前跑不了長時間觀察。** 需要 NPC 重新決策的回合共嘗試 9 次，成功 2 次、失敗 7 次；失敗一次就整回合回滾並中止自動推進，而且同一狀態重試多半拿到同樣的錯。
2. **規則模式穩定。** 連續 12 回合自動推進沒有任何錯誤，每回合約 24–30 秒。
3. **建城流程走得通，但很慢。** 8 張人物卡加 7 個場所範本，純操作約 25 分鐘，其中每次模型操作固定等 40–50 秒。
4. 一開始整個流程被失效的 OpenAI Key 擋住，而 UI、Worker log 都看不出是 Key 的問題。

## 問題清單

### P0　AI 回合：`methodAssessment.choice` 與行動類型不一致就整回合失敗

- 畫面訊息：「技術故障：模型未回傳有效的意圖與行動格式。請換個模型再試。」
- 出現 5 次（第 5 回合 3 次、第 6 回合 1 次、第 21 回合 1 次），每次都是第 1 或第 2 個 NPC 決策就中止。
- 從決策追溯看其中一筆（蘇以安，npc:5）：OpenAI 回 HTTP 200，內容是完整的 `npc-decision.v3` JSON，但 `methodAssessment.choice` 是 `continue`，`selectedAction.type` 是 `observe`。`lib/models.ts` 的 `methodAssessment` 驗證要求 `(choice==='continue') === (selectedAction.type==='continue')`，不成立就丟錯。模型把 `continue` 理解成「沿用原本的做法繼續看」，不是「行動類型是 continue」。
- 只看了這一筆的回覆本文，其餘 4 筆訊息相同但沒有逐筆打開確認是不是同一個欄位。
- 世界狀態沒變，重試容易得到同樣的回覆，所以會連續卡住。這次是靠切規則模式推一回合才繞過去。
- 一個 NPC 的格式問題讓 8 個人的整回合作廢、自動推進中止，沒有單一 NPC 重問或降級的機制。

### P0　AI 回合：裁定模型回 no-op 效果就整回合回滾

- 畫面訊息：「裁定候選不合法：物件已由該持有人持有。」
- 第 5 回合第 1 次嘗試。林澄提議「把小桌上可移動的物品逐一整理、擦拭桌面，再將物品整齊放回原位」，裁定模型（`gpt-6.1-sol`）回了 `{kind: physical, reason: "noop", operation: "place", objectId: 小桌}`，`lib/world-effects.ts` 以 `unchanged_holder` 拒絕。
- 當回合另外 7 人的決策一起作廢，7 次呼叫照樣計費。
- 模型自己標了 `reason: "noop"`，卻被當成不合法效果處理。

### P1　建角被失效的 Key 擋住，且從 UI 與 log 都看不出原因

- 一開始 `POST /api/character-drafts/generate` 與 `/form` 連續 5 次回 502，畫面只有「人物草稿未能生成」「人物背景未能判讀」。
- 帳號持有人查正式站 D1 的 `decision_traces` 才確認是 OpenAI 回 HTTP 401（`provider: openai`、`model: gpt-6.1-sol`、`failure: {kind: http, stage: provider-response}`），換 Key 後恢復。
- `lib/model-adapter.ts` 的 `providerFailure` 對 401 本來有「API Key 無效，請確認它屬於所選服務。」，但被 `app/api/world/route.ts` setup 區塊的 `catch` 換成通用文案。
- `wrangler tail` 的 `world_api` 事件只有階段與 outcome，沒有供應商 HTTP 狀態。
- 帳號工作區（建角、開局）的操作不會出現在任何存檔的「操作追溯」選單，UI 沒有入口看。
- Key 已經 401 時，帳號設定仍顯示「模型已就緒」「已有有效 Key」。

### P1　失敗的呼叫照樣扣每小時額度

Key 無效那段，5 次失敗、0 token，全部算進每小時呼叫上限。AI 回合失敗回滾時已派送的呼叫也照算（設計上合理，但模型持續出錯時重試幾次就會吃掉額度）。

### P1　每次模型操作的本站開銷很大

- Key 無效時量到：供應商 0.17 秒就回 401，端到端卻是 19.8 秒，約 19 秒花在 lease、checkpoint 寫入等本站流程。
- Key 正常後，AI 補完與產生數值每次 40–50 秒；一個 8 人的 AI 決策回合約 2.5 分鐘。成功路徑裡模型本身佔多少沒有拆開量。
- 讀取決策追溯約 20 秒才出來（8 筆共 2.7 MB）。
- 回到開局草稿頁，「正在讀取開局草稿…」停留 6–10 秒。

### P1　處理中就出現「重試未完成操作」

每次按「下一回合」後約 10 秒內，頁面最上方就出現「有一個尚未確認結果的操作；重試會沿用原本的識別碼。」和「重試未完成操作」按鈕，但操作其實還在正常進行，之後也成功了。正常等待和真的卡住在畫面上分不出來。這次沒有去按它，不知道處理中按下去會怎樣。

### P1　觀察頁看不出人物在做什麼

- AI 回合的回合紀錄只寫「周曉嵐 開始進行已選活動，完整結果尚未發生。」，人物狀態卡寫「正在進行已選活動，尚未完成。」，沒有活動內容。要到決策追溯才看得到。
- 明細裡的感知詳情，8 人全部是「沒有可接觸的線索」。
- 第 4 回合（21:20）8 個人同時「主動查探：仔細查看附近的情況」並各擲一次感知。每個人都單獨在自己的場所，沒有互動。
- 20 回合內沒看到任何人移動或對話。開局時 8 人都沒指定住處與工作場所（選填沒填），可能有影響，沒有對照測試。

### P2　其他 UI 問題

- **範本開始沒有回饋**：點「用 林澄 的設定開始」後畫面沒變、仍停在原草稿，其實草稿已經建好，重新整理才看得到。
- **首頁「繼續準備世界」卡片**：標題、說明、連結擠在同一橫列，跟下面存檔卡片的直向排版不一致（1920 寬）。
- **等待沒有進度**：AI 補完與形成數值只有「正在補完…」「正在恢復或形成人物…」，40–50 秒內沒有已等多久或取消。
- **錯誤橫幅不會清**：AI 回合失敗後切到規則模式並成功推進，紅色錯誤橫幅還留在畫面上一段時間。
- **運行設定看不出目前模式**：「使用 AI 模式」「使用規則模式」兩顆按鈕沒有選中狀態，只能看頂端的「AI 模式 · 運行設定」字樣。
- **格式錯誤沒指出欄位**：決策追溯只寫「候選欄位格式錯誤」，`field-format` 是所有非記憶類驗證失敗的統稱。
- **無障礙名稱**：人物草稿清單的按鈕沒有可讀名稱；開局人物勾選框的名稱是 `on`。
- **一次點擊沒反應**（未重現）：第 16 回合暫停自動後按「下一回合」，18 秒內回合數沒變，之後再按一次才推進一回合。可能是暫停時還有回合在收尾。

### 已排除

- 草稿清單沒填姓名時用人物概念第一句當名稱：行為合理，只是概念長時清單項目會很長。
- 單一房間的場所會自動選好起始房間。

## 用量

- 建角：8 次數值形成＋6 次 AI 補完，加上 Key 無效時的 5 次失敗。
- 觀察：成功的 AI 決策回合 2 次共 17 次呼叫；失敗嘗試共約 15 次呼叫。
- 頁面顯示的費用都標「部分估算」「費用有未確認範圍」，最後一個計量小時顯示 11 次呼叫、USD 0.0185。完整金額要以 OpenAI 後台為準。

## 建議先處理

1. `methodAssessment.choice` 的語意：放寬驗證，或在 prompt／schema 把 `continue` 限定為「行動類型就是 continue」。
2. 裁定回 `noop` 效果時當成無效果接受，不要讓整回合回滾。
3. 單一 NPC 決策失敗時只重問或降級那一個人，不要作廢整回合。
4. 模型失敗時把供應商狀態（至少 401／404／429／逾時）帶到畫面與 `world_api` log。
