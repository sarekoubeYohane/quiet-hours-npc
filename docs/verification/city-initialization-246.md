# #246 場所初始化與定稿驗證

在「建立城市」選擇場所、人物並填寫住處或其他開局關聯。按「初始化場所」會使用已保存的天上意志模型設定。應用先逐一詢問有相關場所的人物，再以這些描述、已選場所及明示配置取得定稿。回到相同預覽後，可調整新增房間、文字物件、房間連接與步行時間。只有明確按下「開始世界」才保存為運行中的城市。

- 模型輸入只含該人物的設定及可描述的場所。其他人物的私人房間和物件不會出現在逐一詢問的輸入。
- 範本與明示補充優先。共用房間與同房間同名生成物件合併；不同人物的私人房間各有實際身分。天上意志可選擇生成物件的相容狀態，省略候選仍保留先前明列的有效物品。
- 房間連接以房間 ID 表示。已選場所的步行連接保存為成對場所與 1 至 180 分鐘，明示不通行另存。後續移動由 #248 使用這些資料。

## 測試

執行 `node tests/run-activities.mjs tests/city-creation-api.test.cjs tests/character-generation-api.test.cjs`。

- 先驗證未實作時 API 拒絕初始化、實際編輯器缺少控制。實作後，測試以受控 NPC 與天上意志回覆，查驗實際送出的角色資料、同住公共物件去重、私人房間隔離、拒絕未選場所、保留明示不通行與耗時、編輯定稿、開始與重讀。
- 透過實際 WorldApp 控制完成初始化、修改文字物件與再次預覽，然後開始。正式世界 API、SQLite 與受控模型 transport 共用同一條流程。
- 注入已提交但失去回覆的保存故障，重送讀回同一份定稿並保留一次模型用量。初始化沒有推進世界時間、增加自主回合或把草稿寫入角色記憶。來源範本保持原值。

## 相容性

定稿使用既有操作收據保存可重放的結果，使用者確認後才成為世界配置。沒有另建跨工作階段草稿管理。新增的配置需新版執行器讀取。模型產生內容的品質未經付費模型驗收。
