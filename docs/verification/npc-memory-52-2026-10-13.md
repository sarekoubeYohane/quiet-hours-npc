## Red → Green 證據

逐段新增世界 API 測試後才實作。既有基線為 112 世界 API + 24 auth/key + 2 Workers/D1，全部通過。實際失敗再轉通過的代表案例：

| 場景 | Red | Green |
| --- | --- | --- |
| 舊存檔共用短期容量與穩定身份 | 缺少短期正式資料 | 80 筆共用預算、游標重定位、來源未分類 |
| 同次決策選留 | 新候選使 API 回 502，預期 200 | API 讀回長期、版本穩定、同 ID 不重做 |
| 記憶輸入 88 KiB | 大量短期／長期輸入超限 | 優先短期、長期輸入有界但保存不被刪除 |
| 合法 500 字中文舊資料 | 原 512 bytes 預設造成 GET 503 | 4096 bytes 單筆預設，完整選留與重載 |
| 同源身份 | 相同明確 ID 被保存兩次 | 依身份連結；無身份且同文仍各自保存 |
| 接管總量 | 相容投影重複導致超限／無法推進 | 208 KiB 壓力僅淘汰短期，長期完整保留 |
| 極端超長舊文 | 23,000 個「界」被 FIFO 移出，GET 200 | FIFO 前檢查，明確相容錯誤 |
| 重複說服 | 「不會重新擲骰」進角色記憶 | 只留觀察者診斷；正常「擲骰遊戲」原話保留 |

其餘驗收涵蓋不同 NPC 主觀選留、匿名錯誤感知與秘密隔離、無效／越權／過期版本候選整回合回復、已付用量保留、長期硬滿不 FIFO、長時間接管交還、CAS 衝突與提交結果不明重放。既有測試持續驗證純活動續做不增加模型呼叫。

## 範圍與限制

本票只選留原主觀片段，不作信念更新、摘要、遺忘或向量回想。#53–#55 等 #52 PR 合併；#56 UI 未批准。4096 bytes 單筆調整理由見記憶契約；異常超限舊資料明確報錯，原存檔不截斷、不清空。
