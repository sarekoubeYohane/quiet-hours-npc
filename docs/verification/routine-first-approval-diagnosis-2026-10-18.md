## 排序假說與逐步探測

1. **首次核准被字面 selector 擋住。** 預測：同一普通意思換自然語句會收到 null offer；移除首次 offer 的字面前置條件，讓既有裁定明示選一個受限 operation 後，應能保存規則與成果。
2. **NPC 提示將空物件清單當成必須先查探。** 預測：原提示要求泡茶指定具體物件，且未說明可向已知場所提出未確認的普通背景；角色容易持續尋找未配置的材料。提示檢查證實描述缺口；這是可能助因，沒有單獨真人模型 A/B 因果證明。
3. **核准後保存／效果失敗。** 預測：合法核准仍無法 GET 讀回規則或分階段成果。既有 API 與本次測試的合法核准成功，因此不是本次確定性重現的原因。

依原綁定契約，只改 offer 前置條件仍不足：舊候選沒有表達自然語句所指受限做法的欄位，bind 仍須重新字面匹配。補上已付費裁定中的 operation 解讀後，同一命令轉綠。沒有增加額外 dispatch、文字相似度分類器、強制換行動或自動補貨。
