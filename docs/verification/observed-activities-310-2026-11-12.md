# #310 活動觀察驗收

起始基準：`796d5c18596d751d5a210d231d380c49174b9e21`。工作票 [#310](https://github.com/sarekoubeYohane/quiet-hours-npc/issues/310)，母規格 [#303](https://github.com/sarekoubeYohane/quiet-hours-npc/issues/303)。

使用 Chromium 載入真正的 `WorldApp`，經既有按鈕和世界 API 推進與讀取。測試伺服器執行正式 route，使用隔離的 SQLite、固定世界初始條件及受控時鐘。只有模型回覆使用替身；效果、感知、記憶、保存及重送沿原流程。沒有額外 SQL migration。

重現方式：`pnpm test:observed-activities`。在起始版本，規則模式按「下一回合」後，API 成功保存 21:05；重載的主紀錄仍顯示「開始進行已選活動，完整結果尚未發生」。第一個 Chromium 斷言因此失敗。自由裁定同樣重現「開始進行這項活動；活動尚未完成」。接著分別修正開始與進展、未開始與重試、直接控制與舊資料、暫停及重新評估。

| 條件 | 對應證據 |
| --- | --- |
| C1–C2 | 規則模式休息、自由裁定整理小桌及日常重用準備咖啡；三處顯示活動及狀態。開始時 SQLite 的桌面未變，咖啡未生成，直接控制的休息時段結束不報成目標完成。 |
| C3、C5–C6 | 小桌先保存整理、之後才保存清潔；單純續做及重新評估後續做不新增觀察紀錄。另驗後續條件改變失敗、暫停後放棄、同分鐘開始後停止，先前部分成果仍可查看。 |
| C4、C7 | 無原因的否決、確定的投入上限與門狀態、同文案兩次新嘗試、兩位人物與同名對象各自歸屬；同一操作重送維持一筆。 |
| C8–C9 | 原開始與各階段可在重載後查看；舊紀錄有明確事件關聯時使用原有名稱，無關聯時保留原文與缺口。保存前故障與提交後回應不明沿既有恢復及重送路徑。 |
| C10–C11 | 已提交的原續做事件、本人短期經歷和下一次派送的原成果文字仍存在；觀察摘要未進入模型輸入。規則模式及直接控制走原按鈕，查看及單純續做不派送模型；咖啡重用已存日常規則。 |
| C12 | 上述紅燈、實際畫面、測試與固定 SHA 雙軸審查。 |

這是本機隔離證據，未驗證正式站、真實模型、正式 D1 或付費端到端行為。
