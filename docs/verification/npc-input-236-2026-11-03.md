## 最終責任

一般與回想最後派送都經 `prepareNpcDecision`，使用同次準備的 input、schema、messages、context 與實際展示回執。該結果的 `prepareRecall` 承接已驗證的搜尋結果：按原順序移除重複初始來源、預留完整回想、配置記憶、釘選完整正文、重建安排與共用衍生投影，再回傳下一輪使用的 continuation。`models.ts` 不再組裝／篩選可見來源，不再逐欄同步手機、認知、安排、記憶檢視或人物引用。

時序保留為：模型回覆及版本檢查 → 回想搜尋及本人／有效版本檢查 → 續答輸入配置與衍生重建 → `beforeContinuation` → 加入原 assistant/user 續答訊息 → 使用完整 transcript 的末端 body 裁切 → 派送及候選解析。回想配置超限仍在續答前停止；末端 body 超限仍在實際派送前停止。完整 input 的 88 KiB 與派送序列化 body 嚴格小於 164000 bytes 都未放寬。

移除 #235 的 `input`／`recalled` 過渡選項及模型流程的來源選材。純 `npc-input.ts` 沒有 provider 依賴，活動續做、安排線索刷新、手機非時間提醒仍由原共用投影呼叫端使用。搜尋、派送、版本／租約、guard、journal、CAS、SQLite、用量與提交皆留在原外層。
