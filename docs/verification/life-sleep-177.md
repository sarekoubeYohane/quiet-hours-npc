## 真實應用流程與紅綠

測試從世界 API 進入，真正候選／效果／活動／JSON／SQLite 保存重讀。模型 transport 與骰子可替身，沒有呼叫付費模型或正式世界。

- 原程式的睡眠在飢渴升級後切成休息，RED 為 `rest !== sleep`；補上實際睡眠續做與需求訊號分流後，兩小時只 1 NPC＋1 裁定，睡眠需求80→60、疲勞70→60，跨90分鐘、重讀與同ID重送一致。
- 原程式不會依恢復自然醒，RED 為NPC1≠2；補上按恢復積分及共同生命週期結束後，睡眠需求40→20在兩小時自然醒，再由下一個正常決策選擇清醒休息。100起點八小時恢復至20，疲勞另降至30。
- 普通介入不喚醒；真正店主 shout 經可接觸聽覺在兩小時喚醒，只保留兩小時恢復。不同住處、沒有感知機會的喊話不喚醒也不洩露文字。
- 區段內只需6分鐘恢復至界線時，剩餘9分鐘採清醒基線：睡眠21→20.6，疲勞70→69.65，沒有取得完整15分鐘睡眠效果。
- 自審與整合審查補上兩個紅綠：投入上限依實際自然醒界線核對，不被較長估時錯拒；自然醒30分鐘、同輪推至45分鐘時，stage30實際提交、stage480取消，不能漏掉已到期階段或預支醒後成果。
- 否決與明確短投入上限不啟動、不恢復。晚一角色失敗、CAS衝突、提交前／後故障、重載與同ID重送保持時間、需求及進度共同提交／回復；原ID不重派。

命令：`NODE_OPTIONS="--import=$PWD/tooling/verification/no-network.mjs" node tests/run-activities.mjs tests/sleep-api.test.cjs`。本票11條 API 案例；合併後回歸與完整suite由整合記錄補充。

## 限制

24小時為共同有限安排上界；無法在上界內達到自然醒的確認曲線不啟動，不冒稱無限睡眠。足夠刺激沿既有強烈／危險聽覺與直接身體觸覺，非醫學睡眠模型。舊規則沒有 metadata 仍未確認睡眠，不回填歷史。正式模型會否自行睡覺、醒後如何選擇及跨日自然生活仍待另行授權驗收，不因此關閉泡茶問題。
