# #244 開局關聯驗證

在「建立城市」選用場所與人物後，可分開指定住處、私人房間、擁有場所、工作場所及起始房間。人物間關聯記錄由哪一方知道。背景人物可成為關聯對象，不加入自主角色名單。

起始場所和房間若已明示便照原設定。若留空，預覽可從人物範本描述解析「自己的臥室」、「家裡」、「工作的店裡」或唯一的場所／房間名稱。有多間同類房間時可指定住處的私人房間，或直接指定起始場所與房間。變更住處會重新解析依賴它的起點。缺少必要起點時，預覽會指出人物並阻止開始。

「用 AI 整理開局關聯」使用已保存的天上意志模型設定，沿用世界操作的用量與重送規則。模型只能從已選場所中配對，候選需逐字引用既有欄位或使用者描述，具名場所及場景範本類型用於核對候選。建議回到相同編輯器供修改。文字有歧義時，以直接選擇為準。

## 測試

執行 `node tests/run-activities.mjs tests/city-creation-api.test.cjs tests/character-generation-api.test.cjs`。

- 實際編輯器經正式 API 與 SQLite 選兩個場所、兩位全自訂人物，套用受控自然語言建議，新增背景人物與方向性關聯，修改住處及場所名稱後再開始。
- API 案例確認缺少必要起點時無法開始，改住處後只有描述型起點跟著更新，明示公園起點不變，工作場所與所有權分開保存重讀。
- 受控模型嘗試覆寫住處、加入未選場所與無來源的所有權，驗證候選被拒絕。有效候選從同類的兩家店選出其中一家，重送保持同一候選與一次用量。
- 開始後檢查實際 NPC transport。角色收到自己已填的開局關聯與工作場所名稱，其他人物的私人描述、未建立關聯的背景人物及未知道的場所沒有出現在該角色的輸入。背景人物沒有模型回合。

## 相容性

新增的開局關聯存於現有世界配置和各人物的主觀認知，舊世界仍可讀取。新城市使用新版執行器保留角色名單與關聯。場所授權、場所生成及定稿後的初始認知更新分別由 #245、#246 與 #247 接續。
