# #248 場景切換與步行驗證

觀察畫面可切換本次城市的單一場所，依房間顯示人物、文字物件與狀態。觀看選擇保存在畫面狀態。旅行者另外顯示目的地，在實際抵達前不列於兩側場景。

跨場所移動依世界保存的直接連接與分鐘數。明示不通行或未連接時無法直接前往。步行在既有活動計畫與世界時鐘內延續，抵達於第一個達到預定時點的正常回合提交。途中沿用原本裝置、持有物及使用量，並且停止該角色的額外模型派送。離開與抵達才形成物理場景線索。抵達時沿用進出許可判斷。原本未保存路線的舊世界仍由既有移動方式承接。

執行 `node tests/run-activities.mjs tests/city-travel-api.test.cjs tests/world-configuration-ui.test.cjs tests/city-creation-api.test.cjs`。正式 API 建立世界後，以受控 NPC transport 指定 35 分鐘步行。在 15 與 30 分鐘重新讀取同一計畫，確認原操作重送沿用已提交版本。45 分鐘回合觀察到抵達，手機仍為同一物件並跟隨角色。實際掛載的場景控制驗證來回切換、分房、文字狀態及途中清單。模型輸入驗證目的地的角色在抵達前沒有看見旅行者或其裝置，途中遠端訊息保存且未在目的地發出可聽通知。

先重現原本在首個 15 分鐘回合就出現在目的地，以及場景切換控制尚未提供。測試使用掛載的 React 及 SQLite，模型 transport 使用固定回覆。
