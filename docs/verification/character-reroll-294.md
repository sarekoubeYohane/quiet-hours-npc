# 人物重骰與本機隨機性驗證（2026-11-11）

對應 issue：[ #294 ](https://github.com/sarekoubeYohane/quiet-hours-npc/issues/294)。使用者明示要求新增重骰並調查數值不像隨機的原因；此修訂已記錄於 ADR 0012。以下記錄本機實作與驗收；後續依使用者要求整理提交及 PR，未部署或操作正式資料。

## 診斷

按 diagnosing-bugs 流程先建立最小重現，依序檢查預覽固定骰注入、形成公式、共用已存結果三個假說。`node tooling/verification/check-preview-randomness.mjs` 透過真實 API，於獨立的 `dice-diagnostic` 帳號形成三份人物；修正前全為五項 12、精神容量 70、需求特性 1。

根因是互動預覽 `preview-ui-redesign.mjs` 沿用自動驗收的 `diceFaces: Array(2000).fill(4)`，覆蓋每次 d6。正式形成公式本來使用隨機取骰。移除互動預覽注入後，保留模擬模型與隔離 SQLite；固定骰只用於需要確定期望值的測試。修正後三份人物分別為 `[9,11,12,11,7]`、`[11,12,9,6,10]`、`[9,12,13,13,10]`，容量與需求特性也有變化。

此檢查針對固定骰錯誤特徵，不是統計公平性證明；沒有更改既有骰子公式或背景獎勵。

整理 PR 時也移除先前保留的 `show-new-player-ui.mjs` 互動入口固定骰注入，避免從另一個本機入口再次出現同一問題；`new-player-api-journey.mjs` 的固定骰仍用於自動驗收。

## 已實作的重骰

- 已形成、尚未完成的人物，可按「重骰整組數值」，確認後立即保存新五項能力、精神容量與需求特性；取消不寫入。
- 文字、背景判讀及其獎勵沿用，不再次呼叫模型。每組已保存的能力總分固定，仍可配點。
- 完成卡與已建立世界維持不可變。使用者既有草稿沒有被自動重骰。
- 操作 ID 與起始版本先記在本分頁 sessionStorage；未確認操作可在重載後恢復。確定保存的同操作回覆沿用原結果；提交前失敗而尚無保存結果，重試才會重新取樣。
- 版本衝突及帳號不符不覆寫。未確認時顯示上次已保存數值，阻止完成卡或配點寫入。讀回同操作已保存結果會清除 pending、舊錯誤並恢復按鈕。
- 確認區與新結果承接鍵盤焦點；確認文案明示取代原配點。

## Chrome 完整流程

本機入口 `http://127.0.0.1:5191/start`，模擬模型、假 Key、隔離 SQLite。QA 帳號與使用者體驗帳號分開。

1. 開啟已形成草稿，確認初始 `[9,11,12,11,7]`、總分 50、容量 45。
2. 開啟重骰確認再取消，原值不變；再次確認後保存 `[12,9,12,6,9]`、總分 48、容量 80，次數 1。
3. 重載維持同組數值與次數，沒有自行重抽。
4. 注入一次 POST `/api/character-drafts/form` 的 503；畫面保留原值、顯示恢復原操作，配點與完成按鈕禁用。
5. 重載仍能恢復原操作；恢復後保存 `[15,9,12,11,13]`、總分 60、容量 65、需求特性 `[0.8,1.2,0.8]`，次數 2。
6. 保存完成卡後重骰入口消失，數值維持不變。
7. 新開存檔選入完成卡，加入住宅與客廳起點；核對頁沿用最後一組能力、容量及特性。
8. 確認開局進入觀察，實際看到「世界已保存 · 第 0 回合」。
9. 切回 `ui-redesign-demo` 並保留原人物頁；原本林澄的五項 12、容量 70 仍在，新重骰按鈕可用，由使用者自行決定重抽。
