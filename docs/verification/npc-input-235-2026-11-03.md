# #235 一般決策準備與共用投影驗證

規格：[#234](https://github.com/sarekoubeYohane/quiet-hours-npc/issues/234)；本票：[#235](https://github.com/sarekoubeYohane/quiet-hours-npc/issues/235)。基準為 `572ff229`（`integration/npc-input-234` 起點）；沿用 ADR 0001、0008、0009。沒有修改領域規則、prompt 語義、容量、排序、migration 或模型次數。

## 責任分界與過渡

`lib/npc-decision-preparation.ts` 的 `prepareNpcDecision` 是實際 `aiDecision` 使用的完整準備入口。它建立一般投影，依既有 `boundDecisionRequest` 收斂實際派送本文，再一次產出最終 input、schema、transcript、驗證 context，以及實際展示的安排回執與通知機會 ID。caller 使用同次結果派送、解析與交付原有提交路徑，不再同步一般決策的各個可見欄位。schema 由 `lib/npc-decision-schema.ts` 保存，既有解析也使用相同定義。

純投影 `normalDecisionInput` 與既有裁切演算法仍在未修改的 `lib/npc-input.ts`。活動續做、安排線索刷新及手機非時間提醒原路徑不改，也沒有增加 provider 依賴。完整準備入口可以修改本次 input/transcript 副本，不寫回世界或收據。

本票保留回想搜尋後、`beforeContinuation` 前的原有來源配置及衍生同步；它們由 #236 收入準備責任。回想末端派送已共用同一完整準備結果，沒有維持第二套派送/schema/context 裁切路徑。搜尋、有效性檢查、`beforeContinuation`、訊息加入及末端 bounding 的相對時序不改。journal、CAS、SQLite、租約、用量及重送都留在既有外層。

## 重構前基準與 TDD

在 production 改動前，先以當時的 `lib/models.ts`、`lib/npc-input.ts` 產生 `tests/fixtures/npc-input-before-235.json.gz`。第一次執行：

```sh
CAPTURE_NPC_INPUT_BASELINE=1 node --import ./tooling/verification/no-network.mjs tests/run-activities.mjs tests/npc-input-equivalence.test.cjs
```

初次捕捉一般、escape 壓力及成功回想，兩種 provider 共 6 組；結果 1/1 通過。隨後新增公開完整入口契約測試，在 production 實作前得到 red：`TypeError: prepareNpcDecision is not a function`（1 pass / 1 fail）。實作入口並接上 caller 後，同一組得到 2/2 green。

再於仍停留 `572ff229` 的整合工作樹，只讀原始 production，以 `/tmp/npc-input-capture-before-235.cjs` 執行同一 sample（不包含新入口測試），補捕捉安排線索、空回想及必要輸入超限。命令：

```sh
node --import ./tooling/verification/no-network.mjs tests/run-activities.mjs /tmp/npc-input-capture-before-235.cjs
```

最後 fixture 共 12 組：ordinary、escaped、cues、recall、empty-recall、overlimit × OpenAI/OpenRouter。兩次 capture 都使用重構前 production；最終測試已移除所有 capture／覆寫開關。gzip 僅無損壓縮完整 JSON，測試解壓後精確比較完整 parsed provider body（含每一則原始 content 字串、schema、provider 包裝）、接受的決策與回執，或完整錯誤與零派送結果；沒有刪欄或寬鬆比對。

世界從同一 seed 建立，角色、記憶、model、訊息及回想結果固定；唯一原本非確定性的世界 `pursuitContext` 在 fixture 建立時直接指定為固定字串，而非比對前正規化。request ID 不在 provider body；決策輸出經 JSON 序列化保存，因此不保存 JavaScript 的 `undefined` 屬性，與 wire JSON 相同。沒有其他正規化。

`overlimit` 是必要角色設定本身無法容納的 synthetic 反例，保護派送前停止，並不宣稱真實保存世界可合法產生任意大角色設定。受影響回想及世界操作的合法容量反例另由既有整合測試覆蓋。

## 本票驗收

受控 transport，預載 `tooling/verification/no-network.mjs`；真實 world API handler、`node:sqlite` 記憶體資料庫與 production SQL migration，沒有網路或付費模型呼叫。

```sh
node --import ./tooling/verification/no-network.mjs tests/run-activities.mjs \
  tests/npc-input-equivalence.test.cjs \
  tests/pursuit-capacity-api.test.cjs tests/memory-selection-contract-api.test.cjs \
  tests/recall-api.test.cjs tests/arrangement-cues-api.test.cjs \
  tests/phone-calendar-api.test.cjs tests/operations-api.test.cjs \
  tests/interrupted-usage-api.test.cjs
```

結果 **105/105** 通過（`/tmp/npc-input-235-green.log`）。其中七組原有測試在未改 production 前另有 **103/103** 基準（主代理 `/tmp/npc-input-234-baseline.log`）；不是以探索期 47 個測試替代本票驗收。

補完 12 組 baseline 後，再跑 `npc-input-equivalence.test.cjs`，**2/2** 通過。新公開入口契約也確認其 transcript 等於最終 input，引用與手機 handle 對應最終展示集合，通知識別來自展示機會，且準備前後世界逐字 JSON 不變。

## 限制

本票尚未將回想來源配置／續答前衍生同步搬入入口；那是已被 #235 阻擋的 #236 範圍。本票沒有發現需混入修正的既有行為缺陷，沒有執行付費模型或部署。受控本機驗證不等同真實 NPC 選擇品質或正式環境驗收。

本票 self-review 對照 #235 與既有責任分界，未發現待修項；implement-spec 的整合分支兩軸 code review、PR 與 GitHub 更新由主代理接續執行。
