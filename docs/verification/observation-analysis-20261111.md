# 觀察與分析 UI 整理（2026-11-11）

使用者要求：觀察頁頂部兩個收合區與分析頁仍混亂，依新建流程的整理方式重新設計。沿用先前授權：保留既有功能、資料語意及資料保護；本機隔離驗證，不部署正式站。

## 盤點與設計

現況：存檔管理、模型模式、世界時間、自動推進與費用摘要共同把世界推到畫面下方。分析頁開頭先列操作 ID／實錄，接模型、時間、費用、自動推進，最後才是角色狀態與世界紀錄；所有用途串在一頁，人物資料又擠在半頁窄欄。

本次將觀察頁的存檔與運行設定改為時間旁的明示工具入口，一次展開一組工具；下一回合保持主要動作，自動運行時暫停直接可見。運行設定同時放模式、模型入口及自動節奏；提示模式與節奏限本次頁面，模型／Key 另外保存。未就緒時顯示缺少的設定與解決入口。

分析分為四個目的明確的區域，切換只改畫面，不推進世界、不呼叫模型：

| 區域 | 已有能力與新位置 |
| --- | --- |
| 人物分析 | 左側選人物、位置、活動、人物檔案；右側分近況與需求、追求與生活、記憶與信念。保留精神電量、身體需求明示啟用、追求來源、成果、習慣、記憶／信念／安排／喜好與歷史缺口。 |
| 世界紀錄 | 事件與感知按新到舊分批顯示，可篩人物；全部既存事件仍能展開。日常與物件保留手機私人紀錄、日常規則、進度、成果、物件、外在狀態與自然變化；技術來源置於詳情。 |
| 用量與費用 | 玩家用量、共用服務限制、已發生估算、未來推估、預算與價格入口。未確認用量、缺價與不完整估算保持明示。 |
| 操作追溯 | 原操作重送、近期證據、完整決策實錄、缺口、保存範圍。錯誤的「分析詳情」直達此處；費用入口直達用量。 |

存檔另存、刪除與恢復保留原 SaveActions；模型／Key 保留原 ModelSettingsPanel；操作 ID、帳號綁定、讀回與版本檢查未重寫。完成角色啟用等寫入保持明示。已保存狀態與人物主觀內容仍分開；已無來源者不補造。已知場所改顯示名稱，未知識別保留原值便於追查。

## Bug #295：分析返回觀察失靈

[GitHub issue #295](https://github.com/sarekoubeYohane/quiet-hours-npc/issues/295)。Chrome 重現人物檔案的「查看分析」只改本機畫面 state，URL 仍為觀察頁；頂部「觀察」連到相同 URL，因而未切回畫面。HEAD 原有實作亦存在此不一致。

依 diagnosing-bugs 先排序「畫面與 URL 不一致」、「事件被攔截」、「舊狀態恢復」三個假說；檢查原導覽未攔截事件，且無載入／恢復仍能重現，收斂到第一項。公開 UI 組合測試先失敗，再修復單一機制：同一存檔的畫面切換同步 `view`，頂部導覽呼叫相同切換介面。保留其他 query、hash、history state、原自動停止行為，以及修飾鍵的原生開啟方式；不更動存檔或發出 POST。

修復後測試通過，Chrome 重新走完「觀察 → 人物檔案 → 人物分析 → 頂部觀察」、未送出介入保留及分析重新整理，回合均不增加。後續依使用者要求將修正整理提交及 PR，issue 留待合併後關閉。
