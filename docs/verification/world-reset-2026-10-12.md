測試介面沿用 #19 已確認的世界 API 與 SQLite 保存邊界：`node tests/run-auth.mjs tests/reset-api.test.cjs` 以真實路由、登入與儲存模組執行，GitHub HTTP 與模型 HTTP 為測試替身，D1 SQL 在記憶體 SQLite 執行。沒有付費模型請求。

## Red → green

1. `reset` 操作：先失敗（`400 無效操作`），加入 `resetWorld` 與路由分支後通過。回傳初始種子世界、`version + 1`、`operationSettled:true`；GET 讀到同一個世界，店主控制回到自主，下一回合是第 1 回合。
2. 用量保留：付費回合 4 次呼叫後重置，`aiUsage` 與重置前完全相同，角色、記憶與事件回到種子；每小時上限 3 次時推進前即被拒絕（429、`limitReached`），證明重置沒有清掉本小時用量。
3. 帳號隔離：兩個受邀帳號各自推進，重置一個帳號後另一個帳號的世界與版本不變。
4. 重送：同一 `operationId` 的重置在後續推進後重送，只回傳原結果，不再重置，世界與版本保持最新。
5. 租約競爭：另一頁的付費回合持有租約時，重置得到 `409 retryable:true`；回合完成後重置成功，且保留該回合的付費用量，`version` 連續。
6. 舊版資料：把資料列改成沒有意圖、感知、店主與操作日誌的舊世界形狀（版本 7），GET 以相容預設載入；重置不需 migration，版本變 8。
7. 受理前檢查：缺操作 ID 回 400；帳號 scope 不符回 409，世界版本不變。
8. 舊故事的操作：重置前建立、尚未送達的 `intervene` 在重置後重試得到 `410 operationExpired`，新世界事件數仍為 1；重置前已定案的 `advance` 仍可重放原結果；重置後的新操作照常。

## Review 修正

兩路審查（文件標準／規格）後修正：

- 確認鍵競態：自動運行中開啟對話框，排程的推進可能先佔住 `busyRef`，按確認後靜默略過。現在開啟對話框即停止自動運行，確認鍵在回合處理中、有未完成操作或角色行動中停用。
- 提示順序：AI 模式用量達小時上限時，重置回應帶 `limitReached`，原本會以「已達用量上限」蓋掉重置成功提示；現在重置提示優先。
- 舊故事的操作：重置把日誌時間水位抬到重置識別碼時間的前一毫秒，見第 8 項（先失敗：同毫秒的新操作被誤判為過期，改為 `issuedAt - 1` 後通過）。
- 「延續活動省下的決策」屬舊故事統計，重置後歸零；小時呼叫與 token 統計照舊保留。
- 補上詞彙表「重置世界」、`docs/design/world-operations.md` 的 reset 與 #27 歸屬、README 對 #27 與雲端驗證範圍的措辭。
