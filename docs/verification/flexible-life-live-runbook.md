# 柔性生活安排與手機：後續有限正式驗收交接

本輪未部署、未呼叫付費模型、未操作正式世界。這份文件供之後取得明示授權時使用，沒有建立排程或自動執行任務。機制證據見 [A1–A30](flexible-life-185-verification.md)；真實模型是否自然安排、忘記、查看或自主取捨仍未驗。

授權前先核對正式部署SHA、對應整合PR、場景隔離能力、既有模型／Key、原世界歷史及預算。記錄世界版本／context／世界時間、四角色控制／活動、需求、安排、裝置身份／位置、收件匣／calendar版本、提醒去重及用量起點。不能為製造案例重置原世界、補造閱讀歷史或將觀察者trace灌回NPC。

驗收授權須具體包含有限的實際時間、世界回合／分鐘、calls／tokens上界與停止條件；沿既有整輪deadline／租約／預算。未明示授權不提高預算、換模型、手改時間或啟用背景工作。一般觀察可先限定一項安排及一則私訊；不以固定輪數一定出現規劃或閱讀作通過標準。

依真實決策順序觀察：形成安排／實際寫入→時間或本人可知條件→裝置普通通知／可能漏掉→主動列表／閱讀→自主解讀、延期、續做或放下。對照原文、真正讀者、實際模型輸入、condition版本／generation、通知perception、decision-handled及已提交活動進度。已送達、已察覺、已讀、相信、回覆及安排完成必須分開記錄。

遇格式錯誤、provider失敗、預算／deadline停止或保存不明時立即停止自動推進並留證。保留原operationId，先用既有read-only lookup確認journal；不得用新ID重送相同故事操作來繞過uncertain。已知用量照原契約保留，有限trace缺口照實記錄，不從最後世界猜原輸入。

報告分開列「已觀察到」「未到達」「技術中斷無法判定」。沒有看到角色查看，不等於未讀帳本失效；fixture成功也不代表真實角色必定照做。完成後確認自動運行停止、世界及物件身份保留，記錄最終用量與仍未驗項目；不自動關閉其他生活循環或正式站行為票。
