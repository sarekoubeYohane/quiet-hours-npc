# 只保留一套規則，舊固定世界改為範例內容

舊固定世界（Cass、Vera、Kris 與咖啡店老闆）與開局流程建立的世界各走一套規則，每個新功能都要處理相容分支，文件也因此互相矛盾。2026-11-16 使用者確認：只保留新規則，舊固定世界的人物設定、地圖與素材改為範例；用範例建立的世界和其他世界完全相同，沒有例外分支。直接控制不隨舊世界移除，改為新規則世界的功能。

## 決定

- **範例**是內建的完成人物卡、場景與安排。存檔頁「用範例開始」預填開局流程，使用者核對後才建立獨立的世界存檔；範例人物卡與場景也可在人物庫、場景庫單獨選用。
- 範例人物的數值事先設計好，不擲骰，但必須落在人物形成規則的合法範圍內，讓範例卡通過與一般完成人物卡相同的驗證。
- 範例有兩個：街角咖啡館（四位人物、三個場所）與最小日常場景。後者原本是「暫存原世界、結束再換回」的驗收模式，改為一般的範例；該進出機制移除。
- 世界內任何人物都可以被直接控制。同一份世界同時只暫時接管一位；單次指定可下給其他人物，每位最多一個尚未執行的指定。
- 舊世界寫死的內容（內建泡茶日常規則、咖啡館供應設定、髮飾設計與說服的 D20 切片、規則模式的固定行為）移除，改由通用機制承接。規則模式下範例世界不會泡茶。
- 既有的舊規則世界存檔在本決定上線時刪除，帳號層級的用量與費用紀錄保留；上線前先備份各環境資料庫。
- 既有圖檔全部保留，包含目前沒有被引用的舊人物圖，供之後呈現世界當前情況使用。

## 考慮過的替代方案

- **舊世界作為另一套規則長期保留**：不必搬測試，但相容分支與文件矛盾會持續累積。
- **舊存檔唯讀保留或轉成新規則**：唯讀仍須留下讀取與顯示舊資料的程式；轉換則必須重算或重擲既有結果。各環境目前都是測試用途，因此選擇直接刪除。
- **只有咖啡店老闆或開局指定的一位可被直接控制**：前者等於沒有把直接控制帶進新規則；後者把觀察時才知道需不需要的決定提前到開局。
- **範例人物只給文字設定、由使用者自己形成數值**：符合既有建角流程，但開始前必須先設定模型並花一次模型呼叫，也無法作為穩定的測試起點。
- **在範例中預先放入已確認的泡茶日常規則**：會跳過最小日常場景原本要觀察的那一步。

## 後果

- 本決定修訂 ADR 0005、0007 的「舊世界可接續」相容原則、ADR 0009 的「舊世界由明示重置導入」，以及 ADR 0012 的「舊 D20 結果、舊能力與進行中活動保留原義」：這些保護的對象是舊規則世界，該類世界不再執行，既有存檔於本決定上線時刪除。對新規則世界內已發生的結果，「不重算、不重抽」的原則不變。
- 同時只接管一位，是因為被接管的人物每回合多一次獨立的模型呼叫，而回合時間預算以有限的呼叫次數推導。放寬人數前要先重算該預算。
- 多數既有測試以舊世界為起點。舊規則程式必須等測試搬到以開局流程建立的範例世界之後才移除；只驗舊規則的測試隨對應程式一起刪除。
- 內建的人物文字範本原本由舊世界產生，隨之移除。
