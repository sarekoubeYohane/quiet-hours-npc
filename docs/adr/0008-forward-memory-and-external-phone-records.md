# 內在安排沿記憶遺忘，手機外部原文沿實際接觸

#185要求角色能忘記及自主放下安排，也能真正重讀手機上的精確記錄；若永久注入安排索引或把手機全部資料投影到物件，兩者會繞過既有記憶與私有知情邊界。決定內在安排僅在當次實際可用記憶保有完整經歷時展示，沿既有Vector Recall及同次認知／意圖；外部記錄另由實際手機操作與有限內容分享承接，通知只產生可感線索，真正閱讀才取得內容。

代價是機械狀態必須分開保存到期、喚起／送達、通知、察覺、已展示決策機會、閱讀及完成，且有限輸入可能暫不展示全部項目。選擇沿原本同一回合副本／journal提交與共同活動生命週期，接受有界游標及明示缺口；不以永久待辦、逐分鐘模型鏈或背景工作保證角色一定規劃或照做。事件／情境提醒沿本人實際可知線索，手機不取得全知訂閱；時間提醒使用裝置的已提交世界時鐘。

工程數值、相容與本地fixture證據見[柔性安排](../design/flexible-arrangements.md)、[手機行事曆](../design/phone-calendar.md)及各切片驗證。accepted指使用者已確認的邊界；本地fixture通過不等於正式站或真實NPC行為已驗收。

#193以同一世界真API／SQLite／Chromium驗證睡眠漏提醒、晚讀、延期與自主放下，並以真正一次Vector Recall接回省略的有效安排；合法forget後不接受舊向量。外部再閱讀建立新經歷，而非從trace恢復記憶。原收訊人身份固定於訊息，不隨手機目前所有者變動；第三人閱讀仍只記真正讀者。工程回退與有限證據入口見[整合契約](../design/flexible-life.md)，不改既有成本／期限或授權邊界。

## #226 分層追求的再考慮關聯

沿用相同安排與條件辨識器，只增加安排到正式追求的穩定關聯，不把提醒另建成永久待辦。連結當時的追求版本與目前版本分開：無關版本變動不令追求失效或重新喚起，已結束／缺失身份則停止該追求的再考慮線索，安排仍獨立保存。代價是需要明示關聯缺口與各自生命週期；不能用追求 ID 取代完整可知安排經歷，更不能從關聯復活已忘或未讀原文。程式／受控畫面證據見[#226 驗證](../verification/pursuit-arrangements-226.md)，不表示真實行為已通過。
