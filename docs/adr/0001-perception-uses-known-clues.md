# 關注條件以角色已察覺線索比對

世界可能知道事件的完整來源與原因，但 NPC 只能接觸部分線索。直接以完整事件比對較容易，卻會讓角色因系統掌握的真相而提前察覺尚未辨識的身分。

決定僅以該 NPC 已察覺的線索比對關注條件；未知來源保持未知，期待與猜測不替代辨識。此邊界影響提前決策及後續資訊的保存，避免未經察覺的真相滲入角色所知內容。

例：等 Vera 的角色隔著門聽見腳步時，可以關注「有人靠近」，但辨識前不能直接匹配「Vera 到了」。設計已於 2026-10-10 的感知 Grill 7 確認，尚不代表功能已實作。

後續補充（Grill 22–25）：感知大失敗可產生錯誤的主觀感官內容，包含誤認熟人或沒有對應外在刺激的感受。關注條件同樣比對角色實際取得的主觀內容；若主觀誤認 Vera，可因該誤認觸發關注，不能因世界知道其錯誤而抑制。候選來源限角色既知／期待資訊，不直接讀取事件的隱藏真實身分。世界真相與診斷標記仍不進入角色上下文。此補充維持本 ADR 的核心資訊邊界，同時明確區分真實辨識與錯誤感知。

## #157 實作補充：可知行動回饋

一般裁定、日常執行及活動階段沿既有 `record → 短期經歷 → 下一次模型輸入` 保存原提案／對象及時點，續做仍不新增決策。採既有 NPC 物件投影重述持有或指定物件的已知公開狀態，並明示它是既有狀態，不能把它當成本次新成果或受阻原因。已知物件身份不表示角色知道供應餘量或私有使用許可；即使日常程式已生成原因，也不能直接灌入角色經歷。

角色自己設定的投入上限與已確認耗時可直接說明；其他程式或模型理由留作觀察者診斷。已提交階段僅描述其步驟與可知成果，不暴露內部五段級別，隱藏狀態值不從效果摘要旁路送入。既有觀察／聽聞及錯誤主觀感知維持原來源，回饋不以隱藏真相校正；餐點已消耗等知識須來自原有角色經歷，而非裁定自述。完整原提案與本人已知語境透過 `actorExperience` 保存，旁人仍由原本公開事件及感知機制取得線索。

沒有新增持久化知識儲存、回饋生成模型呼叫或保存 migration；短期經歷沿原 80 筆、64 KiB 及總記憶容量淘汰，舊世界讀取不補造回饋。限制與本地替身驗證見 [#157 驗證紀錄](../verification/action-feedback-157-2026-10-22.md)，不代表真實模型已停止重複或正式站已通過。
