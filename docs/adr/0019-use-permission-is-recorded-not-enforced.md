# 使用許可只記錄，不作為否決理由

2026-11-16 用真實模型在最小日常場景連續推進時，人物反覆提出同一個一直被否決的提案。店主口頭說「可以借你」，但沒有另外提出授權，杯子的使用許可仍只有店主；Vera 與 Kris 都聽到店主答應，提案每次都因使用許可被否決，而人物只收到不含原因的回饋。7 輪試驗共 12 筆這類否決。

ADR 0005 已決定「所有權、持有、使用許可與物理可行性分開」「未經允許不單獨等同於物理上做不到」，#147 也落實了未經許可的物理操作。但實作保留了舊的授權模式作為預設：人物必須明示要擅用，才會走物理操作。結果是誠實認為自己有許可的人物過不了，明示擅用的反而會過。

2026-11-16 使用者於對話中確認以下四項。

## 決定

1. **物理上做得到、沒有被實際阻止的使用就成立。** 保留「當時沒有授權紀錄」這個事實，所有權與授權紀錄不因此改寫。
2. **不看人物怎麼講，一律適用。** 授權紀錄只決定這次使用被記成「有授權紀錄」還是「無授權紀錄」，不再是否決理由。紀錄用「授權紀錄」而不用「使用許可」，因為物主口頭答應也是使用許可，但不會留下授權紀錄；「無授權紀錄」不表示物主反對。（用語於 2026-11-19 確認。）物件與供應都適用。要讓某樣東西真的拿不到，用物理條件表達（鎖起來、不在場），不靠使用許可。
   別人正拿在手上的東西不適用決定 1 的直接成立：對方已遞出給自己時，拿取直接成立；沒有遞出時，照現行方式交給裁定，可能成功也可能失敗，免費的日常規則重用也不會自動從別人手上拿。從別人手上拿牽涉對方是否抵抗，不是單純的許可問題。（2026-11-19 確認；保留 #147 的現行行為，未另行驗證其穩定度。）
3. **在場的人只是看見，不算阻止。** 物主或旁人在場時行動照樣成立；他們經由原本的感知取得線索，下一次正常決策時自己決定如何反應。
4. **把東西交給還沒表示要接的人，改為遞出就成立。** 東西仍由遞出的人持有，不進對方手裡；遞出期間對方拿取即完成交付，並記為對方給的，不需要遞出的人再提一次，也不需要對方先同意接收。接不接由對方之後自己決定。對方已同意接收時，照原本的方式交到手上。
   遞出沒有時限，在下列任一情況結束：對方拿走；遞出的人改拿去做別的事（自己使用、放下、改遞給別人）；兩人不在同一區域。對方口頭拒絕不會自動結束遞出，要不要收回由遞出的人下一次決策時自己決定。（2026-11-19 使用者於對話中確認。）

## 考慮過的替代方案

- **維持否決，但讓人物知道自己沒有使用許可**：好做、結果確定，但人物會得知現實中不會知道的名單狀態，而且要多花幾個回合回頭請物主「正式出借」，等於要人物配合程式的手續。
- **只放行「誠實以為有許可」的提案**：需要裁定模型判斷人物是否真心以為有許可，這正是目前不穩的地方；同一句交杯提案在試驗中有一次否決、一次接受。
- **物主在場就先擋下**：等於把事前擋點換個名字加回來，還要另外定義在場、表態與等待多久。
- **交付維持否決，改為告知「對方還沒表示要接」**：對方有沒有答應是當事人看得到的事，不算洩漏；缺點同第一項，多花回合。

## 後果

- 使用許可的約束力從「事前擋下」變成「事後可追究」。場景裡「這份餐點只給某人」這類限制不再擋得住別人取用，後果要靠物主與當事人事後的反應呈現。
- 本決定修訂 ADR 0005 的 #147 工程落實中「舊授權效果及既有規則保持原義」：舊授權模式不再是預設的否決依據。「不偽造同意、不改寫所有權、不替他人選擇反應」不變。
- 裁定契約中「獲准才可使用」「口頭台詞不等於 grant」的條文要改寫。物主另外提出授權仍然有效，作用是讓之後的使用記成獲准。
- 免費的日常規則重用一體適用：對世界裡明確存在的物件與供應，授權紀錄不再是重用的前提，只留下有／無授權紀錄。否則同一個動作走裁定會過、走免費重用被擋，結果取決於程式內部路徑。NPC 說明中「已知普通借用方法只在其原許可範圍內重用」要改寫。場所的日常資格（住戶、主人、工作者才能假定現場有普通備料）不是對既有物品的許可，不在本決定範圍內。（2026-11-19 確認。）
- 物主口頭答應不會自動記成授權。判斷一句話算不算答應、對象與條件為何，需要模型判斷，與上面否決的替代方案同樣不穩；授權不再擋事後，它只影響觀察者看到的紀錄。因此物主口頭答應後的使用，紀錄上仍是未經授權。（2026-11-19 確認。）
- 「不能強迫第三者接收」不變；決定 4 只改變沒有接收同意時的結果，從否決改為遞出。
- ADR 0001 的知情邊界不變。人物與旁人不會因此被告知某次使用是否獲准；物主依自己的記憶判斷。不為旁人另開得知管道：旁人只看見動作本身，依自己記得的事判斷，因此人物的認知可以和紀錄不一致，這個落差只有觀察者看得到。（2026-11-19 確認。）
- 有限供應、已消耗、版本與在場等物理前提照舊檢查。餐點已經吃掉時，再取用仍然不成立。
