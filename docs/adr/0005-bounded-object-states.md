# 世界裁定確認有界狀態及外在後果

逐項預列所有物件狀態，會讓合理活動因未寫入某個狀態而無法承接，也使 #125 所選的後果決定權退回固定活動劇本。決定允許天上意志在受約束的狀態描述內確認並保存新狀態，仍保留身份、權限、既有事實及資料大小等檢查；不因此允許任意世界 patch 或模型產生可執行程式。通用變更契約須依本輪範圍設計，不沿用固定活動清單作為永久能力邊界。

本輪涵蓋物件、場所環境及角色身體／外在狀況，讓同一活動的後果可完整保存；不引入生命值或完整戰鬥系統。角色的意願、信念、記憶與自主選擇仍沿既有責任及資訊邊界，不能由外在後果直接改寫。

合法借用活動也可產生經裁定的意外損毀；保存所有權、來源與實際後果，物主的反應仍由本人決定。因此不能用現行 owner-only destroy 讓借用物免於合理意外。所有權、持有、使用許可與物理可行性分開。本輪亦承接未經許可的物件操作，以及刻意對他人造成的身體影響，例如偷拿、損壞、推開或拉住；未經允許不單獨等同於物理上做不到。代價是須區分外在後果與自願配合，不能因持有改變就改寫所有權、偽造同意或替角色選擇反應。帳號／世界隔離、資訊邊界與他人自主仍保持；暫用既有判定，不引入角色表、新對抗骰或完整戰鬥系統。

後果及新狀態影響的合理性主要由天上意志依情境判斷；接受模型可能誤判，並保存裁定理由與前後狀態供查證。程式維持格式、受限效果、權限、資料上限及可機械檢查的一致性約束，不以每項活動的唯一合法後果取代合理性判斷。裁定證據不自動成為 NPC 可知資訊。

已形成狀態的自然變化，由天上意志一併確認可預期的後續變化、時間及條件，再由程式隨世界時間執行；條件改變時停止套用不再成立的變化。這延續已發生事件的後果，避免每回合為熱茶是否冷卻等問題重問模型；代價是需保存可驗證的時間與條件，並處理中途變化、重載與重送。不因此新增離線常駐運行或主動生成無既定來源的世界事件。

分拆後沒有重要差異的部分可先作為整體與份量追蹤，需要分開操作或已有重要差異時再個別追蹤。分拆事實及來源在事件發生時即保存，後續細分不重複產生原物或抹除既有消耗。相較於分拆當下逐份獨立建帳，此方向減少無用細節的保存與上下文負擔，代價是須一致維持來源、餘量及重要差異；不因追蹤粒度改變而改寫世界事實。

相較於每遇到「有茶漬」「濕潤」等狀態便修改程式，此方向容許方法與後果有更多變化，代價是必須處理模型誤判、狀態矛盾、規則適用及可追蹤性。最初決策確認產品邊界；後續工程定稿記於下方實作補充及工程契約，沒有重新開啟已確認的訪談。錯判修正介面仍不在本輪範圍，也不以直接放寬全域驗證器達成交付。

來源：[2026-10-21 Grill Q1、Q2、Q4、Q5、Q6、Q7b、Q8](../design/bounded-world-states-grill-2026-10-21.md)。使用者於共同理解摘要後指示「to specs」，確認本輪整體方向並要求發布正式規格。accepted 表示設計已確認，不表示功能已實作、部署或正式站驗收通過。

## 實作接點（#146）

版本化 `change-state` 已由集中契約、正式自由活動、SQLite 保存與既有分析畫面接通有界新物件狀態；舊 `state` 及既有世界保持原義。具體資料上限與相容策略見[工程契約](../design/world-changes-framework.md)，本機 fixture 證據見[#146 驗收](../verification/world-object-146-2026-10-21.md)。其他能力的落實分列於下方；整體交付以[整合報告](../verification/world-changes-integration-2026-10-21.md)為準，不能以決策 accepted 或單票通過宣稱全部交付。

#148 實作補充：環境與身體狀態保存逐鍵曝光，public須有感知機會，subject僅本人有依據可感到，hidden不自動成為任何NPC知識；觸覺沿既有觀察／記憶／關注而非心理寫入。必要條件以相關鍵及明示位置／持有guard保存，避免無關狀態造成全面失效。身體位移限在場、同場所相鄰可達區域並同步攜物，對方反應仍自主。實作與fixture範圍見[本票驗證](../verification/world-external-148-2026-10-21.md)，不代表正式站通過。

#147 工程落實：物主許可與物理後果以明示版本化 `physical`／`change-state.access` 分開，舊授權效果及既有規則保持原義；新模式共用既有批次、階段與提交，保留知情、可達、版本及有限資源檢查。事前許可不能由後來的 `allowedTo` 倒推，因此在真正提交的物件保存最多 16 筆操作事實、詳細淘汰數及未獲許可累計；理由只留有界觀察者證據，history 不進 NPC。這增加有界保存成本，換取不偽造同意也不抹除已發生後果；不代表 #148–#151 或正式站已通過。見 [#147 fixture 驗證](../verification/world-physical-147-2026-10-21.md)。

#149 工程落實：版本化 `form`／`separate` 保存當前多來源、明示終止事實、份量及共同來源權利，先整體追蹤再按需扣出子件；新產物不能自行指定所有權或許可。跨單位的合理轉化由裁定確認，同單位餘量與新身份、來源可用性、容器連續性仍由引擎檢查；此取捨避免列舉料理／碎裂處理器，也不宣稱物理質量模擬。新形成狀態逐 key 保存可知界線，細分保留 metadata 而不捏造來源個人 history。見 [#149 fixture 驗證](../verification/world-formation-149-2026-10-21.md)；#150–#151 與正式站狀態另計。


#150 工程落實：採離散實際提交時間錨定自然延遲，另保留活動nominal時間，維持原NPC逐slot決策／中斷及資訊順序。將30分鐘拆tick或先收全部決策會改變可知／自主時序，因此本輪不採；同點先已到期自然再角色活動。相關state、位置／持有及future from前提持續檢查，已提交破壞永久失效，無關revision不失效。此取捨不宣稱連續物理模擬，細節見[時間語義](../design/natural-changes-time.md)及[fixture驗證](../verification/world-natural-150-2026-10-21.md)。

相容與回退：新讀取器承接舊世界，讀取不補狀態、來源、份量或確認歷史。寫入新版曝光、份量、自然安排及日常程序後，舊 binary 不理解完整語義，尤其不能保證 hidden 狀態投影；因此資料寫入後的回退須保留新版讀取／執行能力，不能丟欄位或重置。此為發布前應評估的單向資料語義，不表示本輪已部署或改動正式世界。

#151工程落實：新增明示symbolic日常程序v3，重用共用外在效果、來源／份量及自然安排；不以舊drink／wash後果推導新規則。選定當前角色及必要subset後由server重綁版本，新成果fresh身份；舊v1/v2不升格。8個模型核准方法另保留本次原句，同句多scope保留各自範圍。這避免六動詞成永久能力邊界，代價是未知新措辭仍需要既有一次裁定，且32KiB候選與12000輸出tokens只是有限容量。預算仍檢查已知累計而非預約，單次超越剩餘門檻的幅度可能增加。NPC方法投影表示已學知識，不洩漏hidden可行性；權威revision只供執行及觀察者。具體契約／fixture狀態見[工程契約](../design/world-changes-framework.md)與[#151驗證](../verification/world-routine-151-2026-10-21.md)，不代表部署或正式站通過。


Review 工程補充：有限具體來源與普通背景的取捨以當前已保存物件及有界 server-only 規則角色約束保存。成功綁定有限來源後，不因耗盡、損毀或移走便用背景重生；真正新 active 來源仍能接續。每規則最多 8 operation × 8 role，不補舊歷史或舊證據；observer 可看新操作的約束事實，NPC 不接收內部標記。詳見[工程範圍](../design/world-changes-framework.md)與[review 修復證據](../verification/world-changes-review-fixes-2026-10-21.md)。
