# 操作證據隨有界 journal 保存，不進入故事

PR #132 的成功成果無法還原原提案及裁定，而把完整模型對話長期保存或放進世界事件會暴露私人上下文並可能洩漏給 NPC。沿用既有操作 journal 的原子提交與淘汰契約，只保存嚴格有界、經遮蔽的必要證據及原執行關聯；接受超界或淘汰後不能完整追溯，不以額外模型呼叫或猜測補齊。這保留了同 ID 重送的既有語義，也避免診斷資料變成角色可知事實；此界線在後續擴充證據時仍須維持。

## #91／#153：必要投影與完整私有實錄分工

10/22案例顯示必要投影不能回答實際輸入、未變滿杯或正常否決理由；因此擴充原本「不進入故事」邊界，新增同一owner權限下的有界私有實錄，而不是擴大世界JSON或NPC記憶。原journal繼續負責精確重送與近期必要證據，完整實錄獨立保存、查閱、淘汰；快取消失不等於歷史全部消失。這修訂原不保存完整對話的工程取捨，依#153已確認決策直接落實，未重新訪談。

選擇現有D1/SQLite附加表與原子statement內容量trigger；單筆1MiB／owner世界64筆及16MiB源自代表實際序列化body量測。跨context共享上限，不按日數到期，最舊優先；單筆超限、遮蔽、寫入及reset清除失敗均需明示。此成本換取可查當次原輸入與原回覆，仍接受有限容量、憑證遮蔽及供應商／世界／實錄多交易崩潰窗口。世界提交和實錄完成不能相互冒充。

裁定有界explanation與引用事實是模型自述，程式規則／驗證是機械紀錄，維護者猜測是待反證假設。舊事件缺失不補造；固定回覆fixture只證明程式，不證明10/22原事件模型根因，亦不自動關閉#85／#104／#106。工程上限、舊資料及回退契約見[工程契約](../design/operation-evidence.md)。

## #92：持久保存點與不明結果

只有請求結束時寫實錄會丟掉硬中斷與未提交回合，因此改在共用派送的準備、開始、headers／回覆、已知usage及故障邊界逐次await有界保存點；世界候選到CAS／journal確認仍由原交易負責。接受保存點增加D1延遲及寫入量，保留原工作期限／租約與預算；不宣稱provider、世界與實錄可原子提交。prepared只證明準備本文已保存，不能證明fetch已發生；資料缺口與原失敗不得由晚到回覆覆蓋。

私有保存點含跨供應商服務Key的意外echo風險，因此任何本文持久化前先註冊所有當前configured Key並遮蔽；憑證仍不進實錄。逾時後的晚到回覆只作discarded證據，已知lateUsage不回寫原費用或恢復世界執行；最後定案與晚到保存按同一queue排列。超限保留有界機械failure／用量／缺口；淘汰或reset後只UPDATE不重新INSERT舊in-flight操作。

journal仍是精確HTTP重放權威。archive證明ID曾受理而journal遺失時，選擇uncertain且不重派，不從實錄重建原結果。為防這類窗口，在journal未見ID的受理前先查私有archive；archive讀取不可用就明示before-acceptance停止、零模型／零世界效果。這是#92新增可用性取捨，發布前必須套0005 migration；不沿用#91未套migration仍執行新操作的初始退化描述。寫入實錄失敗仍不回滾或改寫已提交世界，保持原journal／用量／提交責任。

歷史理由、模型因果與原10/22根因仍不能從新fixture還原；#85／#104／#106保持獨立診斷及受限正式驗收責任。工程細節與故障矩陣見[工程契約](../design/operation-evidence.md)與[#92本地驗收](../verification/decision-traces-92-2026-10-22.md)。

## #166：完整回合採有界時間預算

#164／#165 與本地 RED 顯示，原固定工作窗口會在合法四角色回合的末次裁定耗盡；2026-10-25 已確認修訂上文「保留原工作期限／租約」限制，以完整呼叫鏈（含回想）及有限保存成本推導一次設定的工作期限、固定租約、收尾餘量與前端等待，接受較長等待與同世界較長占用。保留必要持久保存點、逐 slot 資訊順序、整輪原子提交、已知用量與同 ID 契約，不採續租、背景續接、並行決策、部分提交或新增付費重試。這是已接受但尚未實作的設計；具體數值、完成能力範圍、舊 client 相容及故障驗收以 [#166 規格](https://github.com/sarekoubeYohane/quiet-hours-npc/issues/166)為準，[決策紀錄](../design/round-deadline-grill-2026-10-25.md)保留理由，#85 仍獨立驗收。


## #168 工程落實

以最多四角色的完整合法鏈推導 400 秒工作、30 秒收尾、430 秒固定租約及445秒前端等待；25秒完整聊天及10秒完整回想包含自身保存，外層另留60秒累計餘量，避免只增加末次 timeout。接受較久的同世界占用，保留逐slot資訊、原子提交、冪等、已知用量與必要await保存。不可取消尾端不能恢復候選執行；結果不明仍查原journal。原pending按原存絕對期限，舊125秒client在新付費受理前更新。完整支援包絡與取捨見[工程契約](../design/round-time-budget.md)，本地與正式驗證分列於[#168報告](../verification/round-time-budget-168-2026-10-25.md)；不以此結案#85／#106。

## #92 已知用量恢復的原子去重回條

2026-10-29 中斷 RED 顯示，正常 usage 已 durable 仍可能因原 worker 未收尾而永久漏入世界統計。採用既有有界 journal 的獨立 accounting marker，與用量在同一 owner row CAS 入帳；正常提交也原子寫入 marker，原 worker 晚到只補尚未入帳差額。原 HTTP receipt 與故事保持獨立。新 trace 保存原窗口與歷史價格；舊資料缺少可靠去重基礎時明示無法核對，lateUsage 不參與補算。接受有限容量／崩潰未知窗口，淘汰未定案 marker 留有界未知範圍警示；不建立無界帳本或以重派送補證據。詳見[工程契約](../design/operation-evidence.md)。
