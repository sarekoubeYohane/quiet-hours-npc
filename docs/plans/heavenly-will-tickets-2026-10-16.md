## #93 預定票面

## Parent

Part of [#87：觀察介面、自由行動與世界視覺](https://github.com/sarekoubeYohane/quiet-hours-npc/issues/87)，對應 §4、§4.1、§5、§7。

## What to build

玩家完成獨立裁定配置後，NPC 可用範本外方法取得並食用已確認可供應的餐點，世界真的保存取得與消耗；費用計入玩家預算並能在介面辨識。本票交付第一條完整自由行動路徑，包含必要前置整理、有限派送方案、最小受限效果及失敗處理，不只新增 eat 動詞、設定畫面或空框架。

以各自能完成的取得／食用行動驗收首次接線，不把跨回合活動提前宣告完成。穩定物件身份與基本生命周期在此建立；跨角色借還由 #94 擴充，同一活動的跨回合階段與中斷效果由後續「日常活動分階段推進與中斷成果保留」票交付。上述分工不縮減 #87 的最終驗收。

## Acceptance criteria

- [ ] 開頭以可執行的窄情境落實最小受限效果契約，明確目標、方法、目的、前提、供應具體化、穩定身份及消耗生命週期；提供成功、否決、無效候選與重送例子，隨同完整 API→執行→保存→畫面路徑交付。
- [ ] NPC 可提出範本外方法，經 #74 的獨立裁定形成可組合的受限效果，不全部映射回舊動作白名單、不接收任意世界 patch。模型可依既有契約建議能力／難度及受結果約束的後果，但不擲骰、不指定骰值或最終級別；必要判定、同條件不重擲及後果驗證沿既有引擎。
- [ ] 裁定服務／模型／認證可在既有設定介面配置並讀回，與 NPC 任務、上下文及請求歷史分開；裁定只取本次相關權威條件，不整包取得私人記憶／意圖。沿既有 Key 保護，不要求兩把不同 Key，也不自創公開測試入口。
- [ ] 手動／自動 AI 啟動及世界 API 都要求完整裁定配置，未配置時引導補齊且不派送 NPC／裁定模型。新舊世界均適用；讀取、存檔、規則試玩保持可用，查看設定不額外發出付費驗證請求。
- [ ] 裁定由玩家自己的 Key 自付，與 NPC 呼叫共用玩家預算，每次派送檢查；明細區分任務且總額不重計。既有站主服務帳本不被誤用，未知價格、失敗已知用量與停止原因沿 #78。

- [ ] 已確認供應範圍限制餐點具體化；取得與食用後均可重讀，消耗後同一物件不能重複食用或憑名稱重生，不默認補貨。fixture 明示場景與使用條件，不替正式咖啡館新增菜單／價格。
- [ ] 世界前提不成立、尚無法支持提案與技術故障分開呈現。一般否決不要求玩家逐次批准、不因否決停止世界，不虛構缺貨／成功；角色只取得可知結果，食用不強制清意圖，不加反循環提醒。
- [ ] 維持感知、社交自主性與授權邊界；存在不等於已知或可使用。新方法、需他人同意與前往別處仍由 NPC 決定，不把完整目標暗中執行成多個角色選擇。

## #94 預定票面

## Parent

Part of [#87：觀察介面、自由行動與世界視覺](https://github.com/sarekoubeYohane/quiet-hours-npc/issues/87)，對應 §4、§5；沿 #93 的裁定及世界效果能力。

## What to build

NPC 在具有效同意與場景條件時借用普通用品，可攜帶、轉交、洗淨或改變狀態，再歸還同一物件。觀察者經畫面與重讀能確認身份、持有人、所有者及狀態連續。

本票以跨多次角色決策的借杯→攜帶→洗淨→歸還作完整路徑，擴充 #93 的同一身份／效果機制，不另造物件引擎。長時間單一活動的中間階段、活動中斷及階段前提變動由後續階段票處理；不把那些驗收假裝在本票已完成，也不把整條借還腳本當一次 NPC 行動。

## Acceptance criteria

- [ ] 普通備品按已確認場景範圍管理，需跨事件辨識時沿 #93 同一機制具體化；位置、持有人、所有者及狀態保存／重讀一致，不能因名稱相同複製物件。
- [ ] NPC 自由提案經受限候選完成借用、攜帶、授權轉交、洗淨或狀態改變、歸還；各結果可讀回且可在近況／分析辨識，不以新增固定整段腳本或只寫台詞交付。
- [ ] 借杯→攜帶→洗淨→歸還維持同一身份，持有轉移不改所有權，歸還不生成新杯或偷偷刪除舊杯；借出物品不因備品範圍每回合復原。
- [ ] 場景供應、前提與必要同意都須成立；他人是否同意由其自主決定，拒絕／未同意不被說服結果覆蓋。需要新方法或前往別處時交回 NPC，不由裁定代選。
- [ ] 消耗、損毀與已改造狀態對後續合法操作生效；不存在、已消耗或不符條件的物件不得憑名稱重生、重複使用或代換。
- [ ] 角色只取得可知結果，不因權威身份得知隱藏位置、所有者或他人秘密；既有感知與觀察者追溯隔離保持。
- [ ] 沿 #93 的玩家付費、配置門檻、有限派送與錯誤分類；模型不擲骰／直接改世界，已可由程式處理的效果不增加呼叫，不加入主動事件或防循環提醒。
- [ ] 越權／無效候選、版本／租約失效與保存衝突不能留下當前回合半套變更；重送、重載不重複轉移、改造或擲骰，已知用量保留。
- [ ] 以世界 API、NPC／裁定替身與真實應用瀏覽器 fixture 完成成功／拒絕、跨回合、持有／所有分離、已消耗／損毀、保存失敗與重送驗收；同意與場景用明示 fixture，不要求真實角色固定台詞或必然答應。
- [ ] 不引入完整金錢／物流、逐件普通備品清單、背包遊戲、私人物品或新家設定；沒有專屬動畫時使用真實短描述。

## 新階段票預定票面

預定標題：[天上意志] 日常活動分階段推進與中斷成果保留

## Parent

Part of [#87：觀察介面、自由行動與世界視覺](https://github.com/sarekoubeYohane/quiet-hours-npc/issues/87)，對應 §4.2–4.3 及活動階段驗收。

## What to build

NPC 的一項日常活動可包含必要小步，世界按少數有意義的活動階段逐步留下物件變化。活動中斷後，已完成成果仍存在；其他角色在具知情與權限時可接觸現場。原條件改變時，尚未執行的階段不能沿過時候選完成，角色自行決定下一步。

以「已獲准借杯→泡茶的中間狀態→角色自行選擇中斷→另一角色移動杯子→後續可知回饋」驗證完整世界 API、保存與介面路徑。沿 #93／#94 的裁定及同一物件機制擴充，不新增進度引擎副本、骰法、任意腳本或背景事件。

## Acceptance criteria

- [ ] 一項同目的、同場景且不需新選擇的日常活動可含必要小步；受限階段候選明確效果、生效時點及前提。需要同意、前往另一地點或新方法時交回 NPC，不暗中代作選擇。
- [ ] 少數有意義的活動階段沿既有世界時間與活動計畫推進，不逐個手部動作記錄；已執行物件位置、狀態與資源變化可重讀，未完成活動無未來成果，不以活動開始即套用全部效果實作。
- [ ] 已驗證的階段由程式推進，純階段續做不預設新增 NPC／裁定呼叫或重新擲骰；沿 #93 已定有限派送方案。若工程需調整方案，明確說明且仍有界，不把分階段當無限派送授權。
- [ ] NPC 依既有可知線索自主選擇繼續或中斷；中斷保留早先已完成並提交的成果，未執行部分不因時鐘前進自動完成。續做／重載不重頭套用舊效果，未中斷活動保留原進度與完成時間。
- [ ] 其他 NPC 在具知情與權限的 fixture 中能接觸中間狀態；活動計畫不凍結場景，不憑活動存在授予使用權或秘密。
- [ ] 每階段生效前檢查相關前提仍成立；杯子被移動、物品已消耗、使用條件已變時，不依過時候選完成、不復原他人已提交變化、不生成或暗中改用替代物。
- [ ] 前提變更不直接揭露權威真相。NPC 只取得既有感知允許的線索，例如實際看到原處沒有杯子；不自動知道去向／移動者，由其決定尋找、詢問、換方法或放棄，不加反循環提醒。
- [ ] 區分遊戲內活動進度與技術回合原子提交：當前回合無效／過期候選、租約失效、預算／服務／保存故障仍一致回復並保留已知用量；不撤銷早先已提交階段，正常中斷也不標為技術失敗。
- [ ] 活動階段、物件結果與完成／未完成可從世界 API 重讀並在既有近況／分析以真實短描述辨識，不要求新增頂層頁面或專屬動畫，角色輸入不引用觀察者診斷。
