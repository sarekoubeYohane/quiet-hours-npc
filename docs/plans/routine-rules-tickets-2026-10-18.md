- [ ] 首次合法泡茶提案在既有每 slot 最多一次裁定內，形成可驗證、可保存的規則與必要日常背景；規則核准與當次完成分開，沿世界時間及受限效果留下真正飲品／物件狀態。

### T2：同一日常範圍承接多種活動，保留供應與物件差異

## Parent

## What to build

讓一次核准的咖啡館一般餐飲範圍承接真正不同的活動，至少由泡茶延伸至咖啡或簡餐，並包含餐具清洗的物件連續性。玩家能看到不同活動的可重讀成果，後續活動不用逐項向天上意志重新核准。

一般日常材料不要求逐份庫存；既有有限供應、明確稀缺與指定物件仍有效。本票沿 T1 的通用規則／背景與原有物件引擎擴充，不另造物件系統或只加一份固定咖啡館動詞清單。

## Acceptance criteria

- [ ] 首次裁定保存一組有邊界的餐飲活動範圍；完成泡茶後選擇另一項已包含的咖啡／簡餐活動，新增裁定為 0，留下對應的新活動與成果。不能只換標籤、重播泡茶或首次同組每項仍各呼叫一次。
- [ ] 以可組合受限結果與適用條件表達活動族，規則匹配可重用；不需每次詢問另一模型，不以所有自由提案必須映射回固定人物／動詞白名單實作。
- [ ] 一般茶／咖啡／簡餐所需材料可由已確認日常背景承接，無需逐份食材帳本；活動仍依時間和合法條件製作／取得，不能只因背景存在就提前出現成品。
- [ ] 相同世界可同時存在一般日常背景與明示剩一份的蛋糕：一般飲品可正常製作，有限蛋糕只可取得一次；有限供應不能因背景核准、重載、別名或重試而補回。
- [ ] 正常種類、用途與規模受核准範圍限制；大型宴席、特殊改造或不相容用途不能以普通營業規則直接完成，交回既有自由提案裁定路徑。既有已明確損壞／不存在事實保持。
- [ ] 新合法飲品具有必要身份與消耗結果，已喝掉的同一份不復生；借杯／使用／清洗／歸還沿同一杯子，保持位置、持有與所有權區分。
- [ ] 指定杯子已被移走或耗損時，不生成替代杯冒充該物件；活動不能暗中改方法或選擇別的對象。一般備品背景不抹除具體物件後果。
- [ ] 新產物及有限供應結果保存／重載一致；重送與保存失敗沿 T1 保證不重複具體化、消耗或計費，較早成果保持。
- [ ] 既有畫面可分辨各活動成果、有限供應耗盡與具體物件狀態；角色只看見可知資訊。查看不派送，不新增庫存編輯器或完整菜單設定工作。
- [ ] 用 API／瀏覽器 fixture 走同組跨活動、飲品消耗、有限蛋糕與同杯清洗歸還，核對呼叫計數與重讀世界；明示同意、有限供應與一般背景，不能把 fixture 細節當成正式場景固定菜單。

### T3：已知障礙免重複裁定，新例外與條件恢復可接續

## Parent

Part of [#108：天上意志日常規則重用與供應背景](https://github.com/sarekoubeYohane/quiet-hours-npc/issues/108)，對應已知障礙、新例外、相關前提變化與失敗分類。

## What to build

角色在已核准日常活動中遇到明確障礙時，世界依規則回饋可知的未完成結果。相同相關條件下再次嘗試不重複付費裁定；障礙真實解除後能按新條件執行，未涵蓋的新方法／用途才重新交給天上意志。

以同一泡茶規則走完器具損壞／已知缺貨／無使用權、重試、真實條件改善，以及提出新方法的完整 API→保存→畫面流程。沿 T1 與既有有限供應／物件能力即可驗證，不等待 T2 的多種餐飲擴充。

## Acceptance criteria

- [ ] 在規則已能判斷的器具損壞、明示缺貨、沒有有效許可等情況，直接產生合適的未完成結果，新增裁定為 0；NPC 只取得可知障礙，不得到隱藏去向或權限真相。
- [ ] 用新的世界操作再次提出同一嘗試、合理改寫同一提案，均不新增同義裁定，也不重擲同條件判定；不能只用 operationId 重送測試冒充跨次重試。
- [ ] 相關前提與處理結果可保存／重載；真實且具權限的修復、補足或授權變更後，依當下條件執行，不被過去失敗永久阻擋。這裡可用明示場景變動驗證，不要求新增補貨或修理產品系統。
- [ ] 無關角色移動、時間推進或其他不相關變動不造成整組規則全部失效、重新付費核准；失效與重新檢查以實際相關條件為準。
- [ ] 尚未設定的合理日常背景與明確缺貨分開，前者沿首次確認能力處理，後者不能被重新核准抹除。新規則不覆蓋既有物件事實。
- [ ] 規則未涵蓋的具體新方法、用途或情境，沿既有每 slot 最多一次裁定，處理核准／一般否決／unsupported；不能用表面換句話洗裁定，也不將尚未理解的自由提案永久用字面相似度封鎖。
- [ ] 技術／格式／契約／預算／保存故障與世界受阻分開，不能寫成虛構缺貨或永久日常禁令；已知付費用量保留，無效結果不留下半套規則／背景／效果。
- [ ] NPC 可自行堅持、詢問、換方法或放棄；實際輸入沒有反循環提醒、強制意圖清除或觀察者追溯，正常受阻不因此暫停世界。
- [ ] 活動中途前提改變也遵守此邊界：早先成果保留，過時後續不完成；是否繼續、修理或換方法交回 NPC。規則重用不繞過時間或必要同意。
- [ ] 既有近況／分析分辨規則受阻、例外裁定及技術故障，正確呈現有無裁定與實際用量，不偽造模型回覆，查看不派送。
- [ ] 用 API 與真實應用瀏覽器 fixture 走障礙→不同操作重試→重載→條件解除→再執行，以及新例外裁定；核對世界結果、實際 NPC 輸入、派送與保存。對比中標明零新增裁定不等於零 NPC 決策。

### T4：符合條件的角色與場所共用日常規則

## Parent

Part of [#108：天上意志日常規則重用與供應背景](https://github.com/sarekoubeYohane/quiet-hours-npc/issues/108)，對應同場所角色共用、跨場所沿用、權限與資訊隔離。

## What to build

已建立的日常規則可以由符合條件的其他角色共用，也可以在另一個條件已確認的場所沿用。玩家能實際看到另一角色獲准後泡茶，以及同一角色回家後沿用適用做法，兩者都不因單純換人／換地點而重新付費核准。

當地背景尚未確認時，才以有界裁定確認；物資、權限、所有權與整套營業職責不隨規則搬移。依 T3 已完成的權限／相關條件處理，以真實可知投影與跨場景狀態完成整條路徑。

## Acceptance criteria

- [ ] 同場所另一角色在知情、能力、有效使用許可及當下條件成立時，沿用規則完成活動並保存真實成果，新增裁定為 0；不因不同角色識別而重做相同核准。
- [ ] 未知物件／配備、無使用權、能力條件不成立或他人未同意接收的變體不能得到同樣結果；沿 T3 的已知障礙與資訊邊界，不以規則共用替他人同意。
- [ ] 沿既有合法角色選擇建立有效許可，再由受許可角色執行的流程可驗證；口頭肯定本身不自動生成授權。借用與物件所有權、接收同意仍分開。
- [ ] 另一場所已有合適配備、材料及使用權時，沿用適用規則完成新活動，新增裁定為 0；將規則條件綁定新場所的實際對象，不套原場所物件身份／版本。
- [ ] 另一場所合理日常背景尚未確認時，僅在相關提案觸發有界確認；明確不足／缺貨不能當成留白。確認後重載及新活動可沿用，不形成每次換地點重新付費迴圈。
- [ ] 原場所物資、所有權、許可與咖啡館整套職責不被複製；不相容場所／用途不能僅憑同一規則識別強行完成，也不暗中代替角色移動或取得物品。
- [ ] 只在各角色實際可知條件內提供可用活動與結果；規則存在不洩露隱藏配備、持有人、位置或私人資訊，不從觀察者追溯回灌 NPC。
- [ ] 共享仍限同一世界／帳號的存取邊界；其他玩家世界不可讀寫其規則、背景或物件。跨角色或跨場所候選失效不能越權提交。
- [ ] 規則共用後各自活動與具體產物維持正確身份、狀態及階段，不重播原場景成果；重載、操作重送、條件變化與保存失敗延續既有原子性及已付用量語義。
- [ ] 既有畫面與分析能核對執行角色、場所、規則沿用／當地確認及結果；不為本票另建頂層頁面或權限編輯器。
- [ ] API／瀏覽器 fixture 完成原角色→有效許可的另一角色、原場所→條件齊全的新場所，以及當地留白確認／無權／不知情變體；擷取實際 NPC 輸入與派送，核對當地物件與權限未複製。

## Blocked by

- T3：需要已完成的相關前提判定、無權／已知障礙、條件解除與例外裁定，才能正確決定換角色／場所時可沿用、受阻或確認。
- T1 是 T3 的傳遞前置，不重複列為直接阻擋。

本票不依賴 T2：先用泡茶即可驗證角色／場所共用；與多活動範圍整合時沿同一規則契約，由後合併者補必要組合驗證。
