# 實際睡眠工程基線 v1（#177）

以下是工程選定的有界、可重現基線，並非使用者確認的精確生理值。測試沿 #172 已確認的世界 API、真實 JSON／SQLite 保存重讀、既有角色畫面；模型 transport 與骰子可替身，活動及需求不替身。

| 項目 | 基線與理由 |
| --- | --- |
| 實際入睡 | 只有世界裁定明示核准 `bodyActivity.kind=sleep` 並真正開始後，才成立睡眠。NPC 提案或休息文字不等於睡著；舊計畫／舊規則不推測升格。 |
| 恢復曲線 | 建議確認值為疲勞每小時額外 -6、睡眠額外 -14，與共同清醒基線 +1/+4 合成淨 -5/-10；飢餓及口渴仍按原 +3/+6。疲勞和睡眠恢復速率分開，不能互相替代。裁定可在既有有界 profile 中確認不同的負淨睡眠速率；非負淨睡眠變化不能作實際睡眠。 |
| 自然醒 | 睡眠需求降至 20/100 時自然醒。這是停止條件，非完整恢復全部身體狀態；以實際睡眠時間計算到首次達界線，之後時間恢復清醒基線。 |
| 共同長活動 | 使用共同生命週期與 1,440 分鐘有限上界，不增加伺服器請求期限。模型的一般估時與技術推進區段不叫醒角色；每次 API 仍只推進既有有限分鐘。上界是確認能力範圍，若確認曲線與當下需求不能在共同上界內自然恢復，本次不啟動；不冒稱永遠睡眠。 |
| 提前喚醒 | 僅本人已察覺的強烈／危險聽覺，或直接身體觸覺刺激可提前醒。睡眠時不因視覺、普通對話、遠端訊息、觀察者普通介入或飢渴升級喚醒；睡眠中也不把普通視覺／對話與私人訊息當已察覺經驗。原感知機會仍先驗證，未知來源不補明。 |
| 喚醒與自主 | 醒前由共同生命週期結算不晚於實際醒點的已到期階段，仍在當前提交點重驗前提；晚於醒點的未來階段取消，不回填過去事實。醒來結束睡眠狀態並留下可知回饋，不指定起床、喝水或重新睡。下一個正常角色 slot 自主選擇。睡眠不使用可恢復工作暫停槽，不把喚醒當作免費恢復原計畫。 |
| 相容與原子性 | 睡眠 metadata 沿同一世界候選、需求時間戳及操作日誌保存；沒有獨立寫入。GET、重載不恢復需求；同 ID 不重派或重計。既有無 metadata 的世界保留原義，無歷史補造。 |

只證明本地可控流程，不證明真實模型會自主入睡或正式站已驗收。跨日、故障及合併後完整整合另由 #181 核對。
