# 滿載、來源缺口與明示整理（#227）

本節延續唯一 `Character.intents`，沒有第二套意圖儲存或模型呼叫。現有追求在每次正常／回憶後決策均完整投影；滿載不自動淘汰 active 節點。未提及者保留，原版本與全部受影響關係仍須明示。

| 資料 | 工程界限 | 滿載處理 |
| --- | --- | --- |
| 當前追求 | 12 節點、16 邊、4 層、12 KiB | 明示修改／結束，之後歸檔；不盲截圖 |
| 當次追求增量 | 4 項、4 KiB，與心理增量共用 4 項／8 KiB | 不增加額度；大退出分批明示 |
| 當次候選／收斂 | 最多 4 候選／2 KiB，收斂 1 KiB | 空集合合法，超界拒絕，不裁切選擇 |
| 追求實錄 | 24 筆／16 KiB | 既有有界觀察證據與淘汰數 |
| 歸檔身份 | 24 筆／8 KiB | 保存 id／version，淘汰無保存關聯的最舊身份並累計缺口 |
| 完整模型輸入 | 88 KiB | 必要圖／回憶來源優先，省略可選投影並重建派生線索 |
| 實際 provider JSON body | 小於 164000 bytes | 以同一序列化器量測，派送前收斂可選投影；必要內容放不下則停止 |

`archive` 沿原六欄增量，`node=null`、`references=[]`，只接受當次完整展示、版本相符、已 satisfied／dropped，且無保留中下層或當前／暫停活動目的的節點。已結束父子可同批歸檔，依最終剩餘關係驗證，不依模型陣列先後；歸檔按身份穩定排序，避免接近容量時偶然改變淘汰結果。歸檔也占原四項額度。

保存中的安排（包含已結束安排）及當前／暫停活動的目的與歷史 origin 所引用的歸檔身份受到保護，不因 tombstone 淘汰而誤連同名新追求。所有身份都受保護且無空間時明示拒絕，必須先沿原能力整理保存關聯。8 KiB 容納 24 個合法最長 CJK 身份及版本／JSON 結構，不壓縮成僅能保存短 ASCII 的隱性規格。已淘汰身份不提供永久唯一性保證；觀察畫面只顯示有界數與歷史缺口，不能把缺資料補成連續歷史。

明示 drop 可以釋放已結束節點的 context／references／reason／assessment／progress，保留身份、範圍、標準、關係及已結束狀態；原 before 與當次理由仍在有界觀察實錄中。這讓精確 12 KiB 狀態仍有合法結束／歸檔路徑，不因 status 多一個 byte 或評估文字卡死。沒有自動壓縮有效追求。

形成來源與評估來源每次依真正展示、本人持有且版本有效的 short／long／belief／relationship 重驗。來源失效或沒有展示時，形成 context 與該引用不回灌，節點另帶 `sourceGaps` 計數；過去 reason 與 assessment.text 一律不進 NPC。當前 content／scope／satisfaction 仍是角色自己的現有意願，並不代表原文仍可回想。保存原資料供觀察者核對，但私有 trace、未讀手機正文、安排來源與已忘原文不成為記憶旁路。這是來源身份與結構保證，不使用語義模型判定任意自然語言是否抄錄來源。

正常及回憶輸入共同計算完整 envelope，先在原 88 KiB 內預留 1536 bytes 給末端衍生資料；回憶精確來源及其可知安排優先。最後再依實際 system、schema、messages 和 provider body 界限，收斂可選舊狀態、長記憶、認知、方法及線索。每次收斂後重建 arrangements、memoryReview、關係、手機可見引用及投影缺口，不能留下已省略來源的線索。嚴格 short source id/version 配對、80 筆上限與 128 字 ID 不縮小。全圖、回憶釘選來源與當次選擇不裁切；沒有增加輸出 tokens、時限、slot、重試或預算。

所有結果沿原整輪 journal／CAS／SQLite 保存。歸檔、順序、cue 收據、活動與世界一起提交；後角色非法、衝突、保存故障或租約失效皆回復世界，已知用量保留，同 ID 重送不重新派送。受控證據見 [#227 驗證](../verification/pursuit-capacity-227.md)，不等同真實 NPC 行為改善。

外層 JSON 會再次 escape 來源文字。極端引號／反斜線下，即使已存 short JSON 小於 64 KiB、完整圖 12 KiB，仍可能在原 body 包絡超額；最後允許省略輸入副本中的短期來源，明示 `projectionGaps.shortTerm`，保存記憶不變。優先保留已展示安排及通知機會所依據的來源，並移除依賴已省略來源的複本／派生線索；每次重建 schema，只有本次真正展示的 id/version 配對合法。普通 80 配對壓力案例仍全部保留，不靠降低上限通過。
