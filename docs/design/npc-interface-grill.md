## 已確認決定

### Q1：角色可知上下文由共用系統組裝

使用者回答：好。

- 共用系統先組裝並限制該 NPC 可知的決策上下文。
- 模型轉接層只接收已篩選的決策上下文，不接收完整權威世界或其他角色的秘密。
- 雲端與本機模型沿用相同的上下文語義與知情邊界，不各自重做感知篩選。
- 例：Vera 隔門只聽見未辨識的腳步時，轉接層取得主觀腳步線索，不取得門後人物的隱藏真實身分。
- 模型服務網址、認證等連線設定是獨立執行設定，不屬於交給模型的角色上下文。

具體 TypeScript 型別、版本策略與檔案拆分尚未定案。

### Q2：行為指導與輸出契約共用，轉接層僅調整服務格式

使用者回答：是。

- 雲端與本機模型共用 Playbook、知情限制、各階段責任、動作含義、記憶選留規則，以及必要回傳欄位與驗證標準。
- 轉接層可調整 messages／聊天模板包裝、JSON Schema 傳送方式、格式提醒與服務參數；不得改變上述行為語義或放寬知情邊界。
- 不得因模型差異而偷偷省略記憶選留等必要功能，或改變意圖的含義。
- 無法符合必要契約的模型須明確呈現不相容；相容性檢查方式與錯誤處理細節待後續討論。

### Q3：人物資訊區分四個維度

使用者先確認「要分」，再確認補充的第四維度。

- 已知人物：是否知道這個人。
- 可聯絡性：是否具有聯絡該人的管道；不代表知道其當前位置。
- 當前感知：當下看到／聽到的人物或線索；不代表認識對方。
- 身分辨識：當次感知中的主觀身分，可為未知或主觀辨識為某人；不保證符合世界真實身分。
- 四者非互斥狀態。辨識附在當次感知上，不另建第四份人物名單，也不因此新增信心分數。
- 例：認識 Cass 且可傳訊息，不代表能辨識隔門腳步是 Cass；認出熟人也不代表有其聯絡方式。
- 目前 `contacts` 列出全世界角色，`visiblePeople` 使用可見角色的 ID／姓名；需在後續契約與實作中對照此差異。
- 本輪定義邊界；現有四位測試角色可透過初始設定保持互相認識、可以聯絡，不捆綁完整交友／交換聯絡方式系統。

### Q4：互動對象代號與主觀身分分離

使用者回答：ok。

- 模型以不透露真實身分的互動對象代號指定當面互動；系統保留實際對象映射並驗證其仍可互動。
- 例：輸入「p7：櫃檯旁的人，身分未知」，模型向 p7 說話；系統解析及驗證對象，不把角色真實 ID 當作未知對象代號暴露。
- 若 NPC 誤認 p7 是 Cass，當面說話仍指向眼前 p7，不改送真正的 Cass。
- 傳訊息給 Cass 使用已知聯絡管道；與當面互動對象分開。
- 代號有效期限、跨回合延續、離開後重新辨識與記憶引用方式尚待討論。

### Q5：對象代號依主觀追蹤連續性延續

使用者回答：可以。

- NPC 能持續追蹤同一對象時，代號跨回合保持不變。
- 失去追蹤後再次出現、且無法確認是否同一人時，使用新代號；不依系統真實身分暗中建立角色未知的連續性。
- 後來辨識為 Cass，可在當前對象附上該主觀辨識，不自動新增聯絡管道。
- 舊代號可保留在歷史記錄，但不能直接作為當下可互動目標。
- 持續追蹤的具體判定、記憶關聯格式尚待細化。

### Q6：資訊片面與感官失真分開，不向模型揭露客觀對錯

使用者提出資訊隔離本身可能自然產生誤會，並確認保留感官失真、不強制模型演出誤會。

- 資訊不完整造成的理解偏差由模型按實際可知內容自然形成；模型也可保留疑問、詢問或查探，不要求必須誤解。
- 保留既有感知大失敗可產生感官失真的機制；交給模型的是取得的主觀內容。
- 主觀清晰度與是否辨識來源可進入上下文；客觀正誤、隱藏真相、骰值與錯誤診斷標記不進入 NPC 輸入。
- 感官失真不必然主觀模糊，不能因系統知道內容錯誤就額外標註「可能聽錯」暗示答案。
- 此決定沿用現有感知 ADR 的知情邊界，不新增強制錯誤結論或額外心理系統。

### Q7：當前感知與歷史經歷分開呈現

使用者回答：好。

- 共用決策上下文明確區分現在感知到的情境與先前留下的經歷。
- 歷史經歷保留發生時間；再次出現在模型輸入中不代表事件仍在持續。
- 例：十分钟前看見 Cass 在櫃檯旁，是歷史經歷；目前視野內沒有 Cass，是當前感知，兩者不混為即時事實。
- 未看見某人不等於知道他已離開場所；當前情境也須遵守主觀感知與知情範圍，不能以權威世界快照補足未知真相。

### Q8：行動範本外允許自由提案，以有界通用效果承接（B）

使用者要求行動有範本但能提出範本外行動；了解 A／B 差異後，確認直接朝 B 的有邊界自由行動設計。

- 標準行動範本是引導，不是 NPC 能提出的方法之封閉清單。
- NPC 可提出想做的事、對象、方法與預期目的；預期目的不是已發生的世界結果。
- 世界以明確支援的物件能力與效果承接自由提案。候選能力例如移動、持有、放置、開關、阻擋，具體集合尚未逐項確認。
- 可以組合已支援能力形成沒有專用範本的新互動；不僅限於映射既有動作（未採用先做 A 的建議）。
- 世界尚無法表達或承接的效果不能僅靠敘述宣告完成，也不能因模型提及就自動生成所需物件。
- 系統須檢查可行性、裁定不確定結果、驗證狀態變更，並處理時間、中斷、角色可知回饋及一致提交。D20 不代替前置條件判斷。
- 第一個範圍採咖啡館內物件互動；完整能力清單、是否使用 LLM 裁判、呼叫預算與裁定協議尚待確認。
- 這是新增通用行動能力，超出 #66 純介面盤點。後續另拆實作工作，與 #66 契約連結；本次不代表已批准 runtime 實作、增加模型呼叫、合併或部署。

### Q9：採獨立世界裁定階段（B）

使用者回答：b。

- NPC 提出行動方法與目的，獨立世界裁定階段將提案解讀成受限世界操作候選，由程式驗證並執行。
- 既有範本可直接由程式處理；新穎組合可由模型協助解讀，可能增加模型呼叫。具體呼叫條件、預算、逾時與失敗處理仍待確認。
- 裁定階段只讀取處理該行動所需的權威世界事實；模型不得直接寫入世界。
- 回給 NPC 的內容仍限制為該角色可感知的結果，不回傳隱藏裁定真相。

### Q10：角色需求驅動世界建置，使用者確認後納入

使用者提出角色性格完成後，再詢問 NPC 的生活需求來決定地圖；並確認建置提案需經使用者確認。

- 完成角色設定後，讓角色提出生活與互動需求，討論空間、物件及取捨；使用者確認後才納入世界。
- 未來 Cass 與 Vera 的住處可採此流程，讓角色參與決定家中配置。
- NPC 提案是待確認的角色詮釋，不自動升格為人設或世界事實。
- 世界建置提案與世界內行動分開：角色希望有工作桌，不代表執行時可自動生成工作桌。
- 本輪先定義物件感知、互動能力及狀態變更的共通契約；具體地圖、房間與物件清單延後至角色設定完成後。
- 咖啡館可作為契約的測試場景，不在本輪鎖定完整地圖或物件設計。先前的工作桌／共享空間例子僅為說明，未確認為 Cass／Vera 人設。

### Q12：模型容量由轉接層提供，資料選取由共用組裝層負責

使用者回答：好。

- 模型轉接層提供上下文容量、輸出預留量，以及 token 計算／估算方式；不得將 byte 上限視為 token 上限。
- 共用上下文組裝層依相同選取規則與既有記憶契約，在容量內選取資料。共用語義不要求不同容量模型每次取得完全相同的資料量。
- 轉接層傳送組裝結果，不自行截斷或偷偷省略內容。
- 未放入本次輸入的記憶仍保存，不等於遺忘；必要內容裝不下時明確報錯，不任意刪除。
- 完整請求預算須涵蓋 Playbook、角色設定、行動說明等，不只有既有 88 KiB 記憶相關輸入。
- 精確 token 計數不可用時的估算餘裕與具體選取優先序尚待規格化，不在此另改已確認的記憶選取規則。

### Q13：所有模型經過共用決策驗證入口

使用者回答：好。

- 轉接層取出供應商回覆、用量及完成狀態，交回尚未通過領域驗證的決策候選。
- 共用驗證器統一檢查欄位、可見引用、版本、容量與候選一致性；供應商 strict JSON Schema 不替代共用驗證。
- 世界執行層仍負責實際行動前提、裁定與執行。失敗處理沿用既有契約。

### Q15：共用決策契約明確版本化

使用者回答：要。

- 天上意志指定決策契約版本，轉接層按版本呼叫模型，共用驗證器按同一版本驗證。
- 版本為系統間資訊，不要求 NPC 理解或自行選擇。
- 修改提示詞措辭不必然升契約版本；資料結構或行為語義變更需評估版本相容性。
- 舊模型無法提供新版必要內容時明確報告不相容，不偷偷補造決策。
- 轉接層宣告支援版本仍需契約測試佐證，不以標籤取代驗證。
- 具體版本編號、相容轉換與淘汰策略於規格化時細化。

### Q16：系統管理決策識別並綁定輸入與回覆

使用者回答：好。

- 每次決策帶系統管理的識別，綁定 NPC、當次輸入及契約版本。
- 沿用世界版本、operationId 與租約；operationId 識別世界操作，決策識別區分其中各 NPC 的模型請求，不另建提交機制。
- 已取消或失效請求的遲到回覆不得套用。
- 識別及歸屬由天上意志與轉接層保存、傳遞，不依賴模型自行填寫 NPC 身分。
- 此為請求關聯契約；不等於批准 #65 完整輸入快照、保存政策或診斷 UI。

### Q17：NPC 決策與世界裁定分開配置模型

使用者選擇分開，並提出天上意志使用的模型可能需要較大。

- NPC 決策與天上意志的模型輔助世界裁定，依任務分開配置模型；具體模型與大小尚未選定。
- NPC 可使用本機微調模型；裁定可選較大或更適合規則解讀與結構化輸出的模型。這是配置方向，不是較大模型必然更可靠的保證。
- 共用服務轉接能力，但各自使用任務契約、上下文與請求歷史；NPC 主觀資訊與裁定所需權威事實不可混入同一對話歷史。
- 天上意志仍包含程式協調、驗證、擲骰與一致保存，不將整個系統等同於裁定 LLM。
- 模型不可用時不默默切換到其他付費服務。本輪不新增模型設定 UI，不選購或啟用服務。

### Q18：裁定輸入限制為本次行動相關資料
