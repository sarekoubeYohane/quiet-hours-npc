## 已確認的產品規則

2026-10-12 接續設計對話確認：

> 長期記憶可以因重新評估而濃縮或遺忘，不能只是容量滿了就先進先出。

1. 新的主觀經歷進入固定容量的短期記憶。容量滿時由最舊開始移出；尚未處理的內容也可能淡去。接管很久同樣適用，不暫停世界、不增加專用模型呼叫。
2. NPC 在既有自主決策中，依情緒意義、未完事項、關係影響及自身在乎的事，選留短期經歷為長期記憶。一次重大經歷即可選留；不是每筆都轉長期，也不使用統一重要性分數。
3. 長期記憶不因年代久而被新內容擠掉。容量壓力可以要求重新評估；模型須明示要保留、合併、濃縮或遺忘哪些內容及簡短理由。關鍵記憶亦非永久鎖定。
4. **不得以 `slice(-N)`、oldest-first、時間排序截斷或降低上限的方式，隱式刪除長期記憶。** 模型未提出有效取捨時，程式不得代替角色刪掉一筆騰出空間。
5. 選留、評估、摘要與意圖調整合併在既有決策；接管、待命、純活動續做及規則試玩，不為整理而新增自主模型呼叫。交還後才沿既有決策時機處理仍在短期容量內的經歷。
6. 保留已確認的更正方向：舊內容可標記已修正並連結新資訊，不把已撤回看法當現行事實再次灌入。相反看法可以作為未解矛盾共存，不強迫二選一；歷史容量依下方工程限制。

其餘沿用 #50：短自然語言、自由關係標籤、信念先影響意圖再影響行動、當前心理解讀產生當前情緒。歷史感受不是現在情緒；不擴建獨立心理系統。

## 資料與投影契約（工程設計）

- 每筆資料包含穩定 ID、角色範圍、世界時間、短文字、版本，以及有限的來源／已知人物／已知場所引用。具體 TypeScript 欄位於 #52 實作，不建立第二套事件系統。
- 短期 Observation 與既有文字若有明確同源身份，以引用連結；只因文字相同不得斷定為同一事件。舊資料可用角色 ID、原欄位、位置與時間產生一次性穩定身份，重載不得反覆建立新記憶。
- 選留只能引用本次模型可見的短期 ID；合併／改寫／遺忘只能引用本次可見、屬於此 NPC 的有效版本。客觀事件 ID 可用於系統追溯，但不授予角色讀取事件真相的權限。
- 可回憶文字、角色仍記得的來源與系統精簡追溯分開投影；系統追溯不進模型或 Embedding。忘記來源不代表抹掉整段印象；保留追溯不代表 NPC 仍記得來源。
- 假感知是合法主觀內容；不得夾入骰子、錯誤診斷或匿名聲音的真實身份。摘要必須保留聽聞／推測及矛盾語義，不能以世界真相校正。
- 當模型候選超限或引用無效，按決策驗證失敗處理：不保存候選、不隱式刪記憶、不額外呼叫模型修復，沿世界 API 整回合回復並保留已知付費用量。此處不是短期 FIFO 溢位；合法短期溢位本身不中斷世界。
- 正式可回憶內容與版本隨世界一起提交。刪除、合併或來源遺忘後，舊版本索引不能復活內容；索引命中必須經 D1 範圍、版本及可回憶狀態再次驗證。

## 容量與工作量（工程預設，分票實作）

以下為可調整的初始工程設定，不是既有程式上限，也不是額外服務授權。1 KiB = 1024 bytes；集合上限以 UTF-8 的序列化 JSON 計算，包含中介資料，不能只計文字長度。每筆文字另限制 bytes；不切斷 Unicode 或以靜默截字改寫重要語義。

| 每 NPC 範圍 | 筆數上限 | 集合上限 | 每筆主要文字上限 |
| --- | --- | --- | --- |
| 短期經歷，含未處理與接管經歷 | 80 | 64 KiB | 4096 bytes |
| 長期片段與摘要合計 | 64 | 64 KiB | 4096 bytes |
| 現行信念 | 24 | 16 KiB | 512 bytes |
| 自由關係標籤合計 | 32 | 12 KiB | 256 bytes |
| 更正／來源追溯紀錄合計 | 24 | 12 KiB | 短理由 256 bytes，不存完整原文 |

**#52 工程預設調整：** 原單筆短期 512／長期 1024 bytes 無法容納既有介面合法的 500 字中文訊息及敘事前綴，會讓正常舊存檔無法續玩。依既定工程調整授權，兩者改為 4096 bytes，以完整原文選留，不截斷 Unicode 或改寫語義；80／64 筆、各 64 KiB 集合、88 KiB 輸入及總量限制不變。世界 API fixture 驗證合法 500 字中文舊／新經歷；異常超過單筆上限的資料明確報錯且保留原存檔，不自動刪除或截字。

記憶相關狀態總上限先設 208 KiB／NPC，包含引用、狀態與索引同步中介資料；各筆引用最多 8 個、ID 最多 128 bytes。總量仍需保存前驗證，不能因各集合分別合格就略過總上限。此預算不涵蓋既有世界事件、習慣或操作結果快照，不宣稱整個世界儲存已全面有界。

- 短期碰到任一集合上限，依已確認 FIFO 移出最舊經歷；Observation 和接管投影共用同一邏輯容量，不能另設未裁剪副本供角色找回。游標以穩定身份／進度重定位，不跳過保留中的未處理項。
- 長期／信念／關係達到任一上限 75% 時，在下一次正常決策附有限整理候選。最多 8 筆候選、最多 4 項選留／整理操作；無自主決策機會就不增開呼叫。已滿時仍可提出淨容量不增加的合法整理。
- 每次記憶相關輸入序列化總上限 88 KiB，含短期、相關長期、信念、關係與引用。保留短期待處理內容的預算，再選相關長期／信念／關係；整理候選為同一預算內的明示子集。未展示項目不能被模型刪除，也不能被程式當作已遺忘。
- 每次記憶相關輸出上限 8 KiB；候選最多 4 項操作。硬滿而候選未能釋放足夠空間時拒絕整份無效決策，不默默犧牲一筆現行長期資料。這個上限限制單次工作，不保證一次整理所有積存。
- 更正歷史與追溯同樣有界：有效更正鏈保留狀態與必要 ID，完整舊文字不必永存；涉及角色仍記得的內容須併入模型明示重新評估，不能 FIFO 刪掉現行信念或讓矛盾被默默解決。超限候選不保存。
- 自然語言敘事忠實性不可能只靠 schema 證明；自動驗證限權限、引用、版本、長度與狀態，另需有限人工情境檢視。

## 舊世界相容方案與未決邊界

沿用保守相容方向：缺少新版欄位時，以「舊版來源未分類」讀取純文字記憶，作為待選留的近期內容，不自動升為長期或已驗證觀察；Observation 保留原主觀語義，關係文字不自行拆成新信念，不補猜來源、確信或重要性。不清空世界、不重播事件、不在 GET 上呼叫模型或索引服務；在正常自主決策時才選留，提交後才具備索引資格。新版正式保存仍走現有世界更新與操作日誌。

短期 80 筆預設與既有文字記憶容量一致；舊 Observation 依 ID 去重，未處理觀察滿額依本輪已確認的短期 FIFO 規則處理，裁剪同步重定位游標。不能因文字相同就刪除不同經歷，或保留未裁剪的角色可讀副本繞過上限。既有關係以原文字保留，不擅加數值確信。

對正常上限內存檔採確定性轉換；對異常超長舊文字或已超出整體 byte 預算的資料，實作時須先確認實際 fixture 能否遵守相容及上限，不能偷偷截掉舊重要文字。若無法以已確認短期規則處理，回報具體相容限制再決定，不把所有舊存檔正規化重新變成一輪 Grill。

## 回想與服務契約

已確認共用向量索引、D1 權威、帳號／世界／NPC 隔離、每次至多一輪回想。已確定供應商選型，但尚未開通；不可以 D1 簡化搜尋替代。

工程預設：每輪最多 2 個問題、每題最多 5 個候選、合併後最多 8 筆記憶；每次傳輸批次最多 8 筆，以記憶 ID／版本去重。**#55 工程預設調整：** 原「每次索引同步最多 8 筆」改為單次邏輯回想最多追平 64 筆既有正式長期版本、每批 8 筆；否則首次載入 64 筆已提交記憶會迫使用者反覆付費聊天重試。仍共享 10 秒總等待、租約工作期限與持久預算，每批最多三次精確版本就緒檢查，不開背景決策或索引工作。回想只針對本回合開始時已提交的資料水位；同回合候選不能造成等待自身提交的死結。服務寫入成功不等於索引已可查，adapter 必須能證明所需版本水位已就緒；否則依等待失敗處理。

等待及搜尋合計最多 10 秒、最多 3 次服務嘗試。整回合設定 `workDeadline = leaseExpiry - 10 秒`；所有 NPC 共用此期限，不逐角色或每次重試重置。每次聊天、Embedding、搜尋與索引就緒等待的 `timeout = min(localTimeout, workDeadline - now)`，且仍受等待及搜尋合計上限限制。每次付費 dispatch 前重驗租約與各類預算；剩餘時間不足即拒絕 dispatch。抵達 `workDeadline` 必須停止等待並取消仍在進行的請求，將剩餘 10 秒保留給一致提交或整回合回復；取消不代表供應商沒有計費，已知用量仍照實記錄。這些是未實作的初始預設，供 #55 以可控時鐘驗證。

已請求回想而仍未就緒、失敗或預算不足時，回復整回合、保留已知已付用量、停止自動推進並回報技術原因。不保存半套信念／意圖、不讓其他 NPC 部分提交、不把故障寫成角色經歷。相同 operationId 重放原結果；已保存失敗後的使用者新嘗試須讀新版本、使用新 ID。提交不明不得盲目重做外部請求。

**2026-10-13 已確認服務方案與費用歸屬（#51）：** Cloudflare Vectorize ＋ OpenAI `text-embedding-3-small`，1536 維、cosine。Vectorize 由站主 Cloudflare 帳號負擔；Embedding 由站主的 OpenAI API 帳號／Key 負擔；NPC 聊天與自主決策仍由各使用者自己的有效聊天模型 Key 負擔。只使用 OpenRouter Key 的使用者**不需要**另提供 OpenAI Embedding Key。由站主提供 Embedding 服務並不授權開通任何付費資源或設定 Key；實作必須加入站主每月總預算及每帳號用量上限、付費 dispatch 前檢查，超限不得暗中轉嫁給使用者或跳過已要求的回想。各類用量須區分聊天、Embedding、向量索引與搜尋；bytes 預算不是 token／金額預算。可先設計替換 adapter 與模擬服務；測試／正式環境 Key、索引與付費啟用仍須另行授權。本輪不開通、不付費試跑。

設定交接須列出各環境獨立 Vectorize binding／索引、Embedding 模型與維度、站主 OpenAI Embedding Key 與使用者聊天模型 Key 的分離、站主及每帳號各類預算；Key 不寫入文件或世界。Vectorize mutation 為非同步，#55 須驗證可查狀態／版本水位；mutation UUID 不可按字典順序推斷先後。參考：[Vectorize API](https://developers.cloudflare.com/vectorize/reference/client-api/)、[Vectorize 費用](https://developers.cloudflare.com/vectorize/platform/pricing/)、[OpenAI Embedding](https://developers.openai.com/api/docs/guides/embeddings)。

## #55 本分支實作及限制（2026-10-15）

- `lib/recall.ts` 只讀取回合開始的已提交 snapshot；沒有 state 或 state=active 的自己長期記憶才可索引。版本 ID 為範圍與記憶 ID／版本的 SHA-256，mutation UUID 不作排序。
- 無原文 manifest 在 upsert 前保存，涵蓋提交不明；下一次回想清理改寫／已忘的過期 ID。manifest 最多64筆，計入208 KiB檢查；所有索引原文僅為主觀text，不含reason／origin／eventID或診斷。非同步刪除期間仍以D1回讀拒絕舊命中。
- 同次最多兩題、每題五筆、去重後八筆。回想文字連同初始輸入做88 KiB上限檢查，沒有自動截字或簡化搜尋。回想後第二輪要求拒絕整回合。
- `workDeadline=leaseExpiry-10000` 在整回合固定；回想本身另受十秒合計限制。付費 guard 在預算保留後再驗一次租約；聊天fetch及body解析均受取消期限保護。Vectorize binding不能取消已送達的伺服器作業，故保留不明用量。
- 新增本機migration0004：共用付費帳本與世界派生manifest；未執行正式migration。回想關閉時一般GET／聊天不讀取新表或binding。啟用缺少服務、共用帳本、預算、就緒或版本證據都拒絕本回合。
- 付費預算使用跨環境唯一RECALL_USAGE_DB，按UTC月、服務類型同時限制站主總量與每帳號總量；保留為保守units，provider回報的Embedding tokens獨立保存。未宣稱可限制持續向量儲存帳單，正式開通與付費smoke test待另行授權。
- 世界API／模擬服務驗證見 `docs/verification/npc-recall-2026-10-15.md`；此結果不代表正式服務或網站已部署／驗收。

#55 付費guard在同次邏輯回合固定使用advanceActivities的usage；滾動一小時在回想中途到期不能清零當回合上限。GET或下一輪仍按既有視窗規則更新。跨視窗總用量與operationId重放另有API回歸。

#55 所有世界狀態寫入（包含介入、接管、指定行動、交還）提交前共用manifest-aware短期FIFO，將persisted索引中介資料計入208 KiB；滿額只移除最舊短期及相容投影，不刪長期、不額外模型呼叫。若無短期可釋放仍超限，整次操作回復並保留已知付費用量。關閉回想不查新表。

#55 派生manifest可在失敗後保留，因此新增前必須同時驗證目前角色與已提交snapshot角色加plannedmanifest均不超過208 KiB；較早NPC行動造成的短期FIFO縮減不能降低回復基準需求。基準不足時在任何索引／Embedding副作用前拒絕，以免技術失敗後容量整理改動原短期。
