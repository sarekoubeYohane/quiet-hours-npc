# 自主習慣工程基線（#179、#180）

以下是工程選值，並非使用者已確認的精確產品參數。測試沿父規格的世界 API、實際 JSON／SQLite 保存重讀及既有應用分析入口；模型 transport／骰子可替身。

- 延續每角色最多 24 個情境習慣、最近 21 世界日內證據、每習慣最多 14 個不同世界日、30 世界日未出現淘汰；3 個不同世界日且衰減強度至少 0.2 才形成。強度 `min(1,days/6) * 0.5^(未出現天數/7)`，同日不能刷強度。
- 新證據只有已開始的自主行為；整輪保存才成為事實。否決、非法、未開始、純續做、直接控制、規則試玩與回應使用者要求均排除。既有泛稱習慣原樣保留，不回填細分類或來源。
- 新活動語義版本為 `activity.v1`。已確認日常規則採其 operation；通用已確認方法採其模型確認的 program operation。新單次自由裁定可在同次既有裁定確認 `activityIdentity={version:1,key,label}`；key為1–64字英數._-穩定語義碼、label最長64字，裁定可從最近24個本人已確認身份選擇沿用。已知key不得更換名稱，具體物件ID不得作key。角色投影使用本人原提案目的／內容名稱，裁定名稱只供世界分類與觀察者查證，不把潛在隱藏分類名稱灌回角色。舊單次裁定缺穩定方法語義時仍保存真正開始，但明示 semanticGap、不跨日偽合併；不把相同 effect.kind 或提案措辭當成等義證明。杯子或材料實例 ID 不參與方法分類。此分類不是完整自然語意理解。
- 每角色保留最近 96 個已開始自主行為來源（不超過 30 世界日）；記錄時間、場所、語義、開始事件及本人短期經歷引用。是否完成／有效／需求滿足不從開始證據推導。淘汰計數顯示有限缺口。
- 事件關聯候選最多 12 個；每次正常決策最多 2 個，與記憶／認知更新共用既有 4 項、8 KiB 上限。引用限本次實際送出的本人短期經歷 id/version，事件與自主活動必須有時序且間隔至多 120 世界分鐘、同一地點；跨日形成仍依上述 3 日／強度規則。120 分鐘旨在界定『之後』而非因果推斷。
- 事件語義限本人已保存且可見的自主活動語義或主觀觀察種類／來源，不以自由自述補造事件。候選可在來源不足時保持未形成；不能回溯付費分類、不能因重送重新累積。既有資料缺欄位視為無新證據，不追補歷史。
- 回退程式必須保留 JSON 新欄位；舊版若丟棄新欄位，需先保留完整存檔再回退。此版不增加 SQLite schema、不修改租約、模型期限或預算。
