## 相容與回退原則

缺新欄位不表示舊世界已存在需求、喜好或新習慣。讀取不回算舊時間，不補造歷史，不重建規則。各模組明示第一個可寫操作的啟用與資料版本；舊日常方法缺新後果時仍保留其已確認原義。

一旦寫入新版活動、需求、喜好與習慣資料，直接換回不理解它們的舊 binary 不能保證繼續執行正確。回退需保存完整 JSON 與 operation journal，保留新版讀取／執行語義，或在未啟用新資料的副本另行驗證；不能以丟欄位、重置或抹除進度達成相容。本輪不執行正式資料升級或回退。

## 驗證邊界

沿已確認世界 GET／POST API、實際 JSON／SQLite 保存重讀及既有應用 Chromium 畫面。只替身化 auth／Worker bindings、模型 transport、時鐘與骰子；活動、效果、來源核對、提交與原操作恢復使用應用流程。每張票完成適用 API、保存、畫面與故障驗證，#181 再驗跨票順序與跨日場景。

固定輸出測試只證明機制能承接合法選擇，不能證明真實模型會自然吃喝、睡眠、形成喜好或習慣，也不證明原泡茶 loop 已全部修復。正式模型與正式站依另行授權及有限驗收流程執行。

## 同次心理更新與輸入容量

記憶選留、記憶整理、認知、喜好、事件型習慣候選五類陣列，合計最多4項；這些更新連同 `interpretation` 的 JSON 合計最多8 KiB UTF-8，各類原有較小上限仍適用。意圖沿原最多12筆由 NPC 自主排列，不由喜好或習慣代排。候選均核對派送當時實際展示的本人來源，不能因同份回覆選留了一段記憶就猜測它尚未存在的新身份。

現行喜好與相關已形成習慣傾向納入原88 KiB記憶／心理投影預算。超界只省略本次可選投影，不刪除保存內容，也不准修改未展示的喜好。世界物件、場景等原有輸入責任維持，不把88 KiB誤稱為整份世界上下文尺寸上限。回想續接仍核對實際重建的可見集合與原限制，不增加模型 output tokens、伺服器期限或預算。

同份喜好、習慣候選、記憶及意圖維護，和需求、物件、活動及時間共同提交；較後角色或保存故障不能留下半套新主觀事實。實際 D20 外在失敗可以對應喜歡過程的主觀評價，內部骰級及判定數值仍不送入 NPC 的經驗輸入。
