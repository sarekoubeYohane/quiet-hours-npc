# 世界操作的持久重送（#24）

`advance`、`intervene`、`direct`、`takeover`、`return-control`、`reset` 必須附 `operationId`，格式為 `Unix 毫秒:UUID`。識別碼屬於一次使用者操作，網路重試、租約等待與重整後重試都沿用原本的完整 payload。新的使用者操作才建立新 ID。模型 Key 管理不改變世界，不使用此日誌。

## 保存與重放

`worlds.operations` 與世界在同一筆 D1 row。取得現有 120 秒世界租約時，以世界版本、原日誌與租約條件原子寫入 pending；寫入成功之前不呼叫模型。完成時，世界、版本、成功或失敗回應和解除租約由同一條 UPDATE 提交。重送已接受的 ID 回傳保存的 HTTP 狀態與完整 JSON，包含當時世界快照，不重做行動或計費。只有已確認持久化的結果附 `operationSettled:true`；未確認的 5xx（例如重試時登入服務或 D1 暫時失效）不代表原操作失敗，瀏覽器保留原 ID，不能把下一次點擊變成新操作。傳入不同但有效的 payload 仍回放原結果，不把同一 ID 視為新操作。

無效輸入、登入/來源拒絕、Key 未設定等受理前錯誤不建立日誌。另一個請求持有租約時回傳 `409 retryable:true`；API 不讓 Worker 睡眠，瀏覽器每秒用同一 payload 重試，約 15 秒後顯示等待逾時。等待其他回合的重試預算為 15 秒；單次 POST 的回應逾時另設為 125 秒，涵蓋伺服器 120 秒租約，避免正常的多角色 AI 回合被過早取消。未完成操作保留在同分頁 sessionStorage，重整後提供「重試未完成操作」，不自動補跑。重新載入與回到前景會先唯讀確認已保存結果，見下方 #77 恢復查詢。新操作按鈕停用，避免把新意圖誤當作恢復舊操作。

GET 提供 `operationScope`；瀏覽器按已驗證帳號分隔 pending，並把 scope 放入 POST。帳號在兩次請求間改變時，伺服器拒絕舊帳號的 payload。scope 只是避免誤操作，實際授權始終來自登入 cookie。世界不存 API Key；pending payload 也不包含 Key。

## 租約到期與不明結果

每次新的模型 dispatch 前重新檢查租約。最後提交也要求租約尚未到期、版本及 pending 日誌仍一致；旧請求不能覆蓋後來的世界。模型失敗會回復整個回合，保留已發生呼叫與供應商用量，並保存相同的失敗結果。

- 確認 CAS 沒提交時，沿用既有 `retainPaidUsage`，只補入該回合差額，保存失敗結果；重放不重複補記。
- 儲存呼叫拋錯時可能已提交。重新讀取日誌，若已完成即回傳該結果；不能確認時保留 pending 或記錄失敗，絕不盲目再執行模型。
- pending 的租約已過期時，原子轉為 `502 operationUncertain:true` 並讀取最後結果。此 ID 永不重新執行。瀏覽器保留 pending 並提示結果不明，不自動解鎖新操作；需保留 operationId 進一步診斷。
- Worker 在模型請求送出後終止、或 D1 在用量回寫前失效時，無法從本機結果確定供應商已收費多少。本票提供至多一次模型執行，不宣稱可跨外部模型與 D1 做分散式交易，也不猜測/重加不確定用量。已保存用量不重複計入；尚未保存的供應商用量可能缺失。每日共用帳本是 #27 的範圍。

## 重置世界（#25）

`reset` 走同一條租約、版本與日誌路徑，把世界換成初始種子並保留帳號的小時用量統計。重置會把日誌的時間水位抬到重置操作的識別碼時間：更早建立、尚未送達伺服器的操作（例如另一分頁網路中斷時留下的 pending）重試時回 `410 operationExpired`，頁面改為重新讀取新世界，不把舊故事的意圖施加在新世界上；已定案的結果仍可重放。識別碼時間來自各裝置時鐘，水位是盡力而為的保護，不是跨裝置的嚴格排序。

## 有界保留

保留最多 8 個結果。每次取得新租約及保存新結果時以 UTF-8 計算日誌大小，優先淘汰最早 ID 的舊快照，目標 500,000 bytes；當最新單一完整結果本身超過門檻時仍保留它，以維持精確重放，因此實際界線為 `max(500,000 bytes, 最新單一結果+日誌欄位)`。世界與最新回應仍受 D1 單列/字串限制；若因既有大型世界超限而保存失敗，會保留 pending/失敗並禁止同 ID 再次呼叫，不能保證那次世界提交成功。

淘汰時持久更新時間水位。過期 Worker 的遲到錯誤只可更新仍存在且屬於自己的 pending，不會把已淘汰的結果重新插回日誌。找不到且時間不晚於水位的 ID，以及找不到且已超過 24 小時的 ID，回傳 `410 operationExpired:true`，不會因清理而重新执行。仍在日誌中的結果即使超過 24 小時也可重放。落在水位以前的延遲新操作也會被拒絕；客戶端重新讀世界仍不能把已淘汰操作視為確認失敗；保留 pending 供進一步診斷。裝置快於伺服器超過 60 秒時拒絕新 ID 並提示校時。

## #133 操作驗收證據

已受理操作的必要原提案、裁定候選、實際派送／usage、部署與保存結果隨同 journal 原結果提交，僅供觀察者查閱，不進入 World／NPC。單筆證據另有 64 KiB 硬上限，沿用本頁的八筆保留、水位及精確回放；舊、淘汰或未完成的資料不補造。分析頁可讀取近期操作並沿原 POST 重送 advance，同一 ID 不再派模型或重做世界效果。完整欄位、遮蔽及未確認提交的限制見 [操作證據設計](operation-evidence.md)。

## UI 版本與刷新

完成操作後 GET 最新世界；回到前景也 GET。POST 的歷史重放快照與 GET 回應都經版本比較，只接受不小於目前畫面的版本，因此回放舊操作不會把畫面倒退。登入帳號改變才重設版本基準。此票不實作跨分頁共用自動排程（#26）；目前自動推進仍是分頁自己的排程。

## 資料庫更新

部署新版前，對目標環境套用 `drizzle/0003_world_operations.sql`（本機用 `pnpm db:migrate:local`；雲端用既有 Wrangler D1 migrations apply DB 指令，明確指定 test 或 production 環境）。它只新增含空日誌預設值的欄位，保留既有世界、版本、租約及模型 Key。

舊程式雖可讀取新增欄位的資料庫，卻沒有操作冪等保證，且舊瀏覽器不會送 ID。更新後需重新載入瀏覽器；不要用舊版程式處理新日誌中的 pending。回退前停止寫入並檢查未完成操作，不刪除欄位或重置世界。

## #77 恢復查詢與非 JSON 回應

`GET /api/world?operationId=<原 ID>` 為唯讀查詢。依登入帳號取得同一筆 row 的世界、版本及日誌，附 `operation`，不取得租約、不提交回合、不執行模型，也不把到期 pending 改寫為定案結果：

| state | 意義 | 前端處理 |
| --- | --- | --- |
| `settled` | 日誌保存了確認成功或失敗，附原 HTTP `status` 與 `error` | 接受同次查詢的最新世界，解除該 pending；失敗時顯示原因 |
| `pending` | 原 pending 租約尚未到期 | 保留 pending，可明確按原 ID 重試 |
| `uncertain` | pending 已到期，或已保存結果本身標示不明 | 保留 pending，不自動建立新操作 |
| `unknown` | 日誌未找到且未超過保留水位／時限 | 保留 pending；唯讀查詢不把尚未送達的請求變成付費操作 |
| `expired` | 已超出保留範圍，無法從日誌確認結果 | 保留 pending，供進一步診斷 |

一般 GET 不附此欄位。重新載入先取得帳號 scope，再只查該 scope 在 sessionStorage 的 pending；不同帳號不沿用舊 payload。結果與世界使用同一個 SELECT，避免確認較新結果卻顯示提交前快照。

GET、POST 及 Key 管理的前端解碼均檢查 Content-Type、JSON 語法與物件形狀；讀取世界另檢查必要欄位。HTML、空白或無效資料顯示 HTTP 狀態與安全的格式標記，不展示回應本文。非 JSON 的 4xx 也不是應用層已確認拒絕，不能因此刪除 pending。401 仍提供重新登入。GET 期限為 15 秒；既有 POST 的 125 秒期限與 15 秒等待重試預算不變。

此恢復查詢可修復服務恢復後「操作已定案、但頁面仍只知道 pending」的狀態；它不能確認 Worker 終止前尚未保存的供應商用量，亦不會猜測補記。線上最初逾時與 HTML 的來源仍需 HTTP／Worker 證據。
