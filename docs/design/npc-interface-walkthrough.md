# 介面走查：Vera 聽見門外腳步

狀態：#66 設計走查草稿，非執行結果、非正式 JSON Schema，非角色正史。使用者於 Q19 同意使用此案例檢查介面。本文套用已確認邊界；不新增感知規則或額外模型呼叫。

## 測試情境

假設 Vera 在咖啡館儲藏室、靠近已知且關閉的門，Cass 位於門外前台。Vera 先前收到 Cass「晚點會來」的訊息，現在聽見未辨識來源的腳步。這些是示例 fixture，不是修改角色設定或線上世界。

假設 Vera 已到正常決策時機；不以 Cass 的隱藏身分觸發決策。腳步若已停止只能作歷史觀察，不能列成仍在發聲。

## 介面順序

| 接點 | 輸入 | 輸出／限制 |
| --- | --- | --- |
| 世界 → 感知 | 位置、門、事件與適用規則；系統知道 Cass 在前台 | Vera 的主觀觀察：門外傳來腳步聲、時間、感官及主觀清晰度，來源身分未知。客觀來源與骰值不流入角色輸入 |
| 上下文組裝 → NPC | Vera 設定、當前活動與意圖、關門的可知狀態、剛才腳步觀察、先前訊息等可見記憶與 ID／版本、行動範本 | 契約版本與容量受控的請求；歷史訊息不證明 Cass 現在到場，腳步也不自動授予可當面互動的人物代號 |
| NPC → 共用驗證器 | 上述主觀上下文 | 示例候選：保留「確認來者」意圖；選擇打開已知的門。記憶選留與其他候選可為合法空集合；不為展示強制新增信念 |
| 共用驗證器 → 世界執行 | NPC 回覆及綁定的可見引用、版本與請求資訊 | 檢查格式及引用，再檢查門操作前提。NPC 猜想「可能是 Cass」不能直接改寫感知來源或真實世界 |
| 世界裁定／執行 → 感知 | 合法開門請求、相關門與角色位置 | 在本 fixture 可直接按既有規則開門，不必呼叫裁定 LLM，也不必擲不必要的骰。開門耗時沿用現有規則 |
| 感知 → 新經歷 | 開門後當下場景與角色感知條件 | 若此時確實看見並辨識 Cass，產生相應主觀觀察；若人已離開或仍被遮擋，不保證獲得身分 |
| 候選世界 → 一致提交 | 經驗證的意圖、門狀態、事件、各角色可知觀察及操作資訊 | 沿用版本、租約與 operationId 一致提交；失敗不保存半套新狀態，已知用量沿既有契約處理 |
| 下一次合法決策 | 成功提交後角色仍保留的主觀經歷 | NPC 可自行重新評估意圖與行動；不得因本例在同一次回覆偷渡「開門、看見 Cass、打招呼」三步結果 |

## 簡化資料示意

下列是閱讀用摘要，並非可送給現有 API 的完整 payload：

- 當前情境：位於儲藏室；已知門關閉；視野內沒有前台人物。
- 近期觀察：時間 t1，門外傳來腳步聲，來源未辨識。
- 歷史訊息：時間 t0，Cass 說晚點會來。
- NPC 候選：想確認來者；請求開門。
- 執行後新觀察（僅在 fixture 支持時）：看見前台人物，主觀辨識為 Cass。

請求系統資訊另含決策識別、契約版本、世界操作關聯；由系統維護，不要求 NPC 自己填寫。完整欄位、token 估算與容量分配尚待正式契約化。

## 走查結論與未決項

- 未辨識腳步應指向線索／可知區域，而不是向 NPC 暴露隱藏 Cass 的人物 target。人物互動代號不能成為匿名感官線索的身分洩漏通道。
- 主觀推測與感官辨識分開；知道某人可能到來不會自動辨識腳步。
- 既有確定性動作可由程式裁定；獨立裁定責任不等於每次都增加 LLM 呼叫。
- 這個正常路徑不解決自由行動無法映射到支援效果時的產品處理；先前 Q11 已撤回，後續需在通用行動工作中明確收斂，不能假裝已確認。
- 本例未呼叫模型、未執行測試或修改世界。後續契約驗收需用可控 fixture 檢查送出的實際輸入、候選、重讀世界與失敗回復。
