# 個人化身體需求正式政策 v2（#274／#278）

產品數字及取捨沿 [2026-11-09 已批准方案 C](character-dice-energy-recommendation-2026-11-09.md) 與 ADR 0012；本文件只定義工程承接。不是精神電量政策，不新增耐力／d100／五分鐘 UI 交付前置。

`enable-body-needs` 是世界 API 的擁有者明示導入操作。`bodyNeeds` 列出人物 id、可選 source、三項 traits 的合法子集（0.8/1/1.2）、新人物的 initial 或 feelings（區間0–3）。人物已存在需求時保留值，不能藉導入重設；已存在 personal 資料一律拒絕重抽。UI 在既有分析頁逐人確認背景／初值。自由文字不推導數字，GET 不啟用，任何寫入沿原操作ID、CAS與共同保存。

`needs.personal.version=2` 保存一次形成的三特性、允許子集、擁有者來源、請求／啟用時點、待睡眠結束狀態、亂數狀態及目前絕對五分鐘格四顆骰。每新有效格由持久32-bit xorshift序列取四個獨立位置，拒絕最後三個非零32-bit狀態，以1–4294967292均勻映射d6；每需求各取一顆，同格傳輸分段／重讀沿用。序列種子只在明示導入形成，候選預算投影複製狀態不消耗權威亂數。不是依角色名／操作ID取骰，不預抽未來格。

內部每點60,000,000單位（每時率先轉微點），按照實際覆蓋分鐘積分；五分鐘整數起訖的已定基線精確，舊精確事件時刻允許有界浮點分鐘。畫面及有限歷史呈現兩位小數，不把顯示取整回餵權威積分、需求感受門檻或自然醒。物件攝取仍使用明示完整份量後果，沒有額外骰。

既有進行中睡眠保存整套舊需求曲線、精確自然／刺激醒及醒後到當次提交的舊需求積分，該次正常提交才啟用新規則。新正式睡眠按已發生絕對五分鐘格末判斷≤20，off-grid首段只計真實分鐘。合法上界檢查只用最慢恢復界及格末位置，不取未來骰。自然變化先確立刺激醒、身體時間再確立已發生自然醒，最後精神時間讀取真實睡段；精神本身有效格與收支仍屬#256。

新世界可先在分析頁明示導入後再推進；未導入者維持既有v1工程路徑，不在GET偷偷升格。正在運行的舊API仍按15/30分鐘請求，但需求內部逐格計算。#276的新活動向後開始時，首段身體恢復為0，之後按真正經過分鐘結算；舊活動不倒改已提交歷史。持久版本、數值、種子及骰果損毀會拒絕推進，不靜默回退。
