# 手機行事曆與提醒工程基線（#192）

行事曆沿既有 `type=phone` 單次15分鐘操作、同一私人資料存取／原文／呈現handle責任及共同回合提交。`collection=calendar` 支援原有list/read/create/update/delete/share/display；每機32筆，文字沿每筆300字／1024 UTF-8 bytes與單一content最多500字的共同界線。list沿8筆分頁，正文及條件須真正read；寫入者知道自己成功保存的原文與設定，不因此新增閱讀回條。

記錄可另存 `schedule` 條件（同內在安排time/event/context）及 `arrangement:{id,version}`。連結只能指向當次真正展示、仍可回憶的本人版本；它是寫入時的關聯，不是另一份活動進度，也不在之後自動跟隨／重建內在安排。內在可以不寫手機；手機可以不設提醒。刪除紀錄、取消提醒及放下內在安排為分開的明示操作。

設定或延期：`operation=reminder,id,version,condition`；取消：同操作、`condition=null`。create/update可明示 `reminder=true` 並提供condition，以一個行事曆寫入保存紀錄與設定；未指定則不自動設提醒。單獨修改schedule不暗改既有提醒，須明示設定提醒。提醒設定另有版本、是否啟用、條件基線、共同cue游標及最後發聲key；它們保存在同一行事曆記錄。正文／分享改版保留有效條件與發聲key，故不因改字重響。明示設定／延期／取消替換有效設定版本，取消舊通知的待處理handle，不偽造已讀或已處理。

`phone-calendar.ts` 沿 `arrangement-cues.ts` 同一條件語義鍵、三態可知線索及轉換規則，沿 `phone-notifications.ts` 同一真實聲響／感知／睡眠／決策receipt責任；沒有第二套提醒引擎、注意力公式、手機AI或背景時間。時間取已成功推進中的世界分鐘，裝置離身或主人睡著仍可由裝置時鐘到期；感知機會另依手機實際物理位置。事件／情境只在清醒所有者實際可操作裝置時讀取同一有界正常輸入中的本人線索，不遠端訂閱其記憶或世界真相。不在場的所有者移動、隱藏人物或私人活動不使裝置取得線索。

在每個角色slot之前，沿當前回合副本檢查條件，已發聲key不重放。這保留先後slot資訊與每NPC唯一最終決策；最後一個slot設定的當下提醒留待下一個既有推進點，不追加模型。通知無正文／行事曆身份提示；真正read才建立內容及條件經歷。通知、察覺、正常決策機會、正文閱讀及安排完成分層可查。待處理通知容量沿前票128；不能由容量整理刪未讀正文或未處理通知。

`plannedCalls` 只在副本上檢查潛在提醒，遇可能新聲響時保守包含清醒自主角色；不產生聲響、感知試驗、擲骰或模型。實際budget／deadline仍由原本每派送守門；預估是上界機會，不保證角色一定察覺。

資料相容：PhoneState沿v1新增可缺省calendar，不更改SQL；舊世界GET與重載不建立紀錄、設定或閱讀史，第一次真正行事曆操作才保存該集合。原物件／歷史／內在記憶／活動保持，裝置遺失或損毀不補生。回退需保留完整JSON與能理解新狀態的執行器，不刪欄位／重置。共享88 KiB輸入、4個通知／cue展示與缺口、4項／8 KiB心理更新及400秒工作／430秒租約／445秒client政策不變。
