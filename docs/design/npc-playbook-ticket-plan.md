每項工作交付可驗證的完整行為，涵蓋必要的模型、世界狀態、API、儲存及最小介面；驗證沿用已確認的世界 API 入口。自動測試使用模擬模型，性格自然程度以實際決策紀錄檢視。

## 相依順序

- T1 無阻擋，可先開始。
- T2 依賴 T1。
- T3 依賴 T1；新增角色與單次控制不必等待 T2 的續做能力。
- T4 依賴 T3；T3 已包含 T1 的意圖保存與同次決策能力。交還控制時重新決策，不強制恢復接管前的活動，因此沒有額外 T2 阻擋。

T2 與 T3 在 T1 完成後都可開始；此處是工作相依關係，不代表自動啟動平行代理。每票包含自己的驗證，所有工作完成後再跑整體回歸，確認原規格全部驗收情境覆蓋。

## 已確認工作

### T1：接入共用 Playbook，保存每位 NPC 的意圖佇列

**交付：** NPC 在一次 GPT 決策中更新自己的意圖與排序、選擇行動；重新載入後仍保留。觀察者能從角色狀態看到其意圖。

**阻擋項目：** 無，可先開始

**驗收條件：**

- [ ] 所有 NPC 載入同一份已確認 Playbook，角色設定、意圖與已知情境各自獨立；共用內容維護單一來源。
- [ ] 同一次模型回覆提供可驗證的意圖佇列更新與一個具體行動，不增加獨立的意圖呼叫。
- [ ] 模型可新增、保留、重排或移除自己的意圖；等待中及未被選中的意圖可以保留，排序由 NPC 判斷。
- [ ] 意圖內容、強度、輕重緩急與供下次決策理解的簡短情境說明，隨角色世界狀態保存；沒有固定評分公式或硬期限。
- [ ] 單次行動完成不自動移除意圖；完成判斷使用已知結果。規則拒絕的行動把實際結果回饋給該角色，而非假定成功。
- [ ] 模型請求只包含自己的佇列、設定與知情資料；他人的私密意圖或設定不混入。
- [ ] 世界 API 能讀回意圖及順序，現有角色狀態面板以簡單唯讀方式呈現；不新增意圖編輯器或大幅改造介面。
- [ ] 缺少意圖欄位的舊世界相容載入；既有世界進度、記憶與習慣保留。
- [ ] 回覆契約錯誤或模型失敗時，原回合的意圖與活動一併回復，用量仍按既有規則記錄。
- [ ] 按已確認的世界 API 測試介面，用模擬模型驗證保存、重讀、排序、等待與移除、私密性、舊世界與失敗回復；不寫死真實模型的台詞或排序。

**規格覆蓋：** 規格驗收情境 1、2、3、7、10、11；包含意圖形成、強度、輕重緩急與性格的共用引導。

### T2：收到新消息後，由 NPC 選擇續做或切換活動

**交付：** NPC 可以檢視新消息、重新排序意圖，同時把手上的活動做完；也能選擇切換，且活動延續不重複呼叫 GPT。

**阻擋項目：** T1

**驗收條件：**

- [ ] 需要新行動時，同次決策取得自己的意圖佇列、既有活動與進度、最新已知消息與實際行動結果。
- [ ] 角色知情的新消息或活動結束觸發評估；私密想法或不屬於該角色的消息不觸發其評估。
- [ ] 模型可選擇繼續原活動並更新意圖排序，保留原進度與完成時間，活動不從頭計時。
- [ ] 模型也可依性格與輕重緩急選擇切換至另一個合法行動，保存更新後的意圖與活動。
- [ ] 未出現需要決策的情況時沿用現有活動與意圖，不另為意圖升降增加模型請求。
- [ ] 已理解但延後處理的消息可保留為意圖；同一已看過消息不在每個延續回合重複觸發決策。
- [ ] 延續既有活動不重複台詞、想法或記憶，不新增自主習慣證據；碰壁或未達預期結果供下次同次決策理解。
- [ ] 現有活動狀態顯示反映剩餘進度與續做／切換結果，動畫及自動推進保持回合不重疊。
- [ ] 沿用現有呼叫與 token 門檻、失敗計量和回合提交／回復；用量不足或模型失敗不留下部分角色更新。
- [ ] 透過世界 API 驗證新消息時續做／切換、進度保持、不重複決策與記憶、私密事件、呼叫數和錯誤回復。

**規格覆蓋：** 規格驗收情境 4、5、6、12，以及情境 7、10 的延續／新消息情況。

### T3：加入半控制咖啡店主與單次指定行動

**交付：** 觀察者能選取店主，指定其下一個行動；行動完成後恢復原控制方式，原有意圖仍保留。

**阻擋項目：** T1

**驗收條件：**

- [ ] 加入可選取的咖啡店主測試 NPC，角色設定獨立；三位既有測試角色保留原設定與自主方式。
- [ ] 既有世界能相容取得店主，不覆蓋原有角色、事件與進度；店主設定為測試用途，不改寫小說正史。
- [ ] 既有觀察介面提供店主的最小選取、狀態與單次指定入口，和一般介入明確區分。
- [ ] 可選世界允許的行動、對象與必要內容，API 按既有世界規則驗證；無效指定不產生不合法效果。
- [ ] 單次指定可覆蓋店主下一次行動，優先於其當下自主活動；意圖佇列保留。
- [ ] 指定行動完成後恢復原控制方式；自主狀態下，後續需要決策時仍以一次模型請求選擇。
- [ ] 直接執行指定行動不另呼叫模型選同一行動；結果只提供給依世界規則知情的角色。
- [ ] 其他 NPC 同回合照常生活，指定行動不被當作店主自主習慣證據。
- [ ] 單次指定、世界回合與意圖保持一致提交；重新載入不丟失待執行指定或意圖。
- [ ] 透過世界 API 驗證指定優先、行動規則、控制方式恢復、意圖保留、其他角色推進與呼叫數；以操作檢查驗證最小介面。

**規格覆蓋：** 規格驗收情境 8 的單次指定部分，以及控制功能的角色、儲存與介面相依需求。

### T4：暫時接管店主、待命與交還自主控制

**交付：** 觀察者能暫時接管店主；沒有指令時店主待命、其他 NPC 照常生活。交還後，店主帶著原意圖與期間經歷重新決策。

**阻擋項目：** T3

**驗收條件：**

- [ ] 店主介面提供暫時接管與交還控制權入口，狀態讓觀察者辨識目前由誰控制。
- [ ] 暫時接管持續至觀察者交還控制權，重新載入後控制狀態、意圖與待執行指定保留。
- [ ] 接管且沒有指定行動時店主待命，不自主挑選活動，也不發出店主自主模型請求；其他 NPC 照常生活。
- [ ] 接管時可以繼續單次指定下一個行動，行動完成後仍維持接管方式，不提前交還。
- [ ] 原有意圖保留；控制期間保存店主實際知情的經歷，不引入其他角色的私密資訊。
- [ ] 交還控制權使店主在下一次需要行動時取得原佇列、期間已知經歷及當前狀態，在同一次 GPT 請求重新評估意圖、排序與下一步。
- [ ] 交還不重置原世界與意圖，也不把使用者指定行動學成店主的自主習慣。
- [ ] 控制與回合使用既有提交、版本及用量機制；失敗不保存部分意圖或錯誤控制狀態。
- [ ] 透過世界 API 驗證接管、反覆指定、待命、其他角色推進、重新載入、交還後一次決策與知情範圍；操作檢查控制按鈕。

**規格覆蓋：** 規格驗收情境 8 的接管／待命部分、9，以及情境 7、10、11 在控制狀態下的回歸檢查。
