# 喜好的工程基線（#178）

以下為實作前選定、可調整的工程基線，不是使用者已確認的數值決策。

- `preferences` 為可缺省的角色資料；舊世界缺欄位表示尚無明示保存的喜好，不由人格、成敗、需求、習慣或歷史回填。首次正常決策明示更新才建立版本 1。
- 現行喜好最多 16 筆、16 KiB；每筆穩定 id、遞增版本、主題、適用情境、主觀喜惡描述、來源引用與理由。滿額須同次撤回再新增，不能偷偷淘汰現行喜好。描述為文字，不以信念確信程度或骰值換算喜歡程度。
- 每筆主題最多 128、情境 256、描述 512、理由 256 UTF-8 bytes；來源 1–8 筆，只接受當次輸入實際可見且版本相符的本人短期／長期經驗。單次鮮明經驗即可更新；來源淡去後保留 handle 並明示缺口，不還原原文。
- 每次正常決策可 upsert、keep、withdraw；與記憶選留、整理、認知共同最多 4 項、8 KiB，不新增模型派送。喜好投影計入原 88 KiB 輸入、208 KiB 角色記憶上限；超界只省略本次投影，不刪保存內容。
- 變更痕跡最多 24 筆、16 KiB，最舊先釋放並累計缺口；只保存身份、操作、版本、時間、短理由、來源，不保存撤回的完整喜好正文。此獨立有限紀錄沒有被其他認知引用的責任，不影響既有不可默刪的記憶／認知 trace。舊 id 在現行或保留痕跡中不能冒充新項目；新項目須新穩定 id。
- NPC 只收到本人現行喜好；觀察者痕跡、他人偏好不進上下文。系統不依喜好改動意圖與行動。正常整輪候選、SQLite 保存與操作 journal 負責原子性及重送。
- 回退前須匯出新欄位。舊程式若忽略新欄位，不能宣稱仍可維護喜好；讀取不進行付費重建或補造歷史。

驗證沿已確認世界 GET／POST、實際 JSON／SQLite 保存重讀、既有分析元件及真實應用瀏覽器；模型 transport 可使用明示 fixture，不以此宣稱真實 NPC 已自然形成偏好。
