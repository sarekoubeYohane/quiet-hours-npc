# 活動生命週期責任

來源：[主規格 #125](https://github.com/sarekoubeYohane/quiet-hours-npc/issues/125)、[工作票 #126](https://github.com/sarekoubeYohane/quiet-hours-npc/issues/126)。架構取捨見 [ADR 0002](../adr/0002-bounded-activity-outcomes.md)。

`activity-lifecycle.ts` 集中開始、繼續原計畫、階段推進、到期、取消及舊計畫清理。自主、直接指定與規則模式經 `activities.ts` 的同一入口開始；自主免決策續做、直接控制進度及 NPC 明示續做，經同一推進入口保留起點、完成時間與游標。接管／交還的 API 也使用同一取消入口。

生命週期操作的是本回合世界副本。`world-effects.ts` 仍負責效果權限、物件身份、整批驗證及階段前提；只有驗證完成的物件／供應變化才能與游標共同進入當回合候選。取消只清掉本計畫尚未具體化的 pending 供應，保留已消耗材料、已產生物件與他人變更。

`activities.ts` 保留 NPC 決策協調、知情新消息、模型呼叫與用量；世界 API 保留版本、租約、操作日誌與整回合保存。生命週期不派送模型、不自行選下一項活動，也不獨立寫入資料庫。

#126 是既有行為整理，沒有新增結果分支、模型生成日常程序或遷移舊資料。結果分支與日常規則擴充分別依 #127–#129 交付；本文件不將其規格當作已實作能力。既有時間、上限、開放式時段與續做契約見 [活動耗時契約](activity-time-contract.md)。

## 可恢復長活動（#176）

世界明示 `resumable:true` 的一般裁定／v3日常方法，才保存可暫停標記。NPC 正常決策的 `pause` 先結算實際已過時間及到期階段，將原計畫、階段游標、判定、投入分鐘、餘時及所有參照條件放入本人唯一暫停槽；它不再自動產生未完成工序成果。原來換事／控制取消仍保持取消語義，不一律變成暫停。

`resume`／`abandon` 的 target 使用本人暫停活動 id。復工必須在原區域、所有參照物件／供應／外在條件保持原身份與保存條件，才重設時間起點並延續原游標。中間停工時間不計入工時，原骰子與已提交工序不重播。失效給本人一般條件改變回饋；觀察者可對照既有世界資料。自然變化與他人活動持續，改變條件後可以放棄並提出新方法重新確認，不從過期候選直接生成成果。放棄只清理原未來候選，已提交成果仍保留。

容量為每角色一項，槽滿拒絕另一次暫停，不暗中淘汰進度。舊世界缺資料不補造暫停或可恢復性；現有世界 JSON 與整輪 SQLite 提交同時保存，沒有獨立持久化責任。本人投影只給自己的原方法、時點與進度，不給內部前提快照。既有分析頁顯示暫停與等待自主復工狀態。

## #177 實際睡眠

世界明示確認 `bodyActivity.kind=sleep` 並真正開始後，沿同一計畫持續；普通需求升級及技術區段不會重選。需求模組只計已發生睡眠時間，達工程自然醒界線或已察覺的足夠刺激時，由共同生命週期結算不晚於實際醒點的到期階段，再清理未來候選並保存醒來回饋。階段仍在當前提交點驗當前條件，不回填歷史；醒後下一正常決策自行選擇。

具體曲線、有限上界、明示投入上限及感知界線見[工程基線](life-sleep-baseline.md)；API／SQLite／Chromium fixture證據見[#177驗證](../verification/life-sleep-177.md)。沒有新增逐tick模型、伺服器期限或費用政策；不表示真實NPC／正式站已驗收。
