# 柔性安排工程基線（#187／#185）

2026-10-27：本文件記錄 #187 已接入的內在安排。時間／事件／情境喚起由 #191 接續，手機紀錄與提醒由 #188–#192 接續；本文件不宣稱那些接點已交付。

安排為角色本人、具穩定 id 與遞增版本的可修訂期待。`arrangementUpdates` 接入既有同次最終決策，與原五類心理工作共享合計四項／8 KiB，沿原 intents 自主排序及共同活動執行；新安排不自動新增／置頂意圖。upsert 可改時間／條件，keep 不換版本，complete／drop 明示改狀態。跨過時間不刪安排，也不生成已錯過的角色知識。

Character.arrangements 的 schemaVersion=1；最多16筆、24 KiB（含完成／放下身份）。採此界線以避免永久完整待辦與有限模型輸入背離。滿額明示拒絕整輪候選，不淘汰有效安排；NPC 可明示 archive 已完成／放下項目釋放索引。歸檔不刪記憶；保留最近24個 id/version tombstone，拒絕近期舊身份重用；更早歸檔身份無永久查證保證，新安排須使用新 id。容量的選擇是工程初值，不是性格／重要性公式。

每次建立／變更安排寫入一則自己的短期經歷；安排索引只在本次實際展示的短期或長期記憶保有同一完整經歷時才提供內容及版本。選留沿既有長期記憶，回想沿既有一次 Vector Recall；濃縮、改寫或遺忘後，索引不能復活被刪的原文。單純未展示不刪安排。投影仍受原88 KiB心理輸入預算；在輸入中被省略的安排不能被本次候選修改，即使索引／記憶身份仍在服務端。

條件是 time（世界絕對分鐘）、event（可知 clueKind/source/region）或 context（已知 region）。#187 只保存條件，不比對世界真相、不新增模型或背景時鐘。#191 必須沿已知主觀線索及上述可回憶投影觸發，不以索引內容建立全知提醒。

所有變更只寫回合副本，再沿原 journal／CAS 提交；新安排經歷、意圖、認知與活動共同回復及重放。狀態缺欄位保持可讀，GET 不建立安排史。沒有 SQL migration。舊執行器不理解安排引用與遺忘語義，回退須保留完整 JSON 並使用能理解狀態的執行器，不刪欄位或重置。

既有分析入口展示觀察者安排索引、客觀到期及目前可回憶差異。角色實際輸入另受當次預算／回想限制；開啟畫面不產生 NPC 知識。私有 trace actor snapshot 保存安排，始終不進記憶。

## 最終審查補充：順序、語義身份與共同投影

事件條件沿本人當次真正展示的觀察及短期經歷 handle，綁回同一主觀觀察的穩定 ID，依已發生順序承接尚未處理的匹配／非匹配轉換。每個 cue 增存最後一個 ID／世界分鐘及內部單調觀察序號高水位，仍受原 1 KiB cue／40 KiB 整體上界；原 ID 重送與純重讀不重放舊轉換。未展示、未察覺、無關或隱藏變化不參與。即使離開與返回都落在本人兩次 slot 之間，實質的已知條件變化仍能提供一次新機會，不追加同輪決策。舊 cue 缺可靠序號時，在可寫回合候選產生新感知前以已提交觀察序列建立基線，不猜測重放舊往返史。序號隨既有短期感知建立，角色僅保留一個安全整數高水位；forget／FIFO 可移除正文與來源但不倒退高水位，同分鐘稍後的新觀察仍可處理。序號不進 NPC 投影、長期選留正文或 Embedding；不是觀察者實錄復活內容的入口。

條件是否相同依共同 `conditionKey` 的語義身份判斷，不依 JSON 欄位排列；合法 complete／drop 不因物件鍵順序改變而失敗，真正改動仍須 upsert。正常與回想後的記憶選取責任保持分開，後續手機 handle、安排 cue、中性 notice、gap 與 byte 預留則共用同一派生投影收尾，避免兩條輸入管線分歧。

## #191：可知條件與一次處理機會

`npc-input.ts` 集中原本 NPC 輸入建構，供實際派送及活動續做預檢共用。提醒是否可見使用相同的記憶、安排及預算投影；不以未展示索引打斷活動。新 cue 不另開規劃、反思或提醒模型。真正睡眠與接管待命維持原活動契約。

共享 `arrangement-cues.ts` 負責條件辨識及去重，供 #192 裝置提醒沿用：time 只看成功推進中的世界時間；context 只看本人當前已知所在區域；event 只看本人真正收到的觀察，依 kind／已辨認 source／region 比對。不存在相關可知線索是「未知」，不被當成條件消失；匿名聲響不升格具名人物。相同文字的另一事件 id、改措辭、無關 revision 或隱藏變化不構成新條件。已知相關人物／區域變化，或本人離開再回到情境，可提供新機會。

安排另有有界 cue 游標，分別保存條件語義鍵、已知成立狀態、條件輪次、喚起時間及實際派送後的處理時間。世界到期、喚起、正常決策承接與安排完成分開；只有真正展示的 cue 才隨同輪提交標處理，無須 NPC 回傳機械 receipt。上輪處理 continue 不重設活動起點／進度；原 ID 重送不重派或重消耗。明示延期更換有效條件並建立新游標；只改安排文字保留條件基線及游標，不可刷新提醒。游標不進角色安排索引，只有可知的一次機會 handle 展示在 self.arrangementCues。

同次最多展示4個 cue，共用一次正常決策；self.arrangementCueGap 明示尚未展示數量，未展示項目不標已處理。這是工程輸入界線，不是重要性排序；保留記錄順序，意圖仍由角色自排。有效安排 core 保持24 KiB；每個 cue 保留至多1 KiB，合計狀態40 KiB，並繼續計入原208 KiB角色記憶總量。此預留避免合法安排接近容量後，僅到期增加必要游標便阻塞後續正常決策。

手機記錄引用與安排提示沿共同88 KiB輸入包絡：先依實際展示記憶重建手機handles，再將可選引用／cue納入有界輸入，明示 phoneReferenceGap／arrangementCueGap；裝置身份及列表操作仍可用。省略引用不能修改或標已讀，即使服務端保有來源。回想完成後重建同一投影及範圍，不新增回想輪數。初次未展示、回想才取得的 cue 由最終實際派送receipt隨故事提交，不能提前消耗。
