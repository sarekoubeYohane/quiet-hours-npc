# NPC 行動模式

狀態：grill-with-docs 核心行為已由使用者於 2026-10-07 確認；實作規格與測試介面已於 2026-10-08 確認並發布。四項工作已於整合 PR #6 實作，尚未合併或部署；以下區分設計原則與 PR 分支的實作及驗證狀態。

## 已確認設計

### 以 Playbook 提供 GPT NPC 判斷原則

使用者明確說明：原本想寫一份給 GPT NPC 看的 playbook；意圖強度的變化可以是其中一條生活判斷原則。後續設計以這個用途為中心，先整理可供模型理解的原則。狀態保存、行動驗證及呼叫觸發的技術安排另行釐清。

所有 NPC 共用同一本生活判斷 Playbook；角色設定各自獨立，每位 NPC 搭配自己的角色設定。共同原則由不同的性格、在乎的事情與個人傾向產生不同選擇。

已確認原則見 [npc-playbook.md](./npc-playbook.md)，模型請求已載入相同來源。

### 意圖與行動分成兩層

先有模糊的意圖，再依當下情境選擇具體行動。後續行動可隨現場情況調整，不要求一次排定完整步驟。

例如 Vera 的意圖是「想換個環境，做點自己的事」，可以先前往咖啡館，再依現場情況選擇畫髮飾或和人聊聊。

生活習慣是可改變的傾向，可成為新意圖的來源；角色依當下性格與情境判斷，仍可做出不同選擇。

### 意圖強度影響時間

使用者已確認：隨意圖的強度來決定時間。

意圖強度影響 NPC 多長時間仍把這件事放在心上：弱意圖較容易淡去，強意圖會維持較久。急迫性影響多快開始處理；單次活動的持續時間依具體活動決定。

意圖可以跨越多個行動，也可以在做其他事情時繼續存在。例如 Vera 強烈想確認 Cass 平安，可以先傳訊息、接著整理房間，期間仍惦記這件事。

意圖強度會隨性格、經過的時間與新資訊升降，維持時間也隨生活變化。例如持續收不到回覆可能加強牽掛，收到安心的回覆則可能減弱；較弱的外出念頭可能隨忙碌淡去。

重新考慮時機見「需要新行動時，一次檢視意圖與行動」；意圖狀態隨角色世界保存，強度、重要程度與急迫性各以 low／medium／high 表達；沒有固定加權排序或硬期限。

### 輕重緩急與性格

使用者已確認：先考慮事情的輕重緩急，再讓 NPC 按自己的性格處理。

每位 NPC 根據自己的性格與所知情境，判斷哪件事比較重要、比較急，再選擇具體處理方式。性格同時影響優先順序與處理方式；不同角色面對相似情境可以做出不同判斷。NPC 的判斷限於自己知道的資訊。

例如很累且尚未收到 Cass 的回覆時，Vera 可能覺得確認 Cass 的狀況更急，先傳訊息；Kris 若沒有得知新的危險跡象，可能覺得先休息、明天再問更重要。此例說明性格差異，不是固定行動腳本。

多個意圖以 NPC 可排序的意圖佇列保留，見下節。

### NPC 可排序的意圖佇列

使用者已確認：保留一個意圖佇列，其中的意圖按優先順序處理；NPC 可以控制排序。

每位 NPC 保留自己的意圖佇列。佇列中的項目是想滿足或追求的方向，每次再依選中的意圖與當下情境選擇一個具體行動。其餘意圖可以保留。

NPC 依自己的性格、所知情境與輕重緩急安排優先順序，也能在新情況下調整排序。共用的是 Playbook，角色的意圖佇列與排序各自獨立。

最高優先的意圖暫時無法推進時，NPC 可以保留該意圖，先處理佇列中其他可推進的意圖；收到相關新資訊後再重新判斷排序。例如 Vera 等待 Cass 回覆時，可以先畫髮飾或休息，收到訊息後再重新排序。

意圖是否移出佇列由 NPC 自己判斷：覺得已滿足、決定放下，或已不再在意時，可以移出；仍在等待條件的意圖保留。單次行動完成不等於意圖已滿足，例如傳出訊息後，是否已確認對方平安仍取決於角色對回覆的理解。

佇列重排與等待中意圖的再次評估，在需要新行動的同次決策中進行，見後節。

### 新意圖由生活情境產生

使用者已確認：新意圖由 NPC 根據生活情境自行產生，來源包括身體需求、眼前事件、關係、個人目標與生活習慣；再依自身性格判斷是否加入自己的意圖佇列。

例如累了想休息、看到布料想做髮飾，或想起某人而想聯絡。沒有新念頭時可以繼續原有活動，不必每回合產生新意圖。

這是 Playbook 的判斷原則；模型取得自己的性格、目標、關係、記憶、已知對話及當下相關習慣；本輪未新增生理數值模擬。

### 是否中斷當前活動由 NPC 判斷

使用者已確認：新事情出現時，NPC 自己判斷立即切換，或先做完手上的事；重排意圖時也考慮眼前活動的進度。

角色依自己的輕重緩急、性格與活動進度做出選擇。例如泡茶時收到普通訊息，可以泡好再回；收到角色認為急迫的求助，可能先停下。性格也影響容易分心的程度與願意等待的時間。重排意圖不必立即切換正在做的活動。

### 未達預期後的反應也受性格影響

使用者已確認：行動沒達到預期時，由 NPC 依自己的性格、所知情境與理解的原因，判斷重試、換方法、等待或放下。

一次碰壁不必移除原意圖；是否繼續保留或調整強度，由角色自己判斷。例如找人聊天卻發現對方不方便，可以稍後再問或先做別的事。不同性格可以對相似結果做出不同反應。

### 直接控制期間保留意圖佇列

使用者已確認：直接控制店主時，保留其原有意圖佇列。

單次指定先執行使用者選定的行動；暫時接管期間由使用者控制，沒有指定行動時店主待命，其他 NPC 照常生活。控制期間經歷並知情的事情仍可能影響意圖；交還控制權後，由店主重新評估排序與下一步。

意圖保留不會覆蓋使用者已指定的行動。交還後首次自主請求會取得控制期間保留的最近 80 則已知經歷，連同原意圖與目前狀態判斷；成功提交後清除該經歷緩衝，失敗保留。

### 需要新行動時，一次檢視意圖與行動

使用者已確認：每次需要決定新行動時，順便檢視意圖佇列。在同一次 GPT 請求中考慮意圖、排序與下一步，不另設獨立的意圖判斷呼叫。

活動結束、收到自己知情的新消息，或交還控制權時，觸發決策；活動延續期間沿用既有決定。收到新消息時重新評估不代表必須中斷，NPC 仍可選擇繼續當前活動。

意圖強度隨經過的時間與新資訊變化，在上述決策時一起評估。模型同次回傳完整意圖佇列（最多 12 個）及新行動或 continue；程式驗證欄位與行動，繼續時保留進度，沿用現有呼叫與 token 限制。

## 目前實作與驗證

[整合 PR #6](https://github.com/sarekoubeYohane/quiet-hours-npc/pull/6) 已接入共用 Playbook、每角色意圖保存、同次意圖與行動決策、新消息後續做或切換，以及咖啡店主的單次指定、接管、待命與交還。活動延續不增加模型請求、不重複記憶或自主習慣證據。舊世界相容加入空意圖及店主，既有進度保留。

每位角色保存最近 80 則記憶，一般決策提供最近 12 則；交還控制後首次自主決策另提供控制期間最近 80 則已知經歷（不含純延續紀錄）。緩衝只收集店主知情的實際結果及事件，不收集他人的私密資訊或未執行指令；成功提交後清除，失敗保留。超過上限的早期經歷可能被裁去，沒有長期摘要。

世界回合維持一致提交／回復。最終保存確認零列衝突時，只把本次付費用量差額加到最新帳號世界，保留較新角色狀態、租約與節省決策數並增加版本；較新的小時計量窗口不被舊請求取代。提交結果不明的資料庫拋錯不盲目重播，以免重計；全面中斷或程序終止仍無冪等用量帳本保證。

驗證以已確認的世界 API 測試介面及模擬模型進行，儲存 fixture 使用記憶體 SQLite 執行實際 SQL。規格與驗收來源為 [Issue #1](https://github.com/sarekoubeYohane/quiet-hours-npc/issues/1)，工作票拆分見 [ticket plan](./npc-playbook-ticket-plan.md)。

尚未合併或部署。店主控制按鈕的瀏覽器操作檢查待完成，因本環境 CUA 的檔案 URL 被政策阻擋，未採取繞過方式。未發出付費模型請求，模擬回覆不能證明真實角色的性格或敘事自然程度。
