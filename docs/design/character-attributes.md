# 穩定人物建角工程契約（#275）

產品依據：[已批准 A 方案](character-dice-energy-recommendation-2026-11-09.md)、ADR 0012。四屬性為力量／耐力／靈巧／感知能力，1–5 整數、一般為3；本切片形成與顯示資料，沒有開始 #277 的 d100 接入。

## 設定與數值權威

`CityDraft.characters[].characterSetup` 在既有城市編輯器中呈現，與自由文字背景及能力並列供擁有者核對。`attributes` 的四鍵可分別設定 `value`、`min`、`max`；全部可省略。設定不能超出1–5、空區間或與指定值矛盾；不夾值、不用重抽修正。自由文字及角色名不轉換為隱藏權威數字，背景需要的數值約束由此草稿明示確認。

`expertise` 是最多16個 `{scope,modifier}`，`senses` 最多3個 `{scope:'sight'|'hearing'|'touch',modifier}`；修正限 −20／−10／0／10／20。同一正規化範圍不能重複。不填表示沒有確認數值，不移除原來感官硬限制。草稿只保存候選，成功開始或導入才成為 `authority:'owner-confirmed'` 資料；既有能力標籤保持原文。

無指定、無範圍限制者取兩顆獨立公平 d3 相加減1；受限範圍直接在原分布1:2:3:2:1內條件抽樣，不反覆重骰、不改成等機率等級。精確值不取骰。基本屬性不套用精神容量公式。

## 原子形成、相容及顯示

城市預覽只驗證，不取骰；`start-city` 在原租約取得後，於世界候選內形成各人物資料。存成 `Character.attributes`，包含 version1、形成時間、各值、已確認限制及分開的專長／感官設定，與世界共同保存。未提交、CAS失敗或時間限制不留下部分人物。

缺值舊人物從現有人物檔案明示「設定並導入基本屬性」；使用原世界API `adopt-character-attributes`，參數 `target`、`characterSetup`、`expectedVersion`、`worldContext`、`operationScope` 及原 operation ID。只對缺值人物生效；已形成不能用新操作重抽。舊世界未導入者維持原行為，GET、重載、跨日、睡醒不補資料或歷史。操作收據沿用原日誌，先讀回已提交結果，再驗證新設定；同ID重送及提交後遺失回覆不重新取骰。

此操作不啟用精神電量、不修改其既存政策／容量／餘額，不建立第二份容量；控制權身分不受角色名、職業或人物數值影響。API及觀察者人物檔案可查看穩定值、背景範圍、專長及感官數字；當前需求、喜好、行動命令分開。尚未接入的行動／感知不宣稱受到新值影響。後續 #277 應依既存機會優先承接舊結果，不能把新增人物欄位當作重骰理由。

## 驗證接點

沿既有世界API、真正序列化／SQLite及WorldApp，受控亂數與模型transport；外部行為測試包含完整九組普通結果、受限範圍邊界、無效設定、舊人物明示導入、新城市開始、原ID回放、保存前後故障／CAS、檔案SQLite關閉重開，以及既有人物畫面操作／重載。Chromium旅程沿既有隔離 browser fixture，沒有新增正式或測試專用產品UI。逐票結果見 [#275驗證](../verification/character-attributes-275.md)。
