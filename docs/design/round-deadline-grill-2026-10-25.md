# 完整回合時間政策：Grill 決策紀錄（2026-10-25）

承接 [#166](https://github.com/sarekoubeYohane/quiet-hours-npc/issues/166) 與[診斷報告](../verification/round-deadline-diagnosis-2026-10-25.md)。本文件記錄已確認設計；正式規格已依 to-spec 更新至 #166 並標記 ready-for-agent。這不是已交付修正，本輪只發布規格與文件，未修改產品、部署、呼叫付費模型或推進正式世界。

## Q1 已確認：A，接受較長但有限的完整回合等待

使用者於本次 grill 選擇 A：以完整呼叫鏈及保存成本推導有界回合時間預算，同步調整工作期限、固定租約及前端等待；接受同一世界的其他操作可能等待較久。目的是讓合法四角色回合在明定的模型與儲存延遲範圍內能完成，不能只將相同失敗延後。

本決定修訂 ADR 0004 中「保留原工作期限／租約」的設計限制；現行程式仍是 120 秒租約、提前 10 秒停止工作、單次最多 25 秒及前端 125 秒等待。A 沒有選定新的秒數，也沒有批准續租、heartbeat 或背景續接。

## 沿用的契約

- 角色逐 slot 決策，後一角色承接前面候選變化；不並行收集 NPC 決策。
- 整輪故事、記憶、意圖與回饋一起提交；提交前技術失敗維持整輪回復，提交結果不明仍依原 journal 查證。
- 已知用量保留，未知用量不填零；同一 operationId 精確回放，不重新派送或重套效果。
- 不新增付費重試、不切換模型、不部分提交。等待上限增加不等於派送次數或費用上限增加。
- 沿既有固定租約與 CAS 所有權保護；較長等待仍須處理失聯、過期 pending、晚到回覆與不明結果。
- 私有實錄與故事提交維持不同責任，必要持久保存點不可擅改成 fire-and-forget。

## 補充查證：完整容量與等待界線

- [既有派送契約](free-action-effects.md#派送與費用)是每 slot 最多兩次 NPC 聊天（含一次回想續答）及一次裁定，整輪最多 3N 次聊天；無回想最多 2N 次。[決策流程](../../lib/models.ts)以 recalled 限制一次回想。觀察用驗收場景停用回想，所以本次八次派送不是所有合法四角色回合的上限。
- 初始及驗收世界有四角色，但角色集合與[活動迴圈](../../lib/activities.ts)沒有全域四人上限。規格須明示支援 N 與完成能力範圍，至少涵蓋目前四角色；不暗加角色數產品限制，也不宣稱任意 N 都能在同一固定時間完成。
- [共用 transport](../../lib/model-adapter.ts)只有 fetch、headers 保存、body 及 response 保存的工作受 withDeadline race；prepared、dispatch、failure、usage、candidate 保存仍直接 await。signal 過期不能硬中斷所有保存；usage callback 也在 usage 保存之後。
- [回想服務](../../lib/recall.ts)的 10 秒限制裁剪服務派送，但 manifest、資料庫寫入及權威重讀仍有直接 await。不能把 25 秒或 10 秒當作整個函式必然返回的保證。
- [世界 API](../../app/api/world/route.ts)以 journal 已存的絕對 pending 到期時間判斷等待／uncertain；新政策不能改寫舊操作的到期語義或重派舊 ID。[已開啟的舊前端](../../components/world-app.tsx)仍有 125 秒 POST timeout，單改新後端不能延長舊 bundle；發布相容措施及原 ID 查詢／回放須納入工程驗收。

推導起點為聊天次數 C ≤ 2N + R、0 ≤ R ≤ N，R 為允許的回想續答數。工作預算涵蓋 C 次模型處理、R 次回想及其餘 setup／guard／保存／驗證／活動成本；固定租約再包含提交／回復與故障收尾餘量，前端等待另外容納受理前及 HTTP 交付。已涵蓋的保存不可重複計算，未受 race 限制的等待不可遺漏。這是預算結構，尚未選定數值，也不是對無限慢儲存的硬返回保證。

## 需由工程定稿的內容

這些是事實與驗收工作，不要求使用者猜測時間常數：

1. 明示支援的角色與完整呼叫鏈範圍，包括既有回想搜尋／續答；不能只以本次隔離場景的八次派送代表所有合法回合。
2. 分開列出單次時間限制、其已涵蓋的保存成本，以及尚未涵蓋的 setup、guard、驗證和收尾，避免重複計算或遺漏。
3. 以明示有限的延遲範圍推導工作期限、固定租約與前端等待的關係；對超出範圍的慢模型、慢保存或失聯仍須有界停止。任意慢儲存不在完成保證內。
4. 驗收舊 client／pending 與原 ID 恢復的相容性；不能只改後端常數而讓前端先中斷。
5. 沿既有世界 API → transport 替身 → 真實序列化／測試 SQLite → 原 ID 查詢及重送驗收。現在的 8×14 秒 RED、含保存延遲及回想情境須在選定範圍內真正提交；超界、競爭及不明結果則保持原保護。

## 流程狀態

2026-10-25，使用者在整體設計摘要後要求「to spec」，確認收束並進入規格發布。#166 已依 to-spec 整理問題、方案、18 則使用者故事、實作決策與9組驗收條件，標記 ready-for-agent；維持一個可驗收的垂直切片，沒有新增重複 Issue 或子票。最高層世界 API → transport 替身 → 真實序列化／測試 SQLite → 原 ID 查詢及重送沿使用者既有指定；具體秒數、延遲測試及舊 client 相容機制由工程在規格界線內定稿，不再要求使用者猜測實作細節。

此設計對原期限政策的修訂記入 [ADR 0004](../adr/0004-operation-evidence-stays-outside-story.md#166完整回合採有界時間預算)。沒有新增領域用語，GLOSSARY 不放入工程計時常數。設計已確認與實作通過分開：目前 RED 尚未因產品修正轉綠。

#85 的泡茶 loop 仍需技術修正後另行授權的有限正式行為觀察；本次設計決定、本地替身及期限診斷都不代表行為通過。
