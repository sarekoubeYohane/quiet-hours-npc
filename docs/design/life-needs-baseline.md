# 自主生活需求工程基線 v1

這些是 #173/#174 的工程基線，不是使用者已確認的生理參數。驗收介面沿 #172：世界 API、真正序列化／SQLite 保存重讀、既有角色畫面。transport 與骰子可替身；不呼叫正式模型。

| 項目 | 工程值／理由 |
| --- | --- |
| 權威刻度 | 各需求 0–100，越高越需要處理；分開保存，兩位小數。有限且易查驗，不作醫學宣稱。 |
| 啟用 | 缺欄位世界在第一次成功 advance 的原世界分鐘啟用，初值飢餓20、口渴20、疲勞15、睡眠20。這是明示起點，不表示過去已吃飽或已睡足；GET 不初始化或回填。新世界沿相同起點。 |
| 清醒時間基線 | 每世界小時飢餓+3、口渴+6、體力疲勞+1、睡眠需求+4。15分鐘可查驗、數小時可跨區間；只算已提交世界時間。 |
| 感受區間 | <40 無明顯訊號，40–<65 輕微，65–<85 明顯，85–100 強烈；基線初值至少經數小時才升級，避免初次啟用把既有短活動頻繁打斷。只投影文字，不投影數值、係數或他人需求。 |
| 重新評估 | 清醒原活動遇到任一需求進入高於已評估區間時，在下一個正常 slot 合併為一次決策；本人可續做。正常決策成功候選把四項當前區間記為已評估。降低區間同時降低已評估記號，之後再升級可重觸發。沒有逐 tick 記憶、懲罰或新增模型。 |
| 有限追溯 | 最多32次時間／效果變化，省略筆數明示；不宣稱永久身體史。 |
| 相容與回退 | JSON optional needs，舊資料、舊活動及舊規則保留；回退版本讀寫可能不認識新欄位，需保留完整世界備份後回退，不能把丟欄位當遷移。 |

活動後果與睡眠在後續票明列確認規則；舊規則缺少新需求效果時保持未確認，不能由讀取推測恢復。
