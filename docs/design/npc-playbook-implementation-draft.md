# NPC 共用 Playbook 與意圖佇列：實作規格草稿

狀態：整體行為已由使用者於 2026-10-07 確認；測試介面待確認。確認後發布至本專案 GitHub Issues，正式規格以該 Issue 為準。尚未實作或部署。

## 問題

目前角色每次產生單一行動，沒有保存多個意圖與角色自行安排的優先順序。行動之間難以保留「仍在惦記什麼」的連續性，且新消息會使現有活動需要重新決策。使用者希望 GPT NPC 有可讀的生活判斷 Playbook，依自己的性格與所知情境生活。

## 解決方式

所有 NPC 共用一份生活判斷 Playbook，角色設定各自獨立。每位 NPC 保存自己的意圖佇列，模型在需要新行動時，同次檢視意圖、排序與下一步。程式保存狀態、提供角色知情資訊、驗證可執行行動及維持用量限制。

意圖強度影響惦記多久，急迫性影響處理時機，單次活動時長另依具體活動決定。排序、意圖形成、移除與碰壁後的反應由 GPT 按角色性格判斷。

## 實作決策

### Playbook 與角色輸入

- 共用 Playbook 作為系統判斷原則載入，維護單一內容來源；角色設定、意圖與已知情境分別提供。
- 每次模型決策僅取得該角色的意圖、角色設定、記憶、已知對話與當前活動進度；其他角色的私密意圖與設定不混入。
- 沿用現有已知地點、聯絡人、現場角色、目標、關係、情緒與習慣資訊。生活需求先以角色已有設定與已知生活情境供模型判斷；本輪不新增生理數值模擬。

### 意圖佇列與回傳契約

- 意圖佇列保存於每位角色的世界狀態，保存意圖內容、模型判斷的強度與輕重緩急、排序，以及供下一次決策理解的簡短情境說明。
- 佇列順序由模型選定；程式不另以固定加權公式替角色重排，也不按強度自動設定硬期限。
- 同一次模型回覆包含可驗證的意圖更新，以及新行動或繼續既有活動的選擇。單次決策仍只執行一個具體行動。
- 意圖完成判斷以角色已知的結果為依據；尚未執行或被規則拒絕的行動不能當成已成功。
- 依現有序列化世界狀態保存，舊世界缺少意圖欄位時以空佇列相容載入。既有記憶、習慣與進度保留。
- 具體欄位名稱、強度表達及資料大小限制由實作按最小所需設計，保持模型可讀與回傳可驗證。

### 決策、延續與結果

- 活動結束、角色知情的新消息或自主控制恢復時，需要檢視意圖與下一步；每位需要決策的角色只用一次模型呼叫完成兩層判斷。
- 活動延續時沿用既有決定，不為更新意圖另行呼叫模型。
- 重新決策時保留可供模型判斷的既有活動與進度。模型選擇繼續時保留原活動進度與完成時間，避免將同一活動從頭開始或重複產生既有台詞、記憶及習慣證據。
- 角色已理解但延後處理的事情可反映在意圖佇列；相同消息不應在每個延續回合重複觸發決策。
- 行動驗證與結果回饋沿用現有世界規則，讓角色下一次決策能理解自己知情的實際結果。
- API 或儲存失敗時，意圖更新與行動使用同一回合提交／回復機制；已發生的模型嘗試及供應商回報用量仍保存。

### 店主直接控制整合

- 單次指定優先執行指定行動，意圖佇列仍保留；行動完成後恢復原控制方式。
- 暫時接管期間沒有指令則店主待命，其他 NPC 照常生活。待命不觸發店主自主選擇行動的模型請求。
- 控制期間保存店主已知的經歷，交還後在一次自主決策中更新意圖與排序。
- 目前三位測試角色的程式尚無店主與直接控制機制。這部分是本完整規格的相依功能；拆票時需明確建立相依工作，不以 Playbook 文案替代完成。

### 相容性與用量

- 保留現有規則模式、OpenAI／OpenRouter 行動模式、行動規則與世界知情範圍。
- 沿用每小時呼叫、token 上限與失敗計量方式。新增少量意圖上下文會增加輸入 token，但不增加獨立意圖呼叫。
- 規則模式沿用試玩用途，不用規則腳本假裝驗證 GPT 的性格判斷。

## 測試決策（待確認）

### 主要測試介面

以既有「世界讀取／推進／介入 API」作為主要測試介面。使用模擬模型回覆與測試儲存服務，從請求、回覆及重新讀取的世界狀態檢查結果；同時檢查實際送出的角色模型請求與呼叫次數。不對私有輔助函式逐一寫測試。

- 能驗證：角色意圖新增、保留、重排、移除及重新載入；自己的佇列與知情內容；活動延續、繼續／切換與進度；直接控制與待命；同次決策呼叫數；錯誤回復及舊世界相容。
- 不能單靠此介面保證：真實 GPT 一定以特定性格排序或說話、生活習慣與意圖是否有自然的敘事表現。此類結果以不同角色的實際決策紀錄人工檢視，不寫死特定台詞或思想。
- 既有前例：專案測試已透過世界 API、模擬供應商與儲存服務，檢查回合持久保存、失敗回復、用量與模型輸入；新增驗證沿用該路徑。
- 尚未寫新測試或執行付費模型請求。使用者確認此測試介面後，再發布正式規格；實作時按一個行為、一個失敗測試、一個最小實作的方式前進。

### 驗收情境

1. 模型在一次回覆中更新角色的意圖佇列並選擇行動；保存後讀回得到相同佇列與順序。
2. 最高優先意圖等待回覆時，保留該意圖並選擇其他意圖的一步，不會因未被選取而丟失。
3. 一個具體行動完成後，原意圖可以繼續保留；後續已知結果使模型判斷滿足時才移出。
4. 新消息使角色重新決策，模型可只改排序並延續原活動；完成時間與已完成進度保持一致。
5. 新消息使模型選擇切換活動，世界保存更新後的行動與佇列。
6. 持續活動跨多個回合時，不增加模型呼叫、不重複台詞記憶，也不額外累積習慣證據。
7. 私訊、私密想法與意圖佇列只供正確角色知情，不讓其他角色收到不屬於自己的內容。
8. 店主單次指定與暫時接管保留意圖；接管待命不自主行動，其他角色仍能推進。
9. 交還控制後，店主取得控制期間的已知結果，在一次自主請求中重新評估佇列。
10. 模型失敗、回覆契約無效或儲存衝突時，不保存部分角色的新意圖或活動，既有用量規則保持。
11. 舊世界沒有意圖欄位也能載入及推進，既有進度保持。
12. 相同已看過的消息不導致每個延續回合重複重新決策。

## 範圍外

- 固定性格評分公式、按強度硬倒數的意圖過期機制。
- 新的地點、行動種類、完整生理數值模擬或小說正史改寫。
- 關閉觀察室後的離線自主運行、長期記憶摘要與新社交網路系統。
- 新增意圖編輯器或大幅改造觀察室介面。
- 尚未指示的部署、付費模型大量試跑。
