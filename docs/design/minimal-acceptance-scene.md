# 最小日常驗收場景

使用者於 2026-10-16 批准補上真實模型可操作的最小場景，接續 PR #101 與當晚正式站短測；不重設原世界。

## 操作契約

- 設定頁提供「進入最小驗收場景」。暫停自動並等待目前操作／播放完成才可進入。沿同一世界 API、租約、版本及 operationId 原子保存一份有界原世界快照。
- 驗收使用現有四角色的性格與三地點；重新建立明示的測試經歷，不攜入原世界記憶。原世界暫停；可以重載繼續驗收，或確認結束並返回原世界。結束會捨棄本次驗收故事，不清除已發生用量。
- 模型 Key、裁定配置、玩家預算與價格沿用；每次真實呼叫仍由玩家付費並計入同一帳號用量。進入／返回不呼叫模型，不重設小時窗口或累計；各故事的活動續做統計分開。
- 每次切換使用新的世界情境識別，拒絕其他分頁先前建立但尚未送達的世界操作。已結案操作仍沿原回覆重播，不重做。驗收期間禁止一般「重置世界」，避免遺失原世界。
- 暫存快照僅存於同一帳號世界列，不出現在 API 回覆、模型輸入或操作歷史副本。一次只保存一份，原世界超過 512 KiB 時拒絕進入並保留原資料。
- 本輪場景只用角色本地記憶；驗收期間不啟用向量回想或修改原世界索引。返回後沿原有服務設定恢復。

## 明示條件

四人從咖啡館前台開始；僅在此驗收分支新增以下物件，不新增正式菜單或住宅設定。

- 一份餐點：有限供應 1 份，明示供 Cass 使用；取得後追蹤同一物件，吃掉後不補貨。
- 一只杯子：店主所有、放在前台、大家知道它存在；初始只有店主可用。借用需店主自主授權，持有不改所有權。
- 共用茶具、熱水與茶包：場景明示可供四人使用；杯子支持空杯、已加水、茶已泡好及乾淨／待洗的有限狀態。合法提案可分階段生效。
- Cass 有想吃點東西的初始需求，Vera 有想泡茶的初始需求；兩者仍可拒絕、延後、換方法或休息。不指定台詞、不強制固定回合完成、不注入反循環提醒。

## 可觀察驗收

世界 API 讀回與觀察／分析頁顯示供應剩餘、物件身份、持有人、所有者、生命週期、狀態與活動階段。顯示的都是目前已保存狀態，不把台詞或未來階段當結果。

1. 取得並食用餐點，重載不重生或重複食用。
2. 店主自主同意後借杯、攜帶、洗淨與歸還同一杯子。
3. 泡茶中間狀態可讀回；介入後由 NPC 自主中斷，已完成成果保留。
4. 其他有權且知情角色移走中間杯子，原活動不能沿舊前提完成；不洩漏隱藏去向。
5. 結束驗收後，原世界角色、時間、事件、物件與活動恢復，驗收經歷不混入；真實用量和帳號設定保留。

測試接口沿既已批准的世界 GET／POST、實際模型傳輸替身與真實 Chromium／SQLite。替身驗證工程正確性；真實模型是否選擇完成活動另行記錄，不把兩者混稱。
