# 同次候選發散與自主收斂（#222）

本切片依 #220 第3a節，在原 `npc-decision.v3` 最終回覆加入候選與收斂；`Character.intents` 仍是唯一正式追求權威。沒有新增模型、評分、反思、修復或每層呼叫，沒有改輸出上限、回合期限或玩家預算。

模型依原本本人可知的人格、當前方向、記憶／信念／關係、需求感受、喜好、習慣、感知與已知方法提出 `pursuitCandidates`；程式沒有職業模板、需求到意願映射、抽籤或輪換。每個候選含本人 `:candidate:` 前綴身份、kind、content、scope、satisfaction及可空的本人當次有效來源。候選不提供外在可行性保證，也不為每個選項先呼叫世界裁定。

`pursuitSelection` 包含 `adoptions:[{candidateId,pursuitId}]`、`declinedCandidateIds`、`focus` 和一句可空的 reason。每個新承接 upsert（version=0）須與候選一對一對照，既有節點修訂／排序不必假裝新候選。採用時可修訂範圍／標準，私有證據並列原候選與正式版本；程式不判定所有自然語言語義是否一致。明示拒絕的候選與單純未採用分開，未承接不創造安排、經歷、習慣、喜好、需求恢復或世界成果。

焦點可為 null，或 `{kind:'candidate',id,version:0}`，或 `{kind:'existing',id,version:本次原版本}`。候選焦點必須先被承接，既有焦點須仍為本次可見的有效追求，解析後的正式身份與 `focusIntentId`／方法評估一致。可以一次承接數項而當下沒有焦點，也可以列出候選卻選擇原有追求。空候選／空收斂／空焦點、休息、等待與續做合法；純進度推進不因沒有候選再叫模型。方法取捨仍走既有 `methodAssessment`，不將全部替代方法變成工作。

| 包絡 | 本切片工程值與理由 |
| --- | --- |
| 候選集合 | 最多4項，完整 JSON最多2048 UTF-8 bytes，對齊同次最多4項明示新增，避免縮窄既有合法形成；不迫使湊數 |
| 候選文字 | content／scope各120字、satisfaction可null或80字、id64字、來源最多4個；仍受集合bytes硬界線 |
| 收斂 | 完整 JSON最多1024 UTF-8 bytes；最多4個一對一承接／拒絕引用，reason160字；只有一個焦點 |
| 共同心理包絡 | 兩欄連同追求增量、方法評估及原心理工作共享原8KiB；候選不是狀態更新項，原最多4項狀態更新保留。各欄最大值不能同時填滿至突破共同上界 |
| 永久狀態／追溯 | 未承接候選只存既有私有實錄，沒有新增角色候選庫；實錄仍沿原1MiB單筆及有界保留／缺口策略 |

空候選／選擇佔用很少 bytes，仍保留原先合法的增量維護空間。超界整輪拒絕，不截掉有效選項以通過檢查，不提高原2048／4096 NPC輸出tokens。完整最大圖及88KiB正常／回想投影預留由 #227 接續整合，不能以本票代表整份包絡已驗收。

來源只核對當次真正可見 short／long／belief／relationship 版本，正常及既有回想後共用原可見角色；沒有將隱藏庫存、他人意願、裁定私有理由或 trace灌進發散。`ActivityDecision.pursuitEvidence` 只是當輪協調的暫態資料，路由把它寫成 `npc-pursuit-selection` 私有step；沒有寫入 Character、活動進度或故事事件。

既有分析的決策追溯顯示候選、明示承接／拒絕／未承接、原範圍與承接後範圍、候選／既有焦點和提交狀態；空集合、保存缺口、未通過驗證與未提交分開。結構通過不等於完整心理因果或外在成果。原始失敗候選仍由原回覆實錄查閱，不能回灌 NPC。
