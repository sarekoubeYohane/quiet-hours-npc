# 跨角色需求承接驗收（#210）

本票將 #206–#209 的既有能力沿真正世界 API 組合驗收，不新增服務引擎、初始任務、重複提示或模型呼叫種類。NPC 仍以 `npc-decision.v2` 方法評估選擇行動。查找是可選步驟：未知普通來源可由主持確認，已有足夠知識則直接使用已知方法準備。

共享 fixture `tests/fixtures/demand-integration-loop.cjs` 保留 seed 店主 personality、goal、intents；初始沒有新增服務意圖。客人實際 say，店主感知並詢問，客人下一輪實際回答；測試沒有直接注入需求記憶。受控 NPC 回覆在接到這次需求後自行提出測試用服務意圖，這只是程式能力輸入，不是自主行為證據。

探索路徑依序驗證詢問、確認、回答、承諾、來源確認、準備、grant、客人 consent、transfer、下一輪輸入。來源成立／知情與實物分開，準備會消耗原料並形成餐點。grant 不代表客人同意，consent 不代表已交付；只有後續 transfer 才改持有人，所有權維持，也不代替客人吃下。直接路徑使用已知麵包方法，完全跳過搜索。

wait、口頭承諾、拒絕、改選與放下意圖不建立成果。長活動實際受另一角色談話中斷，可以暫停／恢復或放棄；已提交原料不回復、未執行成果不提前出現。保存、租約及較後角色故障沿現有回合原子性；派送用量保留，同操作 ID 重送不重派。

真實模型試驗使用公開 `tooling/experiments/demand-scene-210.json`，而非測試 responder。該檔封存無秘密的起始世界，含已確認普通場所及已知方法前提；不得把 fixture 的逐步回覆交給真實店主。初始世界 JSON 的 SHA-256 為 `16e774c4d5e688d5f71378bd6f95deb7b0a3eb2e3f2e96f17d1858144123e17d`（5928 bytes）。#211 另外固定觀察窗口、重複次數、預算及判讀，測試通過不推論店主自主改善。

本票只新增驗收與公開情境，不新增 domain 名詞、資料欄位或 SQL migration。容量／舊存檔及來源語義沿 [#208](world-discovery.md) 與 [#209](routine-discovery.md) 契約。完整能力矩陣及限制見 [驗證紀錄](../verification/demand-integration-210-2026-10-28.md)。
